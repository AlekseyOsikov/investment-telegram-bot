# rag/ — офлайн-индексация корпуса документов

Корневые правила — в `/CLAUDE.md`. Полная спецификация — `openspec/specs/rag-indexing/spec.md`;
обоснования — `openspec/changes/archive/*add-rag-indexing-pipeline/design.md`.

Запуск — вручную: `make index` (`python -m rag.cli`), требует локальный Ollama с моделью
`EMBEDDINGS_MODEL`. Не связан с Telegram и `RESEARCH`; командам `/research_chunking_*`
(`src/research/`) и слою `rag` у `/smart_agent` (`src/agents/CLAUDE.md`, стратегия —
`RAG_SMART_AGENT_STRATEGY`) только поставляет индекс на диске. Эмбеддинги (`providers/embeddings_client.py`,
Ollama) НЕ связаны с `MAIN_CLIENT`.

## Модули и инварианты

- `filenames.py` — `parse_filename()`: метаданные из имени `<Title>(<author>, <date>).<ext>`
  (скобочный суффикс; одиночное значение без запятой различается по формату даты `ДД.ММ.ГГГГ`).
  Файл не читает и не переименовывает.
- `extraction.py` — `extract_text()` возвращает СЫРОЙ текст (PDF — системный `pdftotext -layout`,
  нужен poppler-utils; не Python-зависимость). Текст сырой намеренно: `\f` между страницами нужен
  `chunking.py` ДО очистки; `clean_text()` раньше этого сделает границу страницы неотличимой от
  пустой строки.
- `chunking.py` — `chunk_fixed_size()` (окно `RAG_FIXED_CHUNK_CHARS`/`RAG_FIXED_CHUNK_OVERLAP`,
  ждёт УЖЕ очищенный текст) и `chunk_structural()` (ждёт СЫРОЙ текст: делит по `\f`, чистит
  страницу, ищет заголовки — короткая строка без `.!?:` перед абзацем, иначе целая страница).
  Эвристика даёт ложные срабатывания на PDF-слайдах — текст не теряется, чанки мельче; это
  осознанный компромисс.
- `index_store.py` — индекс одной стратегии: FAISS `IndexFlatIP` (L2-нормализованные векторы) +
  SQLite `chunks`. Собирается в `<strategy>.tmp/`, затем прежний каталог удаляется и `.tmp`
  переименовывается. `os.rename` каталога — ТОЛЬКО на несуществующий путь (на FUSE/NTFS
  переименование поверх существующего падает с `Directory not empty`). Крах посреди сборки не
  должен оставлять прежний индекс наполовину переписанным. `search()`/`get_stats()`/
  `index_exists()`/`list_titles()` — чтение для research-команд и слоя `rag`; `list_titles()` —
  заголовки проиндексированных документов (проверка покрытия индекса в `/research_rag_compare`).
- `cli.py` — обходит `data/source/pdf|txt`, чанкует ОБЕИМИ стратегиями, эмбеддинги пачками по 32,
  `build_index()` для каждой стратегии ПОСЛЕДОВАТЕЛЬНО и НЕЗАВИСИМО: сбой эмбеддингов одной
  стратегии останавливает CLI ДО её `build_index()`, индекс другой остаётся обновлённым. Полная
  пересборка при каждом запуске, инкрементальности нет.

**Известный пробел**: PDF без текстового слоя (сканы) дают пустой текст через `pdftotext`, и `cli.py`
пропускает такие файлы МОЛЧА — без предупреждения и без OCR (на корпусе проекта так выпали 13 из 52
документов). Исправление (предупреждение или OCR) — отдельное изменение `rag-indexing`;
`/research_rag_compare` помечает вопросы, чьи ожидаемые документы не попали в индекс.

`providers/embeddings_client.embed_texts()` принимает необязательный `budget_seconds` — предел
суммарного ожидания для интерактивного пути (слой `rag`); без него (индексация, research-команды)
поведение прежнее: 4 попытки с паузами 2/4/6 с плюс повторы SDK (≈17 с при остановленной Ollama).
Калибровка порога слоя `rag` — `scripts/rag_calibrate.py` (с флагом `--rewrite` — сравнение оценок
по исходному вопросу и по переписанному запросу); порог привязан к модели эмбеддингов, стратегии и
переписыванию вопроса, при их смене или пересборке индекса с другим чанкингом повторить.

## Тесты

`tests/test_rag_*.py` — чистые функции и FAISS+SQLite на синтетических векторах, без реальных
эмбеддингов и сети. `pdftotext`, `embeddings_client.py`, `cli.py` и команды бота тестами не
покрыты — проверяются вручную на живом индексе.
