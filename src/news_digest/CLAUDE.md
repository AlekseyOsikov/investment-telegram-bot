# news_digest/ — дайджест новостей по бумагам из `/watch` (`/news*`)

Корневые правила — в `/CLAUDE.md`. Спеки — `openspec/specs/{news-digest,news-server}/spec.md` (после
архивации изменения `add-news-digest`), обоснования — `openspec/changes/*add-news-digest/design.md`.
Активно при `NEWS_ACTIVE` (= `NEWS_ENABLED and PRICE_WATCH_ACTIVE and bool(NEWS_FEEDS)`); иначе
команды не регистрируются и не упоминаются в `/help`/`/start`, фоновая работа не запускается. Не
привязано к `RESEARCH`. Второй случай, когда бот САМ пишет без вопроса (после `/watch*`), и первый,
где в фоне работает модель.

Команды: `/news` (включить по тикерам опроса `/watch` этого чата), `/news_status`, `/news_stop`
(выключить и удалить отметки). Тикеры отдельно НЕ вводятся: бот на каждом тике читает их из
`watch_status` чата; `/watch_stop` дайджест выключает. `/watch*` остаются без модели.

## Разделение ответственности

СЕРВЕР `mcp_servers/news/` (вне `src/`, `src/` его не импортирует — только MCP): собирает публичные
ленты (RSS/Atom, MOEX ISS `sitenews`), убирает повторы, привязывает новости к тикерам КОДОМ по
таблице алиасов, хранит публичные записи, разбор, включённость и отметки доставки в SQLite. Пассивен:
время не измеряет, не отправляет, модель не вызывает. БОТ — команды, часы, разбор моделью, доставка.

```
NewsScheduler.run_tick (каждые NEWS_COLLECT_INTERVAL_MINUTES):
  news_chats -> watch_status(chat) (тикеры; опроса нет -> news_disable)
  news_collect(тикеры)  -> ленты -> дедуп -> привязка -> SQLite
  news_pending -> для каждой: слот llm_queue (низкий приоритет) -> модель -> проверка кодом
  news_save_analysis(разбор | «недоступен»)
  по чатам: news_state / news_ready -> срочные -> дайджест -> отправка -> news_ack  [ТОЛЬКО после отправки]
```

## Модули

- `rules.py` — ЧИСТОЕ: типы событий и важность, терпимый разбор JSON, `validate_analysis`
  (перечни, длины, запретные формулировки `FORBIDDEN_PATTERNS`, ссылка), `next_step`
  (принять/повторить/откат), отбор срочных и дайджеста, сроки.
- `prompts.py` — системное сообщение разбора и сборка сообщений для ОДНОЙ новости.
- `texts.py` — ответы команд, дайджест (делится на части, КАЖДАЯ с оговорками), срочное сообщение.
- `price_context.py` — ЧИСТОЕ: изменение цены по свечам `get_price_history` (`interval=hour`) и
  строка «в это же время» без слов о причине.
- `news_session.py` — один процесс сервера новостей на обращение (по образцу `watch_session.py`).
- `analyzer.py` — разбор под слотом (`KIND_NEWS`), `make_completer` (вызов модели оператора).
- `scheduler.py` — `run_tick(Deps, Settings)` (всё внедряется) и `NewsScheduler`; `build_deps` —
  боевая сборка; `start_scheduler`/`stop_scheduler` — хуки `post_init` (ПОСЛЕ `start_gate`) /
  `post_stop` (ДО `stop_gate`).
- `commands.py` — обработчики (личные чаты; `chat_id` из `update.effective_chat.id`).
- Конфигурация модели — `providers/news_client.py` (`NEWS_PROVIDER`/`NEWS_MODEL`, по образцу
  `rewrite_client.py`); оценка — `research/news_eval.py` + `scripts/news_eval.py` (`make news-eval`).

## Что сохранять

- **Граница «тип события и механизм».** Допустимо: тип, важность, пересказ по тексту новости, ОБЩИЙ
  механизм типа события, совпадение по времени с ценой. Запрещено (и проверяется кодом, а не только
  промптом): направление влияния, прогноз, оценка «хорошая/плохая новость», советы, пороги,
  «сигналы», слова о причине движения цены. Это РЕШЕНИЕ ВЛАДЕЛЬЦА в ограниченном виде; расширение
  (направление, прогнозы, сигналы, суммы, связь с брокером) — отдельное обсуждение. Новый запретный
  оборот добавляй в `FORBIDDEN_PATTERNS` (тесты перебирают набор), не ослабляй проверку.
- **Привязка — кодом, не моделью.** Модель получает только уже привязанные новости и не меняет
  привязку. Короткие/двусмысленные алиасы — в `weak` с контекстом; «Газпром» vs «Газпром нефть» —
  `excludes`. Бумаги вне таблицы находятся только по тикеру латиницей; `/news` честно называет их
  («покрытие ограничено» — `news_coverage`).
- **Модели не отдаются инструменты.** Инструменты сервера новостей изменяют хранилище и принимают
  chat_id — ни один слой бота их модели не отдаёт. На вход модели — публичный текст ОДНОЙ новости
  и её привязка: без chat_id, тикеров других чатов, сообщений и памяти пользователей. Текст
  новости — недоверенные данные в ограждённом блоке (маркеры вычищаются).
- **Системное сообщение разбора — отдельное**, после `SYSTEM_PROMPT` (передаётся параметром), с
  запретом направления/прогноза и оговоркой, что оно НЕ ослабляет основной промпт (тест проверяет —
  не убирать).
- **Оговорки — фиксированный текст кода** (`texts.DISCLAIMERS`), в КАЖДОМ сообщении (ответ `/news`,
  каждая часть дайджеста, срочное): не лицензированный советник; не рекомендация и не прогноз;
  подборка неполная (нет официального раскрытия эмитентов); разбор автоматический. Без гарантий.
- **Доставка «не менее одного раза»**: сначала отправка, потом `news_ack`; сбой оставляет новости
  неподтверждёнными. Один `news_ack` = одно сообщение (+1 к суточному лимиту; дайджест из нескольких
  частей — одно сообщение). Срочные идут ДО дайджеста; когда дайджест подошёл и есть что в него
  положить, ему резервируется одно сообщение суточного лимита. «Бот заблокирован»/«chat not found»
  → `news_disable` ТОЛЬКО для этого чата. Пользователям о фоновых сбоях не пишем.
- **Разбор не мешает пользователям**: `gate.slot(priority=RESEARCH, kind=KIND_NEWS)` на ОДНУ
  новость; не в реестре чата/`/queue`/лимитах. Модель недоступна (`transient`) — новость свежее
  `ANALYSIS_GRACE_HOURS` ждёт повтора (и остальные в тике не мучаем), старше — уходит «без разбора».
  Нарушение правил после повтора и «разбор не настроен» — окончательно «без разбора».
- **Данные наружу**: тексты новостей (публичные) уходят модели разбора — при `deepseek`/`kimi`
  облачному провайдеру; по умолчанию локальный Ollama. Ленты/модель/лимиты задаёт ТОЛЬКО оператор.
- **Хранится только публичное**: новости, разбор, по чатам — chat_id, признак включённости,
  отметки доставки и суточный счётчик. `/news_stop` удаляет данные чата; `/watch_stop` и сброс памяти
  агентов чужих записей не трогают. Срок хранения — `NEWS_RETENTION_DAYS`.
- **Сервер**: запуск `sys.executable`, список аргументов без shell, `--db` абсолютный; файлы модулей
  сервера названы `news_*.py` (в тестах `server`/`rules` других серверов уже заняты).

## Конфигурация (`config.py`, `.env.example`)

`NEWS_ENABLED` (false), `NEWS_DB`, `NEWS_FEEDS` (адреса через пробел/запятую; пусто — не запускается,
предупреждение), `NEWS_PROVIDER` (`ollama`|`deepseek`|`kimi`), `NEWS_MODEL`, `NEWS_TIMEOUT_SECONDS`
(>0), целые ≥ 1: `NEWS_COLLECT_INTERVAL_MINUTES` (15), `NEWS_DIGEST_INTERVAL_HOURS` (6),
`NEWS_DIGEST_MAX_ITEMS` (10), `NEWS_MAX_MESSAGES_PER_DAY` (6), `NEWS_MAX_ANALYZE_PER_TICK` (5),
`NEWS_RETENTION_DAYS` (7). Мусор в флаге/числах останавливает запуск (`_validate_config()`).
