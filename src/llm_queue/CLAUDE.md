# llm_queue/ — очередь обращений к основной модели

Корневые правила — в `/CLAUDE.md`. Спека — `openspec/specs/llm-request-queue/spec.md` (после
архивации изменения `add-llm-request-queue`), обоснования —
`openspec/changes/*add-llm-request-queue/design.md`.

## Зачем

Локальная модель Ollama обслуживает один запрос за раз (`OLLAMA_NUM_PARALLEL=1`). Раньше хендлеры
вызывали синхронный клиент прямо в async-обработчике и замораживали цикл событий. Теперь хендлер
проверяет ввод, ставит ЗАДАЧУ (`enqueue_job`) и сразу возвращается; задача ждёт слот шлюза,
работает и сама отправляет ответ. PTB остаётся последовательным (без `concurrent_updates`).

## Модули

- `rules.py` — ЧИСТЫЕ правила (тесты `tests/test_llm_queue_rules.py`): порядок (приоритет, затем
  FIFO), позиция, `DurationStats` (окно 20 длительностей по видам задач: `main`, `agent`, `compare`,
  `smart_agent`, `dev_assistant` — режим `/dev`, `research`), `estimate_wait` (медиана –
  90-й процентиль, `ceil(n/K)` волн впереди; мало измерений — нет нижней границы, верхняя —
  `REQUEST_TIMEOUT_SECONDS`), лимиты, разбор аргумента `/queue_cancel`, `AskCancelled` /
  `raise_if_cancelled`, ВСЕ тексты очереди. Не импортирует `config`.
- `gate.py` — `LlmGate` (asyncio; тесты `tests/test_llm_queue_gate.py` на фиктивных корутинах):
  `submit()` — задача пользователя (реестр по чатам, лимиты, TTL), `slot()` — слот на шаг
  исследования, `cancel_job()/cancel_chat()`, `shutdown()`.
- `commands.py` — `/queue`, `/queue_cancel`, `enqueue_job/enqueue_message`, `cancel_chat_questions`,
  `saved_notice`, хуки `start_gate/stop_gate` (`post_init`/`post_stop` в `main.py`).

## Что сохранять

- **Слот освобождается по ФАКТУ завершения работы.** Отмена asyncio-задачи не останавливает поток
  `asyncio.to_thread`: при отмене слот и замок чата держатся до конца потока
  (`JobContext.run_thread` → `_on_thread_done`). Основной поток на `AsyncOpenAI`: отмена `await`
  закрывает соединение, Ollama прекращает генерацию — слот свободен сразу.
- **Замок чата берётся ПЕРЕД слотом**: вопросы одного чата не выполняются одновременно даже при
  `LLM_MAX_CONCURRENCY > 1`.
- **Нумерация вопросов** — индекс в реестре чата + 1, пересчитывается при каждом обращении;
  выбор по номеру идёт только среди вопросов чата отправителя. Не храни номера.
- **Отмена вопросов агентов — кооперативная** (`should_cancel`): снятый вопрос не пишется в
  память; запись, начатая до отмены, не прерывается и о ней сообщается пользователю.
- **TTL и глубина — только для вопросов пользователей** (`INTERACTIVE`); исследования срока
  ожидания не имеют и в глубину не входят.
- **Только память процесса.** Ничего не пишется на диск; не добавляй сохранение очереди и оценки по
  длине промпта (non-goals изменения).
- Команды очереди — личные чаты, вне флага `RESEARCH`; `/cancel` не занимать.
