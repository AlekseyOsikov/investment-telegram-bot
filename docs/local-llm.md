# Локальная модель как код-ассистент (Ollama + Continue в IDEA)

Отчёт по заданию «День 4. Local Boost»: локальная модель в роли код-ассистента, правила проекта в
её контексте, прогон задач Дня 1 (`/terms`, тег v0.36) и Дня 2 (профили bug-fix и research, тег
v0.37) и честное сравнение с облачным ассистентом. Это оснастка разработки: бот (`src/`) её не
использует и от неё не зависит.

Все числа — из прогонов на одной машине, **каждый вариант запускался 1–3 раза**, температура 0,2:
это ориентиры, а не статистика. Что не проверялось, указано в разделе «Что не проверено».

## 1. Железо и окружение

| | |
|---|---|
| CPU / GPU | Ryzen 9 7940HS (16 потоков), встроенная Radeon 780M (`gfx1103`) |
| Память | 59 ГиБ общей RAM; у iGPU 2 ГиБ выделенной VRAM + ~30 ГиБ общей (GTT) |
| Ollama | 0.21.0 в Docker, модели на bind-mount `/media/alexey/DATA/ollama/models` |
| IDE | IntelliJ IDEA 2026.1 + Continue (JetBrains) |

**Ускорение на iGPU через Vulkan.** Стартовый контейнер работал на CPU (образ `ollama/ollama`
без проброса GPU). Контейнер пересоздан с Vulkan; старый сохранён как `ollama-cpu`:

```bash
docker stop ollama && docker rename ollama ollama-cpu
docker run -d --name ollama --device /dev/dri --group-add video --group-add 992 \
  -v /media/alexey/DATA/ollama/models:/root/.ollama -p 11434:11434 \
  -e OLLAMA_HOST=0.0.0.0:11434 -e OLLAMA_CONTEXT_LENGTH=16384 -e OLLAMA_VULKAN=1 \
  ollama/ollama:latest serve
```

`992` — GID группы `render` на этой машине (`getent group render`). В логе Ollama при старте:
`library=Vulkan name=Vulkan0 description="AMD Radeon 780M Graphics (RADV PHOENIX)"`, модель
целиком в `vram`. Политики перезапуска у контейнера нет. Сейчас в нём ещё включён
`OLLAMA_DEBUG=1` (включали для диагностики) — для работы его лучше убрать.

Модели: `qwen3-coder:30b` (MoE, 18,6 ГБ), `gpt-oss:20b` (13,8 ГБ), `qwen3:30b-a3b` (18,6 ГБ),
`qwen2.5-coder:3b` (1,9 ГБ). ROCm не пробовали (см. раздел 8).

## 2. Скорость: CPU и Vulkan

Замеры через нативный API Ollama (`/api/generate`), `num_predict` 200. «Префилл» — обработка
промпта (токенов в секунду), «генерация» — токенов в секунду.

**Короткие промпты (0,5k / 1,3k / 2,5k токенов), `num_ctx` 8192:**

| Модель | Префилл CPU | Префилл Vulkan | Генерация CPU | Генерация Vulkan | Ответ на 2,5k токенов: CPU → Vulkan |
|---|---|---|---|---|---|
| qwen2.5-coder:3b | 111 / 103 / 89 | 395 / 533 / 503 | 28 / 25 / 24 | 33,5 / 33,3 / 32,3 | 34 с → 9 с |
| gpt-oss:20b | 62 / 62 / 57 | 246 / 308 / 303 | 14,6 / 14,2 / 13,8 | 19,4 / 19,2 / 18,9 | 55 с → 18 с |
| qwen3-coder:30b | 94 / 75 / 58 | 193 / 211 / 194 | 22 / 18 / 14 | 29,8 / 28,4 / 26,6 | 54 с → 19 с |

**Длинные контексты:**

| Модель | `num_ctx` | Промпт, ток. | CPU: префилл / генерация | Vulkan: префилл / генерация | Всего на Vulkan |
|---|---|---|---|---|---|
| qwen3-coder:30b | 8k | 8192 (CPU), 4468 (Vulkan) | 21,1 / 9,4 ток/с (7,5 мин) | 169 / 24,6 ток/с | 75 с |
| qwen3-coder:30b | 16k | 12785 (CPU), 7704 (Vulkan) | 10,6 / 3,6 ток/с (21 мин) | 132 / 21,2 ток/с | 108 с |
| qwen3-coder:30b | 32k | 15244 (Vulkan) | таймаут 50 мин | 88 / 16,2 ток/с | 263 с |
| gpt-oss:20b | 8k | 8192 (CPU), 3916 (Vulkan) | 24,8 / 13,1 ток/с | 294 / 18,5 ток/с | 57 с |
| gpt-oss:20b | 16k | 11659 (CPU), 6992 (Vulkan) | 37,7 / 10,5 ток/с | 275 / 18,2 ток/с | 46 с |
| gpt-oss:20b | 32k | 18490 (CPU), 13855 (Vulkan) | 26,6 / 8,4 ток/с | 230 / 16,8 ток/с | 82 с |

Строки CPU и Vulkan получены разными скриптами и **разными размерами промпта** (в CPU-замере
оценка токенов занижена, промпт обрезался до окна), поэтому сравнивать их можно только грубо.
Параллельно с CPU-замером на машине работали другие процессы.

**Выводы по скорости:**
- Vulkan ускоряет префилл в 2–5 раз, генерацию в 1,2–1,5 раза; на CPU 30B-модель на 16k
  отвечала 21 минуту, на Vulkan — 108 секунд.
- `qwen3-coder:30b` теряет скорость с контекстом быстрее `gpt-oss:20b`: на 32k префилл падает
  с 169 до 88 ток/с (у `gpt-oss` с 294 до 230).
- Холодная загрузка 30B-модели 43–81 с; `keepAlive` в конфиге Continue поднят до часа.
- Рабочий диапазон — контекст до 8–16k токенов; 32k для интерактивной работы слишком долго.

## 3. Настройка Continue

Файлы в репозитории:

| Файл | Назначение |
|---|---|
| `scripts/ollama/continue-config.yaml` | копия конфига; установка: `cp … ~/.continue/config.yaml`, перезапуск IDE |
| `.continue/rules/code-style.md` | сжатые правила проекта (~2 тыс. токенов), `alwaysApply: true` |
| `.continue/rules/research-profile.md` | профиль research, `alwaysApply: false` |
| `.continue/rules/bugfix-profile.md` | профиль bug-fix, `alwaysApply: false` |
| `.continueignore` | закрывает от модели `.env*`, `data/`, `reports/`, `.venv/`, `.git/`, ключи |

Параметры:

| Роль | Модель | Контекст | Макс. ответ | temperature / top_p |
|---|---|---|---|---|
| чат, правка, apply, агент | `qwen3-coder:30b` | 16384 | 8192 | 0,2 / 0,9 |
| автокомплит | `qwen2.5-coder:3b` | 4096 | 128 | 0 / 0,9 |

Автокомплит: `debounceDelay` 300 мс, `maxPromptTokens` 1024, `onlyMyCode`. Низкая temperature —
для кода нужна воспроизводимость. Эмбеддинги (`@codebase`) и провайдер `codebase` из конфига
убраны: индексация нагружает GPU вместе с чат-моделью и работает с той самой базой, которая
роняла ядро (раздел 8); агентный режим читает файлы инструментами.

**Правила из Дня 1 в контексте модели.** Полные `CLAUDE.md` + `docs/code-style.md` — 75 КБ (порядка
30 тыс. токенов) и в окно не помещаются. В `.continue/rules/code-style.md` — сжатая версия:
структура `rules/texts/commands`, naming, шаблон файла, антипаттерны, домен («не советник»,
запрет секретов), чек-лист проверки. Ollama кеширует общий префикс запросов, поэтому правила
дорого обходятся один раз за сессию.

## 7. Рекомендация: для чего хватает локальной модели

**Хватает (при проверке человеком и линтером):**
- точечный баг с известным местом и понятным воспроизведением (рабочий фикс в 5 из 7 запусков);
- вопросы по одному-двум файлам и пояснение кода в окне до 8k токенов;
- черновик нового файла по шаблону при готовом контексте (структура верная, мелкие ошибки
  запуска и стиля неизбежны);
- чат и приватные данные, которые нельзя отправлять провайдеру.

**Не хватает — нужно облако:**
- фича «в несколько файлов» с регистрацией, справкой и документацией (0 полностью верных из 4);
- агентный цикл без постоянного присмотра (в Continue — ошибки имён инструментов и зацикливание);
- полный аудит по проекту (покрытие тестами, связи между подсистемами): ответы неполные и
  местами выдуманные;
- точные правки существующих файлов и всё, где ошибка должна ловиться до коммита.

**Лучшая связка на этом железе:**

| Задача | Модель и параметры |
|---|---|
| Чат и генерация | `qwen3-coder:30b`, Vulkan, `num_ctx` 8192 (16384, если нужно несколько файлов), temperature 0,2, top_p 0,9, keep-alive 1 ч |
| Агентное чтение и исправление (свой цикл) | `gpt-oss:20b`, `think: low`: меньше выдумывает имён и аккуратнее вызывает инструменты |
| Автокомплит | `qwen2.5-coder:3b`, temperature 0, ≤128 токенов, промпт ≤1024 токенов |
| Не брать | `qwen3:30b-a3b` для генерации кода: 7,5 мин и оборванный ответ; контекст свыше 16k |

## 8. Ловушки и что не проверено

**Ловушки Continue и Ollama (все воспроизводились):**
- индекс `~/.continue/index/index.sqlite` может оказаться пустым и ронять ядро каждые несколько
  минут (`no such table: indexing_lock`); лечится удалением индекса при закрытой IDE;
- кнопка **Apply** пишет код в активный редактор, а не создаёт файл — перед запуском закройте
  файлы; запросы «Continue wants to create…» подтверждает **Accept** внизу диалога;
- `maxTokens` меньше, чем нужно агенту на ход, обрывает ответ и срывает вызов инструмента;
- Continue сам переписывает `config.yaml` и добавляет найденные в Ollama модели;
- имена инструментов в Continue должна знать сама модель: `qwen3-coder` вызывала несуществующие;
- `docker run` без `/dev/dri` и `OLLAMA_VULKAN=1` оставляет модель на CPU.

**Не проверено:**
- качество автокомплита (замерена только скорость);
- работа без сети (сеть не отключалась), телеметрия Continue;
- ROCm (`ollama/ollama:rocm`, `HSA_OVERRIDE_GFX_VERSION`): на `gfx1103` не поддерживается
  официально, память распределяется иначе; вынесено в необязательное усиление;
- `gpt-oss:20b` как модель агента внутри Continue и `qwen3-coder` в цикле bug-fix;
- облачные скорость и полный проход Дня 2 теми же метриками;
- статистика: по 1–4 запуска на вариант; разброс виден (research `gpt-oss` v2 дал и лучший, и
  худший ответ), но не измерен.

## 9. Как воспроизвести

Оснастка лежит в `scripts/ollama/` (не часть бота, `src/` её не импортирует):

| Файл | Что делает |
|---|---|
| `speed_bench.py` | раздел 2: `short` (промпты 0,5k–4k) и `long` (окна 8k–32k), JSON-строки в файл |
| `terms_oneshot.py` | раздел 4.1: однопроходная генерация `/terms`, применение блоков, проверки; `--reuse` повторно применяет сохранённый ответ |
| `agent_loop.py` | раздел 5: цикл с инструментами для профилей `research` и `bugfix`, `--variant v1\|v2` |
| `bugfix_eval.py` | раздел 5.2: независимая оценка результата bug-fix в worktree |
| `local_llm_lib.py` | чистые правила (границы доступа, нарезка, блоки SEARCH/REPLACE, проверка ссылок); тесты — `tests/test_local_llm_lib.py` |
| `local_llm_client.py` | тонкий клиент `/api/chat` и `/api/generate` |
| `prompts/terms.txt` | промпт Дня 1 дословно |

Каждый запуск — в чистом worktree от нужного коммита: `a8cff69` (День 1) и `763b1e2` (День 2),
`.venv` подключается ссылкой. Скрипты не читают окружение: адрес Ollama — `--url`
(по умолчанию `http://localhost:11434`), параметр `think` выбирается по модели (`gpt-oss` — `low`,
`qwen3:` — выключено), переопределяется `--think`. Примеры запуска — в докстринге каждого файла.
Профили v2 скрипты берут из `.continue/rules/`. `agent_loop.py bugfix` и `bugfix_eval.py`
запускают тесты и `python -c` из кода модели: только в одноразовом worktree.

Временные ветки и worktree прогонов (`local-terms-*`, `local-bugfix-*`, `local-bf-*`, `verify-*`)
после разбора результатов удалены; в репозитории остаётся только оснастка и отчёт. Контейнер
`ollama-cpu` оставлен для отката на CPU.
