# Стиль кода проекта

Подключается из корневого `CLAUDE.md` (`@docs/code-style.md`). Корневой файл говорит ЧТО система
должна делать и какие у неё границы; здесь — КАК писать код, чтобы он выглядел как остальной.
Эталоны ниже — реальный код с адресом `файл:строка`; перед копированием открой файл: строки
сдвигаются, образец важнее номера.

## 1. Стек

- Python ≥ 3.10 (в `.venv` — 3.11). `python-telegram-bot` 20.x (async), `openai` SDK (DeepSeek, Kimi,
  локальный Ollama через OpenAI-совместимый API), `python-dotenv`, MCP-клиенты, SQLite на стороне
  MCP-серверов.
- Линтер `ruff`: `line-length = 100`, правила `E, F, I, UP, B` (`pyproject.toml`). Тесты — `pytest`.
- Проверка ТОЛЬКО через `.venv/bin/...` — системный `python3` не содержит ruff и pytest.

## 2. Архитектура в одном экране

```
Telegram update
   |
   v
commands.py   тонкий хендлер: читает ввод, зовёт чистые функции, отправляет текст
   |             (фильтр личного чата, chat_id/user_id, обработка ошибок)
   +--> rules.py   ЧИСТЫЕ правила: данные -> решение. Без Telegram, сети, диска, config
   +--> texts.py   ЧИСТЫЕ тексты: данные -> строки пользователю (русский, без parse_mode)
   +--> клиенты / сессии (MCP, LLM) — только в слоях, которым это нужно
```

Главное правило: всё, что можно проверить без сети, лежит в чистых функциях и покрыто тестами;
хендлер остаётся тонким и проверяется вручную.

## 3. Структура папок и подсистемы

- `src/<подсистема>/` — пакет с `__init__.py`; рядом `CLAUDE.md` подсистемы (зачем, модули,
  «что сохранять», конфигурация, тесты). Образец — `src/llm_queue/CLAUDE.md`, `src/news_digest/CLAUDE.md`.
- `tests/test_<подсистема>_<модуль>.py` — один тест-файл на модуль (`test_news_digest_rules.py`).
- `docs/` — документация, `openspec/` — требования, `scripts/` — одноразовая оснастка (не часть бота).
- Новая подсистема регистрируется в пяти местах: `main.py` (импорт + `add_handler`), `help_command`
  в `main.py`, `README.md` (таблица команд И дерево каталогов), карта `src/` в корневом `CLAUDE.md`,
  вложенный `src/<подсистема>/CLAUDE.md`.

## 4. Naming conventions

| Что | Правило | Пример |
|---|---|---|
| Модуль/пакет | `snake_case`, роль в имени файла | `rules.py`, `texts.py`, `commands.py`, `news_session.py` |
| Команда бота | `snake_case`, префикс подсистемы | `/news_status`, `/watch_report` |
| Обработчик | `<команда>_command` | `news_stop_command` |
| Фабрика обработчиков | `build_<имя>_handler` (один) / `build_<имя>_handlers` (список) | `build_queue_handlers` |
| Константа | `UPPER_SNAKE`, группы под комментарием-разделителем | `EVENT_TYPES`, `DISCLAIMERS` |
| Приватное | префикс `_` | `_call`, `_INTERVAL_RE` |
| Тест | `test_<что_проверяем_по_смыслу>` | `test_fixed_texts_have_no_guarantees_or_assessments` |
| Комментарии, докстринги, тексты пользователю | на русском | — |
| Идентификаторы, имена переменных | на английском | `chat_id`, `analysis` |

## 5. Паттерны, которые используем

1. **Чистое ядро + тонкий слой.** Решения — в `rules.py`, строки — в `texts.py`, Telegram — в
   `commands.py`. Зависимости (клиенты, часы) передаются параметрами, а не импортируются внутри
   чистых функций (`run_tick(Deps, Settings)`).
2. **Проверка кодом, не промптом.** Границы допустимого (запретные формулировки, длины, перечни)
   записаны в коде и проверяются тестами; промпт — вторая линия.
3. **Раздельные `except` на ошибки OpenAI SDK** с русским сообщением и `MAIN_CLIENT_LABEL`.
4. **Фиксированные оговорки** — константы кода, входят в КАЖДОЕ сообщение; тест это проверяет.
5. **Хендлер только для личных чатов**: `filters.ChatType.PRIVATE` у каждого нового обработчика.
6. **Конфигурация** — только через `config.py` (`load_dotenv()` там и только там); числа и флаги
   проверяет `_validate_config()`.

## 6. Шаблон типичного файла

Каждый `.py` в `src/`: докстринг модуля → `from __future__ import annotations` → импорты (stdlib,
сторонние, проектные; сортирует ruff) → константы → функции.

```python
"""Чистые правила <подсистемы>: что решает модуль, чего не знает (Telegram, сеть, модель).

Граница/обоснование одним абзацем; тесты — `tests/test_<подсистема>_rules.py`.
"""

from __future__ import annotations

import re
from dataclasses import dataclass

# Ключ — код, значение — подпись пользователю.
KINDS: dict[str, str] = {"a": "Первое", "b": "Второе"}

MAX_ITEMS = 10


def normalize(raw: str) -> str:
    """Короткий докстринг по-русски: что принимает и что возвращает."""
    return " ".join(raw.casefold().split())
```

Командный слой:

```python
"""Команды <подсистемы>: что делают, личные чаты, не под RESEARCH."""

from __future__ import annotations

from telegram import Update
from telegram.ext import CommandHandler, ContextTypes, filters

from . import rules, texts


async def example_command(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    """/example [аргумент] — одна строка о том, что делает команда."""
    await update.message.reply_text(texts.answer(" ".join(context.args or [])))


def build_example_handler() -> CommandHandler:
    return CommandHandler("example", example_command, filters=filters.ChatType.PRIVATE)
```

Тест-файл: докстринг (что покрыто), импорт модуля, функции `test_*` без классов, данные —
функциями-фабриками; без сети и Telegram. `from __future__ import annotations` в тестах и в пустом
`__init__.py` НЕ нужен (в существующих тестах его нет); он обязателен только для модулей с кодом в
`src/`.

Тест оговорки и запретных формулировок собирает ВСЕ ответы команды (список, определение,
«не найдено», каждый термин) в одну функцию и перебирает их целиком:

```python
def all_replies() -> list[str]:
    replies = [texts.terms_list_text(rules.list_terms()), texts.not_found_text("zzz", [])]
    replies += [texts.definition_text(term, d) for term, d in rules.GLOSSARY.items()]
    return replies


def test_every_reply_has_disclaimer_and_no_guarantees():
    for reply in all_replies():
        assert texts.DISCLAIMER_ADVISOR in reply
        assert GUARANTEE.search(reply) is None, reply
```

## 7. Эталонный код (как ХОТИМ писать)

1. **Модуль с границей и ссылкой на тесты** — `src/news_digest/rules.py:1-10` (докстринг объясняет
   границу, говорит чего модуль не знает и где тесты).
2. **Перечни «код → подпись» и проверка кодом** — `src/news_digest/rules.py:19-30` (`EVENT_TYPES`,
   `IMPORTANCE_LEVELS`).
3. **Тексты: плоский текст, оговорки константами, `DISCLAIMERS` в каждом сообщении** —
   `src/news_digest/texts.py:1-30` (там же формулировка «не лицензированный финансовый советник»).
4. **Фабрика обработчиков с фильтром личного чата** — `src/llm_queue/commands.py:175`
   (`build_queue_handlers`) и `src/news_digest/commands.py:181`.
5. **Раздельные `except` по ошибкам SDK** — `src/main.py:430-470`: каждое исключение — своё
   сообщение с `MAIN_CLIENT_LABEL`, последний `except Exception` с `# noqa: BLE001` и причиной.
6. **Тест запретных формулировок** — `tests/test_news_digest_texts.py:95-117` (`GUARANTEE` +
   перебор ВСЕХ фиксированных текстов). Регулярку применяй к итоговому тексту ответа целиком, а
   не к его частям; оговорку проверяй в каждом ответе, а не в одном.

## 8. Антипаттерны (запрещено)

| Плохо | Хорошо |
|---|---|
| Логика поиска/разбора внутри `async def …_command` | чистая функция в `rules.py` + тест; хендлер только вызывает её |
| Один общий `except Exception` вокруг вызова модели | раздельные `except` SDK с русским текстом и `MAIN_CLIENT_LABEL` (`main.py:430`) |
| Захардкоженное «DeepSeek» в тексте, `os.getenv`/`load_dotenv()` вне `config.py` | `MAIN_CLIENT_LABEL`; настройки только через `config.py` |
| Новый обработчик без `filters.ChatType.PRIVATE`; ответ без оговорки | фильтр у каждого обработчика; оговорки константами в `texts.py`, тест на их наличие |
| Слова «гарантированно», «точно вырастет», «рекомендуем купить» в любом пользовательском тексте | осторожные формулировки; тест с регуляркой `GUARANTEE` по всем фиксированным текстам |
| Модуль с кодом в `src/` без докстринга и без `from __future__ import annotations` | шаблон из раздела 6 (в тестах и пустом `__init__.py` `__future__` не нужен) |
| Правка `main.py` без проверки порядка импортов | после правки — `ruff check` по изменённым файлам (`I001`) |
| Тест запретных слов только по части текстов (определения без ответа целиком, одна константа в цикле, пустые `assert reply`) | перебор всех ответов целиком, как в разделе 6 |
| Подсказки «похожее» по вхождению подстроки без минимальной длины запроса (`suggest("и")` возвращает полсловаря) | порог длины для поиска по вхождению; сложное условие — со скобками или в именованных переменных |

## 9. Чек-лист «добавляю команду»

1. Пакет `src/<подсистема>/`: `__init__.py`, `rules.py`, `texts.py`, `commands.py` (или `command.py`,
   если команда одна — как в `dev_assistant`/`support_assistant`). `texts.py` обязателен по
   умолчанию: все строки пользователю и оговорки живут там (так в `price_watch`, `news_digest`).
   Исключение — `llm_queue`, где тексты лежат в `rules.py` по историческим причинам; в новых
   подсистемах так не делай.
2. Оговорка «не лицензированный финансовый советник / не рекомендация» в КАЖДОМ ответе, если
   команда говорит об инвестициях (формулировки — `news_digest/texts.py`).
3. Регистрация: `main.py` (импорт в алфавитном порядке + `add_handler`), `help_command`,
   `README.md` (таблица и дерево), карта `src/` в `CLAUDE.md`, `src/<подсистема>/CLAUDE.md`.
4. Тесты: `tests/test_<подсистема>_rules.py`, `…_texts.py` — чистые функции; тест запретных
   формулировок и наличия оговорки.
5. Корпус документов, ники и цитаты в примерах не использовать — только вымышленные.

## 10. Проверка перед сдачей

```bash
.venv/bin/python -m compileall -q src
.venv/bin/ruff check <новые и изменённые файлы>     # новых замечаний быть не должно
TELEGRAM_BOT_TOKEN=x DEEPSEEK_API_KEY=x .venv/bin/pytest tests/ -q
```

Токены-заглушки нужны только для тестов: `config` при импорте завершает процесс без них.
`ruff check src/` на старом коде не чистый (в основном `E501`) — сравнивай число замечаний до и
после, не гонись за нулём на всём репозитории. Для `main.py` назови число замечаний ДО и ПОСЛЕ
правки (до: `git show HEAD:src/main.py`) и убедись, что оно не выросло; в итоге укажи оба числа.
