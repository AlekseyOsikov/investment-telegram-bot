# Smoke-сценарии

Текстовые сценарии пользовательского пути в боте. Их прогоняет `make smoke`
(`scripts/smoke.py`): настоящие обработчики `main.py`, апдейты подаются без Telegram, ответы
бота записываются, модель и внешние серверы не нужны. На каждый шаг делается скриншот диалога,
итог — `reports/smoke/<время>/report.md` (не коммитится) или, с `--out DIR`, в выбранный
каталог (`/qa-run` по умолчанию — `reports/qa/<дата>_<время>/smoke/`, в `docs/qa/…` — только
по просьбе сохранить результаты в репозитории).

## Формат

Обычный markdown; строки вне ключей (как эта) игнорируются.

```
# Сценарий: название
Чат: личный               (или «групповой»; по умолчанию личный)

## Шаг: подпись шага
Отправить: /start         (или «Нажать: <подпись кнопки>»; ровно одно действие на шаг)
Ожидать: текст            (подстрока ответа, без учёта регистра; можно несколько строк)
Не ожидать: текст         (подстроки, которых в ответе быть не должно)
Тишина                    (бот на шаге ничего не отвечает)
```

На КАЖДОМ шаге дополнительно проверяется, что в ответе нет формулировок-гарантий
(`smoke_lib.GUARANTEE`) и что в логе бота нет ошибок.

## Сценарии

| Файл | Что проверяет |
|---|---|
| `01-start-help.md` | `/start` и `/help`: оговорка «не советник», без гарантий |
| `02-profile-invariant.md` | создать профиль и инвариант → увидеть в списке → снять → удалить профиль |
| `03-agent-history-reset.md` | `/agent_history` и `/agent_reset` без истории |
| `04-queue-empty.md` | `/queue` и `/queue_cancel` при пустой очереди |
| `05-group-chat-ignored.md` | в групповом чате текст и команды очереди молча игнорируются |

Нужен новый сценарий или правка после изменения бота — скилл `/qa-update-smoke`.
Не используй в примерах корпус документов, ники и цитаты — только вымышленные данные.
