# Трекер задач для execution loop

Файл ведёт пользователь. Раннер (`scripts/exec_loop.py --tracker <файл>`) запускает ассистента
по одной задаче; ассистент сам берёт ПЕРВУЮ невыполненную, выбирает профиль, выполняет,
отмечает `[x]` и коммитит. Всё, что не начинается с `- [`, — обычный текст, раннер его игнорирует
(им удобно описывать общие правила).

Формат задачи:

    - [ ] ID заголовок
      Описание в свободной форме: симптом, что нужно сделать, критерий «сделано».
      Строки описания начинаются с отступа (два пробела).
      Проверка: `команда`

- Статусы: `[ ]` открыта, `[x]` выполнена, `[!]` раннер заблокировал её после провала всех попыток.
- `ID` необязателен (`T01`, `BUG-7`, `DOC-3`…); без него задача получит номер по порядку (`№3`).
  Одинаковые ID в одном файле недопустимы.
- «Проверка:» необязательна, можно несколько строк и несколько команд в обратных кавычках.
  Раннер выполнит их из корня репозитория (`bash -c`) и засчитает задачу только при коде выхода 0.
  Если строки нет, задача принимается по общим проверкам проекта (сборка и тесты не стали хуже).
- Пишите критерий «сделано / не сделано» так, чтобы его можно было проверить командой.

Пример:

- [ ] BUG-1 `/watch` принимает период с нулём
  Симптом: `parse_watch_args(['SBER', '0m', '1h'])` возвращает запрос вместо ошибки.
  Сделано, когда: добавлен тест, падающий на старом коде; полный `pytest` зелёный.
  Проверка: `.venv/bin/pytest tests/test_price_watch_parse.py -q`
- [ ] DOC-1 В README не описана команда `/queue`
  Проверка: `grep -q "/queue" README.md`
- [ ] Просто задача без ID и проверки
  Опишите, что нужно сделать; приёмка — общие проверки проекта.
