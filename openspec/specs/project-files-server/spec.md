# project-files-server Specification

## Purpose
MCP-сервер файлов проекта для ассистента разработчика: безопасно читает и ищет по файлам репозитория,
готовит предложения правок в виде diff и применяет их только по явной команде приложения-клиента.
Все границы доступа обеспечиваются самим сервером, а не доверием к вызывающей стороне.

## Requirements

### Requirement: Доступ только внутри корня проекта и вне запрещённых путей

Сервер SHALL работать с файлами только внутри корня, заданного при запуске, и SHALL определять
корень сам, а не принимать его от вызывающей стороны в запросе. Любой путь SHALL приводиться к
каноническому виду с разрешением символических ссылок; путь, выходящий за корень (через `..`,
абсолютный путь или ссылку), SHALL отклоняться. Сервер SHALL отклонять чтение, поиск и запись для
запрещённых путей: файлы окружения (`.env*`, кроме `.env.example`), каталог `data/`, каталог `.git/`,
виртуальные окружения, кэши, ключи и сертификаты. Запрещённые файлы NOT SHALL попадать в списки
каталогов и результаты поиска. Сообщение об отказе NOT SHALL раскрывать содержимое запрещённого файла.

#### Scenario: Путь выходит за корень

- **WHEN** вызывающая сторона просит прочитать `../outside.txt` или абсолютный путь вне корня
- **THEN** сервер отклоняет запрос с понятной ошибкой и ничего не читает

#### Scenario: Символическая ссылка наружу

- **WHEN** внутри корня лежит ссылка на файл вне корня, и вызывающая сторона просит его прочитать
- **THEN** сервер отклоняет запрос, потому что итоговый путь вне корня

#### Scenario: Файл окружения

- **WHEN** вызывающая сторона просит прочитать `.env` или найти строку, встречающуюся только в `.env`
- **THEN** чтение отклоняется, а поиск не возвращает совпадений из этого файла

#### Scenario: Образец окружения доступен

- **WHEN** вызывающая сторона просит прочитать `.env.example`
- **THEN** сервер отдаёт его содержимое

### Requirement: Чтение, список и поиск с лимитами

Сервер SHALL предоставлять инструменты только для чтения: список каталога, чтение файла по пути
(с необязательным диапазоном строк) и поиск текста по нескольким файлам проекта. Результаты SHALL
содержать путь и номер строки для каждого совпадения. Сервер SHALL ограничивать размер читаемого
файла, число результатов поиска и общий объём ответа; усечение SHALL быть явно отмечено в
результате. Двоичные и слишком большие файлы SHALL отклоняться с объяснением, а не читаться частично
молча. Инструменты чтения NOT SHALL изменять файловую систему и SHALL быть помечены как только для
чтения.

#### Scenario: Поиск по нескольким файлам

- **WHEN** вызывающая сторона ищет имя функции, которое встречается в нескольких файлах
- **THEN** результат перечисляет совпадения с путём и номером строки для каждого файла

#### Scenario: Результатов слишком много

- **WHEN** число совпадений превышает лимит
- **THEN** сервер возвращает первые совпадения в пределах лимита и явно сообщает, что результат усечён

#### Scenario: Двоичный файл

- **WHEN** вызывающая сторона просит прочитать двоичный файл
- **THEN** сервер отклоняет запрос, указав причину

### Requirement: Подготовка предложения правки без записи в проект

Сервер SHALL по пути и полному новому содержимому файла строить предложение правки: вычислять
unified diff относительно текущего содержимого, фиксировать хэш исходного содержимого (или признак
отсутствия файла), присваивать предложению идентификатор и сохранять предложение в собственном
каталоге ожидающих предложений. Подготовка предложения NOT SHALL изменять файлы проекта. Путь
предложения SHALL проверяться по тем же правилам доступа и дополнительно по списку путей, в которые
разрешена запись (документация проекта и образец окружения); путь вне списка записи SHALL
отклоняться при подготовке. Предложение без изменений (новое содержимое равно текущему) SHALL
отклоняться. Размер нового содержимого SHALL быть ограничен. Предложение SHALL иметь срок жизни;
просроченные предложения SHALL удаляться и не применяться.

#### Scenario: Правка существующего файла

- **WHEN** вызывающая сторона предлагает новое содержимое для разрешённого существующего файла
- **THEN** сервер возвращает идентификатор, путь, diff и хэш исходного содержимого, а файл на диске
  остаётся прежним

#### Scenario: Создание нового файла

- **WHEN** предлагается содержимое для разрешённого пути, которого ещё нет
- **THEN** предложение помечено как создание файла, а diff показывает все строки как добавленные

#### Scenario: Путь вне списка записи

- **WHEN** предлагается правка исходного кода `src/main.py`
- **THEN** сервер отклоняет предложение как недопустимое для записи

#### Scenario: Правка без изменений

- **WHEN** новое содержимое совпадает с текущим
- **THEN** сервер сообщает, что изменений нет, и предложение не создаётся

### Requirement: Применение предложения по идентификатору с проверкой хэша

Сервер SHALL предоставлять отдельную операцию применения предложения по его идентификатору. При
применении сервер SHALL повторно проверить путь по правилам доступа и записи, срок жизни
предложения и совпадение текущего хэша файла с зафиксированным при подготовке; при расхождении
(файл изменился, либо файл создан, хотя предложение предполагало его отсутствие) запись NOT SHALL
выполняться, а вызывающая сторона SHALL получать понятную причину. Запись SHALL быть атомарной
(файл не остаётся частично записанным). После успешного применения предложение SHALL удаляться, а
повторное применение того же идентификатора SHALL отклоняться. Сервер SHALL также позволять отклонить
(удалить) предложение без записи.

#### Scenario: Успешное применение

- **WHEN** файл не менялся после подготовки предложения, и вызывающая сторона применяет его
- **THEN** сервер атомарно записывает новое содержимое и сообщает путь

#### Scenario: Файл изменился

- **WHEN** после подготовки предложения файл на диске был изменён другим способом
- **THEN** сервер не записывает файл и сообщает, что исходное содержимое изменилось

#### Scenario: Повторное применение

- **WHEN** уже применённый идентификатор применяется ещё раз
- **THEN** сервер отклоняет запрос как неизвестное предложение

#### Scenario: Просроченное предложение

- **WHEN** предложение применяется после истечения срока жизни
- **THEN** сервер отклоняет его и удаляет

### Requirement: Сервер не зависит от бота и не делает сетевых вызовов

Сервер SHALL запускаться отдельным процессом по stdio, настраиваться только аргументами запуска
оператора (корень, каталог предложений, пределы), не импортировать код бота и NOT SHALL
обращаться к сети. Предложения и данные сервера SHALL храниться вне индексируемых и коммитимых
каталогов проекта.

#### Scenario: Запуск вне бота

- **WHEN** оператор запускает сервер напрямую с корнем и каталогом предложений
- **THEN** сервер отвечает на запросы по stdio без участия бота
