# main-llm-provider Specification

## Purpose
Определяет, как оператор выбирает провайдера и модель основного потока бота (облачные DeepSeek и
Kimi или локальный Ollama) и как бот ведёт себя при неполной настройке или сбое провайдера.

## Requirements

### Requirement: Провайдер и модель основного потока выбирает оператор

Система SHALL обслуживать основной поток и функции, использующие основного провайдера
(`/agent`, `/smart_agent`, research-режимы без собственного выбора модели), через провайдера,
заданного оператором в настройках окружения; допустимыми значениями SHALL быть `deepseek`,
`kimi` и `ollama`, по умолчанию `deepseek`. Модель SHALL задаваться оператором отдельной
настройкой; для `deepseek` и `kimi` при незаданной модели SHALL использоваться модель
провайдера по умолчанию. Недопустимое значение провайдера SHALL приводить к завершению запуска
с понятной ошибкой конфигурации. Пользователь чата NOT SHALL менять провайдера, модель или
системный промпт ни командой, ни текстом сообщения; смена SHALL требовать перезапуска бота.

#### Scenario: Провайдер не задан

- **WHEN** оператор не задал провайдера основного потока
- **THEN** система использует `deepseek` с его моделью по умолчанию

#### Scenario: Выбран локальный Ollama

- **WHEN** оператор задал провайдера `ollama` и модель
- **THEN** вопрос пользователя в основном потоке обрабатывается этой локальной моделью, а ответ
  возвращается пользователю без обращения к облачным провайдерам

#### Scenario: Недопустимый провайдер

- **WHEN** оператор задал значение провайдера, не входящее в допустимые
- **THEN** запуск завершается с ошибкой, перечисляющей допустимые значения

#### Scenario: Пользователь пытается сменить модель

- **WHEN** пользователь чата просит бота переключить провайдера или модель
- **THEN** такой команды нет, настройка не меняется

### Requirement: Для Ollama модель обязательна, ключ API не нужен

При провайдере `ollama` система SHALL требовать явно заданную модель: пустое значение SHALL
приводить к завершению запуска с понятной ошибкой конфигурации. Ключ API для `ollama` NOT SHALL
требоваться; отсутствие ключей DeepSeek и Kimi при этом SHALL не мешать запуску (допустимо
предупреждение о недоступности сравнения облачных моделей). Для `deepseek` и `kimi` ключ
выбранного провайдера SHALL оставаться обязательным.

#### Scenario: Ollama без модели

- **WHEN** оператор выбрал `ollama` и не задал модель
- **THEN** запуск завершается с ошибкой, указывающей на необходимость задать модель

#### Scenario: Ollama без облачных ключей

- **WHEN** оператор выбрал `ollama`, задал модель и не задал ни одного облачного ключа
- **THEN** бот запускается и отвечает на вопросы локальной моделью

#### Scenario: Облачный провайдер без ключа

- **WHEN** оператор выбрал `deepseek` (или `kimi`) и не задал соответствующий ключ
- **THEN** запуск завершается с ошибкой о недостающем ключе

### Requirement: Сообщения называют реального провайдера и не подсказывают ключ для Ollama

Тексты для пользователя и записи журнала об основном потоке SHALL называть реально выбранного
провайдера (для локального — «Ollama»), а не фиксированного. Каждая категория сбоев (ошибка
авторизации, лимит запросов, тайм-аут, нет соединения, ошибка сервера, прочее) SHALL
обрабатываться отдельно и давать понятное русское сообщение. При недоступности сервера Ollama
подсказка SHALL указывать на запуск Ollama и загрузку модели, а не на API-ключ. Приветствие и
справка SHALL по-прежнему содержать оговорку, что бот не лицензированный финансовый советник.

#### Scenario: Сервер Ollama не запущен

- **WHEN** выбран `ollama`, сервер недоступен и пользователь задаёт вопрос
- **THEN** пользователь получает сообщение, что не удалось подключиться к Ollama, без упоминания
  API-ключа, а бот продолжает работать

#### Scenario: Модель не загружена в Ollama

- **WHEN** выбран `ollama`, сервер отвечает ошибкой, что модель не найдена
- **THEN** пользователь получает сообщение об ошибке сервера Ollama, а оператор — запись в журнале
  с причиной

#### Scenario: Подпись провайдера в приветствии

- **WHEN** пользователь отправляет `/start` при `ollama`
- **THEN** приветствие называет Ollama и выбранную модель и содержит оговорку о том, что бот не
  является лицензированным финансовым советником

### Requirement: Возможности, зависящие от модели, деградируют без отказа бота

Система NOT SHALL отправлять Ollama параметры, специфичные для облачных провайдеров. Если
локальная модель не поддерживает возможность, нужную необязательному слою (вызов инструментов,
структурированный JSON-вывод для автоматической памяти), сбой SHALL обрабатываться по уже
действующим правилам этого слоя (слой пропускается или обновление памяти не выполняется с
записью в журнал), а основной ответ пользователю SHALL по возможности выдаваться. Доменные
правила (осторожные формулировки, оговорка об отсутствии гарантий) SHALL сохраняться независимо
от провайдера.

#### Scenario: Локальная модель без поддержки инструментов

- **WHEN** выбран `ollama`, модель не поддерживает вызов инструментов и слой рыночных данных включён
- **THEN** бот не падает: запрос завершается ответом без данных инструментов или понятным
  сообщением об ошибке, запись об этом есть в журнале

#### Scenario: Модель не вернула валидный JSON для памяти

- **WHEN** выбран `ollama` и автоматическое обновление памяти получило невалидный JSON
- **THEN** память не изменяется, ответ пользователю уже отправлен, причина записана в журнал
