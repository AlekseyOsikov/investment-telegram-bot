# Proposal

## Why

Рабочая задача `/smart_agent` может начаться двумя путями: явной командой
`/smart_agent_task_start` или автоматически — детектором намерения
(`SmartAgent._maybe_start_task`), который срабатывает после каждого обычного вопроса,
пока активной задачи нет. Пользователю может быть нужен режим, где задачи начинаются
только по его команде, а обычный разговор («хочу составить портфель», «а что если
добавить облигации») никогда не превращается в задачу сам по себе. Сегодня для этого нет
подходящего переключателя: `/smart_agent_toggle working` — ближайший похожий рычаг —
не годится, потому что выключает СЛОЙ КОНТЕКСТА целиком: прячет состояние задачи от
модели и останавливает автопродвижение уже идущей задачи по этапам, а не только автостарт
новой. Нужен отдельный, более узкий тумблер.

## What Changes

- Новый пункт `/smart_agent_toggle` (условно `autostart`), переключающий отдельный флаг
  автомата задачи — НЕ слой контекста, а поведенческую настройку: при выключенном флаге
  `SmartAgent._maybe_start_task()` не вызывается, то есть задача больше не начинается
  сама по намерению в обычном разговоре.
- Флаг НЕ влияет ни на что другое: слой `working` продолжает участвовать в сборке
  контекста как раньше; уже идущая задача (начатая вручную ДО или ПОСЛЕ выключения флага)
  продолжает автоматически двигаться по этапам, гейтам и извлекать факты через
  `update_task_state()` — отключается только обнаружение НОВОЙ задачи. Все команды
  `/smart_agent_task_*` работают без изменений.
- Флаг общий на весь чат (не per-profile), персистентный в том же JSON, что и
  `enabled_layers`, по умолчанию включён (текущее поведение); старые файлы памяти без
  этого ключа читаются как «включён» — без отдельной миграции, по тому же принципу, что и
  ключ `tools`.
- `/smart_agent_show` показывает статус этого флага рядом со строкой рабочего слоя.
- **BREAKING**: нет. Поведение по умолчанию (флаг включён) не отличается от текущего;
  меняется только то, что появляется способ его выключить.

## Capabilities

### New Capabilities
- `smart-agent-task-automation`: переключаемый пользователем флаг автоматического
  обнаружения новой рабочей задачи `/smart_agent`, независимый от слоя контекста
  `working` и от ручного управления задачей. Капабилити новая и узкая: описывает только
  вводимое этим изменением поведение (сам флаг и его связь с уже существующими
  `_maybe_start_task`/`update_task_state`/`working`), а не весь конечный автомат рабочей
  задачи целиком — остальная его часть (этапы, гейты, инварианты, ручные команды)
  задокументирована в CLAUDE.md и коде и в спеки ретроспективно не переносится (см.
  «Процесс работы: OpenSpec» в CLAUDE.md).

### Modified Capabilities
Нет: команда `/smart_agent_toggle` и автомат задачи не описаны существующей спекой,
поэтому здесь нет капабилити для дельты — только новая, как указано выше.

## Impact

- Код: `src/agents/smart_agent.py` (новый ключ флага рядом с `enabled_layers`, проверка
  перед вызовом `_maybe_start_task()` в `update_task_state()`), `src/agents/
  smart_agent_command.py` (алиас и подпись в `LAYER_ALIASES`/`LAYER_LABELS`/
  `LAYER_TOGGLE_HINT`, пояснительная строка в ответе `/smart_agent_toggle` по образцу
  текста для `invariants`/`tools`, строка статуса в `/smart_agent_show`, докстринги,
  текст `/help`).
- Тесты: класс `SmartAgent` тестами не покрыт (импорт `config.py` требует окружения
  бота — существующее ограничение проекта, см. CLAUDE.md), поэтому проверка ручная, как
  и остального автомата задачи.
- Документация: `CLAUDE.md` (раздел «Конечный автомат рабочей задачи», описание
  `/smart_agent_toggle`), `README.md`.
- Зависимости, сеть, конфигурация (`.env`/`config.py`): не затронуты — это настройка
  чата, а не оператора.
- Другие режимы бота (`/agent`, `/agent_compare`, research-режимы, слой `tools`) не
  затронуты: флаг относится только к рабочему слою `/smart_agent`.
