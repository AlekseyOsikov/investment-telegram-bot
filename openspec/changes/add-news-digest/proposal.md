# Proposal

## Why

`/watch*` присылает по расписанию только цены: пользователь видит, ЧТО бумага подвинулась, но не
видит, какие публичные события вокруг компании могли быть рядом по времени. Просматривать ленты
вручную по каждому тикеру — рутина, которую можно отдать боту: собрать новости, привязать их к
наблюдаемым бумагам и коротко объяснить, к какому типу события они относятся и через какой
механизм такие события обычно связаны с ценой. Это первый сценарий, где AI работает в фоне и
сам пишет пользователю, поэтому границы допустимого фиксируются заранее.

## What Changes

- Новые команды `/news`, `/news_status`, `/news_stop` (личные чаты): включают и выключают для
  чата дайджест новостей по тикерам, которые чат уже наблюдает через `/watch`. Отдельной
  постановки тикеров нет. `/watch*` не меняются и остаются без модели.
- Новый локальный MCP-сервер `mcp_servers/news/` (вне `src/`, по образцу `project_files` и
  `mcp-moex`): по вызову бота забирает ленты, убирает повторы, привязывает новости к тикерам
  **кодом по таблице алиасов**, хранит публичные записи в SQLite. Источники этапа 1: общие
  RSS-ленты и новости биржи (MOEX ISS `sitenews`). Официальное раскрытие эмитентов не
  подключается (доступ закрыт); бот прямо сообщает, что подборка неполная.
- Новый пакет `src/news_digest/`: планировщик по образцу `price_watch`, фоновый разбор новостей
  моделью, сборка дайджеста и срочных сообщений, доставка.
- Модель **только классифицирует** новость по фиксированной схеме: тип события, важность, одна
  фраза пересказа, механизм влияния. Направление («позитивно/негативно»), прогноз и советы
  запрещены; ответ модели проверяется кодом, нарушение — повтор, затем показ новости без
  разбора. Модели не отдаются инструменты, текст новости — недоверенные данные.
- Рядом с новостью дайджест может показать изменение цены бумаги за тот же период из данных
  `/watch` — только как совпадение по времени, без слов о причине.
- Срочное сообщение — только для высокой важности, всё остальное в дайджесте; есть суточный
  лимит сообщений на чат.
- Фоновый разбор идёт под слотом общей очереди `llm_queue` с низким приоритетом (ниже вопросов
  пользователей) отдельным видом задачи; провайдер и модель разбора задаёт оператор (по
  умолчанию локальный Ollama).
- Набор для оценки качества разбора по образцу `dialog_eval`: чистые правила и скрипт, данные в
  `data/`, не коммитятся.
- **Решение владельца проекта, принятое в обсуждении этого изменения:** до сих пор CLAUDE.md
  оставлял «оценки и сигналы» по `/watch*` отдельным решением. Для новостного дайджеста решение
  принято в ограниченном виде: допускается классификация типа события и описание механизма
  влияния; направление влияния, прогнозы, советы, пороги и «сигналы» остаются под запретом и
  требуют отдельного решения. CLAUDE.md и вложенные документы обновляются вместе с реализацией.

## Capabilities

### New Capabilities
- `news-digest`: команды `/news*`, расписание, разбор новостей моделью в рамках запрета на
  направление и прогноз, дайджест, срочные сообщения, лимиты, оговорки, настройки оператора.
- `news-server`: локальный сервер новостей: источники, дедупликация, привязка к тикерам по
  алиасам, публичное хранилище, границы доступа, инструменты для бота.

### Modified Capabilities
- `llm-request-queue`: фоновые задачи разбора новостей получают слот с низким приоритетом и
  собственный вид, без срока ожидания, и не вытесняют вопросы пользователей.

## Impact

- Новый код: `mcp_servers/news/` (сервер, тесты чистых правил), `src/news_digest/` (правила,
  тексты, планировщик, команды, клиент сервера), `src/research/news_eval.py` и
  `scripts/news_eval.py`.
- Изменяемый код: `src/main.py` (регистрация, хуки запуска и остановки), `src/config.py`
  (настройки и их проверка), `src/llm_queue/rules.py` (вид задачи), `.env.example`, `Makefile`.
- Документация: `CLAUDE.md` (карта `src/`, раздел предметной области, безопасность, память),
  `src/news_digest/CLAUDE.md`, `README.md`, `/help`.
- Данные: новый публичный SQLite-файл новостей (`NEWS_DB`, не коммитится); в чате хранятся
  только chat_id, включённость и отметки о доставке. Сумм и данных портфеля нет.
- Внешние каналы: бот и сервер ходят к публичным лентам; тексты новостей уходят модели разбора
  (при облачном провайдере покидают машину оператора — решение оператора).
- Вне охвата: официальное раскрытие эмитентов, направление влияния и прогнозы, связь с
  брокером, «тихие часы», собственный выбор источников пользователем.
