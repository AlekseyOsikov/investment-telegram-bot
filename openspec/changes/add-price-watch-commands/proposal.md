# Proposal

## Why

Сервер `mcp-moex` научился по вызову клиента опрашивать цены выбранных бумаг, копить замеры и собирать сводки (изменение `add-price-watch-scheduler` в его репозитории). Пока клиента нет, эта возможность недоступна пользователю: некому вызывать сервер в нужное время и некому доставить сводку. Бот — единственный долгоживущий процесс в системе и единственный, кто может писать в Telegram, поэтому часы и доставка живут здесь. Результат для пользователя: «агент работает 24/7 и периодически присылает сводку по выбранным бумагам».

## What Changes

- Четыре команды в личном чате: `/watch <тикеры> <период опроса> <период сводки>` (задать или заменить опрос, например `/watch SBER GAZP 15m 1h`), `/watch_status`, `/watch_report` (сводка по накопленному прямо сейчас), `/watch_stop`. Модель в этом потоке не участвует: команды сами вызывают инструменты сервера, `chat_id` подставляет бот.
- Фоновый планировщик внутри процесса бота: по `next_due_at`, который вернул сервер, вызывает `watch_run_due`, рассылает готовые сводки по чатам и подтверждает доставку (`watch_ack`) только после успешной отправки. После перезапуска бота сразу выполняет вызов, чтобы доставить сводки, накопившиеся за простой. Перестраивается после `/watch` без опроса сервера «вхолостую».
- Бот сам пишет пользователю без вопроса от него: это новое поведение, оно включается только явной командой `/watch` и отключается `/watch_stop`. Если Telegram сообщает, что бот заблокирован или чат недоступен, опрос этого чата останавливается автоматически.
- Отдельный запуск сервера для планировщика: `uv run --directory <MCP_MOEX_DIR> mcp-moex --watch-db <файл>`, процесс на каждое обращение (команда, тик), без удержания между обращениями. Сервер для основного ответа smart-агента запускается по-прежнему без этого флага.
- Второй рубеж защиты для smart-агента: модели отдаются только инструменты из явного списка (`search_securities`, `get_current_price`, `get_price_history`), а не любые с пометкой «только чтение». Инструменты расписания в этот список не входят.
- Настройка оператора: возможность активна, только если задан `MCP_MOEX_DIR` (тот же каталог, что у smart-агента) и не выключена флагом; путь к файлу хранилища и тайм-аут задаются переменными окружения. Команды регистрируются и упоминаются в `/help` только при активной возможности, как исследовательские команды при `RESEARCH`.
- Тексты `/start`, `/help`, `README.md` и `CLAUDE.md` дополняются: бот хранит на диске список отслеживаемых тикеров чата и публичные замеры цен и сам присылает сводки.
- **BREAKING**: нет. Обычный поток, `/agent`, `/smart_agent` и исследовательские режимы работают как прежде; при незаданном `MCP_MOEX_DIR` бот ведёт себя точно как раньше.

## Capabilities

### New Capabilities
- `price-watch`: команды опроса цен по тикерам, фоновая выдача сводок по расписанию, доставка с подтверждением, поведение при перезапуске, блокировке бота и сбоях сервера, доступность возможности и границы данных.

### Modified Capabilities
- `smart-agent-market-tools`: модели доступны только инструменты из явного списка и только чтения (вторая линия защиты от инструментов расписания); уточнение границы «инструменты получает только основной ответ smart-агента»: оно относится к модели, а команды расписания вызывают сервер сами.
- `mcp-integration`: вызывать инструменты MCP-сервера теперь могут не только smart-агент, но и планировщик опроса цен; процесс сервера по-прежнему завершается после каждого обращения.

## Impact

- Код: новый пакет `src/price_watch/` (разбор команды, планировщик, обработчики, тексты), `src/mcp_integration/watch_session.py` (запуск сервера с `--watch-db` и вызов его инструментов), правки `src/mcp_integration/market_session.py` (список разрешённых инструментов), `src/config.py` (переменные окружения и проверка), `src/main.py` (регистрация обработчиков, запуск и остановка планировщика, `/help`, `/start`).
- Зависимости: новых пакетов нет; планировщик на `asyncio` (без `job-queue` и APScheduler).
- Диск: файл SQLite сервера в каталоге `data/` (в `.gitignore`); в нём идентификатор чата, тикеры, настройки опроса, публичные цены и готовые сводки. Данных, которые пользователь пишет в диалогах, там нет.
- Внешние системы: запросы к ISS выполняет сервер; бот отправляет сообщения в Telegram по инициативе планировщика.
- Зависит от изменения `add-price-watch-scheduler` в репозитории `mcp-moex` (реализовано; контракт сверен с кодом сервера). Без флага `--watch-db` на стороне сервера бот работать с расписанием не сможет.
- Документация: `README.md`, `.env.example`, `CLAUDE.md` (раздел про MCP, «Ограничения безопасности», правила предметной области: бот теперь пишет сам).
