# Spec Delta

## Purpose

Offline-пайплайн, разбивающий локальный корпус документов бота (PDF/txt) на чанки
двумя независимыми стратегиями, строящий эмбеддинги для каждого чанка и
сохраняющий индекс FAISS+SQLite на каждую стратегию отдельно — чтобы обе стратегии
можно было изучить и сравнить из командной строки и из бота, прежде чем решать,
встраивать ли поиск по документам в ответы какого-либо агента.

## ADDED Requirements

### Requirement: Разбор метаданных из имени файла
Пайплайн индексации SHALL разбирать имя каждого исходного файла в форме
`<Title>(<author>, <date>).<ext>`, где скобочный суффикс и оба значения внутри него
— `author` и `date` — не обязательны, и SHALL извлекать метаданные `title`,
`author` и `date`, не изменяя исходный файл на диске.

#### Scenario: Указаны и автор, и дата
- **WHEN** имя файла содержит автора и дату, разделённые запятой внутри скобок
  (например, `Обзор рынка облигаций (author_name, 22.07.2026).txt`)
- **THEN** пайплайн извлекает `title = "Обзор рынка облигаций"`,
  `author = "author_name"`, `date = "22.07.2026"`

#### Scenario: Указана только дата
- **WHEN** скобочная часть имени файла содержит одно значение, совпадающее с
  форматом даты (например,
  `Разбор портфеля на примере (23.12.2026).txt`)
- **THEN** пайплайн извлекает это значение как `date`, а `author` оставляет
  не заданным

#### Scenario: Указан только автор
- **WHEN** скобочная часть имени файла содержит одно значение, не совпадающее с
  форматом даты (например, `Основы диверсификации (Иванов).pdf`)
- **THEN** пайплайн извлекает это значение как `author`, а `date` оставляет
  не заданным

#### Scenario: Скобочного суффикса нет вовсе
- **WHEN** у имени файла нет скобочного суффикса
- **THEN** пайплайн использует всё имя файла (без расширения) как `title`, а
  `author` и `date` оставляет не заданными

#### Scenario: Исходные файлы никогда не изменяются
- **WHEN** индексация файла завершена
- **THEN** исходный файл остаётся по тому же пути и с тем же именем, побайтово не
  изменённым

### Requirement: Извлечение и очистка текста
Пайплайн SHALL извлекать простой текст из каждого исходного файла (PDF или txt) и
SHALL удалять пустые строки и пустые абзацы из извлечённого текста перед
разбиением на чанки.

#### Scenario: Пустые строки и артефакты страниц PDF удалены
- **WHEN** PDF содержит пустые строки между абзацами или артефакты разрывов
  страниц
- **THEN** текст, используемый для чанкинга, не содержит пустых строк и пустых
  абзацев

#### Scenario: Нет чанков только из пробелов
- **WHEN** txt-файл содержит несколько подряд идущих пустых строк
- **THEN** очищенный текст схлопывает их, и ни один получившийся чанк не состоит
  только из пробельных символов

### Requirement: Стратегия чанкинга по фиксированному размеру
Пайплайн SHALL предоставлять стратегию чанкинга по фиксированному размеру,
разбивающую очищенный текст документа на перекрывающиеся окна настраиваемой
длины в символах.

#### Scenario: Длина чанка ограничена
- **WHEN** очищенный текст документа индексируется стратегией фиксированного
  размера
- **THEN** каждый получившийся чанк не длиннее настроенной максимальной длины,
  кроме случая, когда сам неразбиваемый фрагмент текста длиннее этого предела

#### Scenario: Соседние чанки перекрываются
- **WHEN** из одного документа получены идущие подряд чанки фиксированного
  размера
- **THEN** каждый чанк, кроме первого, перекрывает хвост предыдущего чанка на
  настроенную длину перекрытия

### Requirement: Стратегия чанкинга по структуре
Пайплайн SHALL предоставлять стратегию чанкинга по структуре, разбивающую
документ по обнаруженным структурным границам — строкам-заголовкам, а для PDF ещё
и по границам страниц — с откатом к одному чанку на документ (или на страницу),
если заголовок не обнаружен.

#### Scenario: Строка-заголовок начинает новую секцию
- **WHEN** txt-документ содержит короткую самостоятельную строку без завершающего
  знака препинания предложения, за которой следует абзац
- **THEN** пайплайн считает эту строку заголовком секции и начинает с неё новый
  чанк

#### Scenario: Страницы PDF — структурные единицы
- **WHEN** извлечённый текст PDF-документа содержит маркеры разрыва страниц
- **THEN** пайплайн считает каждую страницу структурной единицей и применяет
  обнаружение заголовков внутри страницы, разбивая её дополнительно, если там
  найдена строка-заголовок

#### Scenario: Заголовок не найден — откат к одному чанку
- **WHEN** в документе или странице PDF не обнаружено ни одного заголовка
- **THEN** пайплайн выдаёт этот документ (или эту страницу) целиком как один
  чанк в рамках структурной стратегии

### Requirement: Построение эмбеддингов чанков
Пайплайн SHALL строить вектор эмбеддинга для каждого чанка, полученного обеими
стратегиями, обращаясь к OpenAI-совместимому эндпоинту эмбеддингов локально
доступного сервера Ollama с настроенной моделью эмбеддингов.

#### Scenario: Эмбеддинг запрашивается перед сохранением
- **WHEN** CLI индексирует чанк
- **THEN** он запрашивает эмбеддинг этого чанка у настроенного эндпоинта и модели
  Ollama до сохранения чанка

#### Scenario: Сбой построения эмбеддинга не оставляет частичный индекс
- **WHEN** эндпоинт Ollama недоступен или возвращает ошибку во время индексации
  стратегии
- **THEN** CLI останавливается с понятным сообщением об ошибке и не сохраняет
  частично построенный индекс для обрабатываемой в этот момент стратегии

### Requirement: Хранение индекса по стратегиям
Пайплайн SHALL сохранять чанки, эмбеддинги и метаданные (`source`, `title`,
`author`, `date`, `chunk_id`) каждой стратегии чанкинга в СВОЮ отдельную пару
файлов — векторный индекс FAISS и базу метаданных SQLite — независимо от файлов
другой стратегии.

#### Scenario: У каждой стратегии свои независимые файлы
- **WHEN** CLI завершает индексацию
- **THEN** существуют два независимых набора файлов индекса, по одному на
  стратегию, каждый из которых можно опросить без обращения к файлам другой
  стратегии

#### Scenario: Полная пересборка при повторном запуске
- **WHEN** CLI запускается повторно
- **THEN** существующие файлы индекса каждой стратегии полностью пересобираются
  из текущего содержимого `data/source/`, а не дополняются поверх устаревших
  записей

#### Scenario: chunk_id разрешается в пределах своей стратегии
- **WHEN** метаданные чанка сохраняются
- **THEN** его `chunk_id` уникален в пределах индекса своей стратегии и
  разрешается в соответствующую строку вектора FAISS той же стратегии

### Requirement: Точка входа индексации из командной строки
Система SHALL предоставлять команду командной строки, индексирующую каждый
PDF-файл из `data/source/pdf/` и каждый txt-файл из `data/source/txt/` обеими
стратегиями чанкинга, независимо от процесса Telegram-бота.

#### Scenario: Весь корпус индексируется за один запуск
- **WHEN** команда индексации запущена без аргументов
- **THEN** она обрабатывает каждый `.pdf`-файл в `data/source/pdf/` и каждый
  `.txt`-файл в `data/source/txt/` и сообщает, сколько чанков получено по каждой
  стратегии

#### Scenario: Пустой каталог с исходниками обработан корректно
- **WHEN** `data/source/pdf/` или `data/source/txt/` не содержит файлов
- **THEN** команда индексации завершается без ошибки и сообщает, что по этому
  типу источника обработано ноль документов

### Requirement: Команда бота со статистикой чанкинга
Бот SHALL предоставлять команду, доступную только при включённом RESEARCH,
которая выводит статистику по количеству и размеру чанков для обеих стратегий
чанкинга на основе сохранённых индексов, без повторного запуска пайплайна
разбиения.

#### Scenario: Статистика выведена по обеим стратегиям
- **WHEN** RESEARCH включён и индексы обеих стратегий существуют
- **THEN** вызов команды отвечает как минимум общим числом чанков и
  средним/минимальным/максимальным размером чанка для каждой стратегии

#### Scenario: Индекс ещё не построен
- **WHEN** RESEARCH включён, но индексы ещё не построены
- **THEN** вызов команды отвечает сообщением на русском языке о том, что сначала
  нужно построить индекс, вместо необработанного исключения

#### Scenario: Команда скрыта при выключенном RESEARCH
- **WHEN** RESEARCH выключен
- **THEN** команда не регистрируется и не упоминается в `/help`

### Requirement: Команда бота для сравнения стратегий чанкинга
Бот SHALL предоставлять команду, доступную только при включённом RESEARCH,
которая принимает произвольный текстовый запрос, строит его эмбеддинг тем же
клиентом эмбеддингов, что используется при индексации, находит наиболее похожие
чанки в индексе каждой стратегии и показывает результаты обеих стратегий рядом
для сравнения.

#### Scenario: Запрос сравнивается по обеим стратегиям
- **WHEN** RESEARCH включён и пользователь отправляет запрос, пока индексы обеих
  стратегий существуют
- **THEN** бот отвечает наиболее похожими чанками отдельно от стратегии
  фиксированного размера и отдельно от структурной стратегии, и для каждого
  найденного чанка показывает как минимум заголовок источника, оценку похожести
  и его метаданные (исходный файл, автор и дата из имени файла, если есть, номер
  чанка внутри документа)

#### Scenario: Эндпоинт эмбеддингов недоступен во время запроса
- **WHEN** эндпоинт эмбеддингов Ollama недоступен во время обработки запроса (после
  внутреннего повтора — Requirement «Построение эмбеддингов»)
- **THEN** бот отвечает сообщением об ошибке на русском языке вместо
  необработанного исключения и остаётся в режиме ожидания следующего запроса, а не
  завершает диалог — команда рассчитана на несколько запросов подряд, и разовый сбой
  одного из них не должен требовать повторного вызова команды

#### Scenario: Команда скрыта при выключенном RESEARCH
- **WHEN** RESEARCH выключен
- **THEN** команда не регистрируется и не упоминается в `/help`
