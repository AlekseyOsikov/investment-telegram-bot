# Proposal

## Why

Сейчас у бота нет способа опираться на собственный корпус документов пользователя
(PDF/txt-материалы по инвестициям в `data/source/`). Прежде чем встраивать поиск по
документам в какого-либо агента, нужен воспроизводимый offline-пайплайн, который
разбивает эти документы на чанки двумя разными способами, строит эмбеддинги для
каждого чанка и сохраняет отдельный индекс на каждую стратегию — чтобы сравнить
и изучить эти два подхода к чанкингу до того, как на один из них будет что-то
завязано.

## What Changes

- Новая команда командной строки (`python -m rag.cli`, также через `make index`),
  индексирующая каждый PDF/txt-файл из `data/source/pdf/` и `data/source/txt/`:
  разбирает имя файла вида `<Title>(<author>, <date>).<ext>` в метаданные (author
  и/или date могут отсутствовать), убирает пустые строки/абзацы из извлечённого
  текста и строит чанки ДВУМЯ независимыми стратегиями:
  - **По фиксированному размеру**: символьное окно с перекрытием.
  - **По структуре**: секции по эвристике заголовков (короткая самостоятельная
    строка без завершающей знаков препинания предложения, за которой следует
    абзац); для PDF первым уровнем структуры служат границы страниц (по
    form-feed-маркерам из `pdftotext`), эвристика заголовков применяется внутри
    страницы; файл/страница без обнаруженного заголовка становится одним чанком
    целиком.
  - Исходные файлы в `data/source/` никогда не переименовываются и не изменяются —
    метаданные из имени файла разбираются только в индекс.
- Извлечение текста из PDF идёт через системную утилиту `pdftotext` (poppler) —
  без новой Python-зависимости для разбора PDF.
- Каждый чанк получает эмбеддинг через локально запущенный сервер Ollama (модель
  `bge-m3`, OpenAI-совместимый эндпоинт `/v1/embeddings`, по умолчанию
  `http://localhost:11434/v1`) через новый `providers/embeddings_client.py`,
  построенный на том же SDK `openai`, что уже используют
  `providers/deepseek_client.py`/`providers/kimi_client.py`.
- Чанки, эмбеддинги и метаданные (`source`, `title`, `author`, `date`, `chunk_id`)
  каждой стратегии сохраняются в СВОЮ пару файлов: индекс FAISS и база метаданных
  SQLite, в `data/rag_index/<strategy>/`. Повторный запуск CLI полностью
  пересобирает оба индекса заново (корпус небольшой; инкрементального обновления
  нет).
- Новая доступная только при `RESEARCH` команда бота `/research_chunking_stats`:
  читает оба сохранённых индекса и выводит статистику по количеству и размеру
  чанков для каждой стратегии рядом друг с другом.
- Новая доступная только при `RESEARCH` команда бота `/research_chunking_compare`:
  `ConversationHandler`, который запрашивает произвольный текстовый запрос,
  строит его эмбеддинг тем же клиентом Ollama, ищет по обоим индексам FAISS и
  показывает топ-k найденных чанков от каждой стратегии рядом для сравнения.
- Обе новые команды бота при недоступности индекса или сервера Ollama отвечают
  понятным сообщением на русском языке, а не падают — зависимость от эмбеддингов
  нужна только CLI и этим двум командам, а не основному потоку бота
  (`handle_message`, `/agent`, `/smart_agent` не затрагиваются).
- Новая зависимость: `faiss-cpu` в `requirements.txt`.

## Capabilities

### New Capabilities
- `rag-indexing`: offline-пайплайн разбиения на чанки/эмбеддингов/хранения индекса
  и две команды бота в режиме RESEARCH для изучения и сравнения двух стратегий
  чанкинга.

### Modified Capabilities
(нет — требования ни одной существующей capability не меняются)

## Impact

- **Новый код**: пакет `rag/` (разбор имени файла и текста, обе стратегии
  чанкинга, хранение индекса FAISS+SQLite, точка входа CLI);
  `providers/embeddings_client.py` (клиент эмбеддингов Ollama);
  `research/chunking_stats.py` и `research/chunking_compare.py` (команды бота по
  образцу существующих `research/*`, переиспользующие обработку ошибок из
  `research/_shared.py`, т.к. Ollama вызывается через тот же SDK `openai`).
- **Изменяемые файлы**: `main.py` (регистрация двух новых обработчиков под
  `RESEARCH_ENABLED`, обновление `/help`), `config.py` и `.env.example` (новые
  настройки `RAG_*`/`EMBEDDINGS_*`), `requirements.txt` (добавление
  `faiss-cpu`), `Makefile` (новая цель `index`), `CLAUDE.md` (документирование
  нового модуля по принятому в проекте формату).
- **Новая зависимость времени выполнения**: локально доступный сервер Ollama с
  загруженной моделью `bge-m3`. Нужен только для CLI и двух новых команд
  RESEARCH — его отсутствие не должно блокировать запуск бота и не влияет на
  остальные команды.
- **Новые данные на диске**: `data/rag_index/` (в `.gitignore`, как и остальной
  `data/`) с файлами FAISS+SQLite обеих стратегий. Обе команды бота зависят от
  того, что этот индекс уже построен CLI заранее.
