# Proposal

## Why

Слой `tools` даёт основному ответу `/smart_agent` поиск бумаги, цену и историю, но
осмыслить историю (просадка, волатильность, сравнение с индексом или с другой бумагой)
модель может только в уме — это дорого по токенам и ненадёжно по арифметике. Сервер
`mcp-moex` теперь считает это сам тремя новыми инструментами (`compute_price_metrics`,
`compare_with_benchmark`, `compare_securities`), которые принимают историю цен целиком
(изменение `add-price-analytics` в его репозитории, заархивировано). Чтобы запрос вроде
«сравни изменение цен за 2025 год по месяцам акций Сбербанка с индексом Мосбиржи»
проходил цепочкой «найти тикеры → получить две истории → сравнить», данные между шагами
не должна пересказывать модель: перепечатывая свечи, она их искажает, сокращает и тратит
на это токены. Бот передаёт их сам, а модель лишь называет результат предыдущего шага.

## What Changes

- Модели предоставляются три новых инструмента чтения сервера (перечень разрешённых
  инструментов расширяется с трёх до шести; условие «сервер сам пометил инструмент как
  только читающий» остаётся обязательным).
- Пока модели предоставлен хотя бы один инструмент анализа, результаты успешных вызовов
  `get_price_history` запоминаются в памяти сессии одного вопроса под короткими именами
  (`r1`, `r2`, …); имя модель узнаёт из пометки в сообщении с результатом. Хранится полный
  результат, как его вернул сервер, а не усечённый текст, который видит модель.
- Параметры с историей у трёх новых инструментов (`history`, `benchmark_history`,
  `history_a`, `history_b`) принимают от модели только ссылку `{"ref": "rN"}`: схема,
  которую видит модель, для них так и описывается, а вместо ссылки история, значение
  иного вида, неизвестное имя или лишние поля возвращаются модели ошибкой без вызова
  сервера. Перед вызовом бот подставляет вместо ссылки сохранённый результат, так что
  серверу данные уходят целиком «по значению» и дословно в том виде, в каком он их выдал.
  Модель не может вызвать анализ по выдуманным данным.
- Сообщение слоя `tools` становится динамическим и учит модель цепочке: сегодняшняя дата
  (по Москве); выбор интервала по границам периода (границы месяцев — `month`, даже
  если разбивку не просили: недельные свечи выбираются по дате начала и дают неверные
  границы, а дневных свечей на год у акций с выходными торгами больше предела в 300);
  `date_from`/`date_till` по границам месяца; умолчания при выборе бумаги (обыкновенные
  акции, ценовой IMOEX); выбор между двумя видами сравнения; передача ссылок; числа и
  предупреждения берутся из результата. Правила добавляются только если сервер
  действительно опубликовал инструменты анализа; со старым сервером сообщение прежнее.
- `MCP_MAX_TOOL_STEPS` по умолчанию поднимается с 5 до 8: цепочка «поиск → история →
  сравнение» при вызовах по одному, а тем более сравнение нескольких бумаг, не должна
  упираться в лимит. У операторов, задавших значение в `.env`, поведение не меняется.
- Проверка (тесты и ручной прогон на живом ISS): подстановка, отказы и цикл проверяются
  офлайн на фейках; четыре запроса из обсуждения (год и период «сентябрь–август», с
  разбивкой по месяцам и без) — вручную, с известными ожидаемыми числами.
- **BREAKING**: нет. Без инструментов анализа, для остальных режимов бота и для результата
  `get_price_history` (он для модели не урезается — осознанно) поведение не меняется.

## Capabilities

### New Capabilities
Нет: изменение расширяет существующую возможность.

### Modified Capabilities
- `smart-agent-market-tools`: перечень разрешённых модели инструментов расширен;
  граница данных «серверу уходят только аргументы модели» уточнена (результаты сервера,
  подставленные по ссылке); добавлены требования про ссылки на результаты истории, про
  передачу данных в инструменты анализа только по ссылке и про сообщение слоя с датой и
  правилами цепочки.

## Impact

- Код: `src/mcp_integration/market_session.py` (реестр результатов сессии, разбор и
  подстановка ссылок, подмена схемы четырёх параметров, перечень разрешённых
  инструментов), `src/agents/market_tools.py` (сообщение слоя с датой и правилами
  цепочки, тексты пометки о ссылке и ошибок ссылок), `src/agents/smart_agent.py`
  (передача даты и признака «инструменты анализа есть» в сообщение слоя),
  `src/config.py` и `.env.example` (умолчание `MCP_MAX_TOOL_STEPS`). Цикл
  `run_tool_loop` и классы результатов не меняются.
- Тесты: `tests/test_market_tools.py` (перечень из шести инструментов; чистые функции
  ссылок и схемы; сообщение слоя; цикл на фейках с проверкой, что серверу пришёл ровно
  сохранённый результат) — без сети и процессов, как остальные тесты слоя.
- Документация: `CLAUDE.md` (перечень инструментов слоя, ссылки, абзац «Данные наружу»,
  умолчание лимита шагов), `README.md`, `.env.example`.
- Зависимости: новых нет.
- Внешние системы: сервер `mcp-moex` с `add-price-analytics` (заархивирован); со старым
  сервером без инструментов анализа слой работает как раньше.
- Ограничения проверки: цикл проверен только на DeepSeek, для Kimi нужен отдельный
  спайк, как и для остальных частей слоя.
- Не входит: команда `/analyze` и любой оркестратор цепочки вне модели, урезание результата
  `get_price_history` для модели, ссылки между вопросами и на диске, инструменты анализа
  для других режимов бота, серверное замечание о несовпадении периода расчёта с
  запрошенным (отложено: сначала проверяется, хватает ли правила в сообщении слоя).
