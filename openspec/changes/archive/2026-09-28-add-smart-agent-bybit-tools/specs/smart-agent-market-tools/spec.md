# Spec Delta

## MODIFIED Requirements

### Requirement: Сервер рыночных данных задаётся оператором

Система SHALL получать инструменты рыночных данных от одного или нескольких
локальных MCP-серверов, каждый запускаемый как отдельный дочерний процесс. Каждый
источник настраивается независимо: каталог проекта сервера Московской биржи
(`mcp-moex`) задаётся параметром окружения `MCP_MOEX_DIR`, каталог проекта сервера
Bybit (`mcp-bybit`) — параметром `MCP_BYBIT_DIR`. Команду запуска для каждого
источника система SHALL собирать сама из заданного каталога и известного системе
имени программы этого источника (`mcp-moex`/`mcp-bybit`), без обращения к оболочке
командной строки, так что значение параметра не может внедрить произвольную команду.
Пока ни один параметр не задан, возможность SHALL быть неактивной, и бот SHALL
работать как раньше, без предупреждений пользователям. Незаданность одного параметра
NOT SHALL влиять на источник, заданный другим параметром: у чата, где задан только
`MCP_MOEX_DIR`, слой работает как раньше, отдавая инструменты только Московской
биржи.

Пользователь чата NOT SHALL иметь возможности задать, изменить или выбрать каталог,
команду запуска, источник или набор источников — ни командой, ни аргументом, ни
текстом сообщения. Это настройка оператора, изменяемая только правкой окружения и
перезапуском процесса. Источники рыночных данных SHALL быть независимы от сервера,
используемого командой списка инструментов (`/mcp_tools`): настройка любого из них
не влияет на другие.

Если параметр источника задан, но каталог не существует или в нём нет проекта
сервера, система SHALL записать предупреждение в журнал при запуске бота и NOT SHALL
останавливать бота; это не влияет на другой источник, если он настроен верно.

#### Scenario: Оба источника настроены

- **WHEN** оператор задал оба каталога (`MCP_MOEX_DIR` и `MCP_BYBIT_DIR`) и
  пользователь задаёт вопрос smart-агенту
- **THEN** система запускает по одному процессу на каждый источник и предоставляет
  модели инструменты обоих

#### Scenario: Каталог задан

- **WHEN** задан только `MCP_MOEX_DIR` (или только `MCP_BYBIT_DIR`), а другой параметр
  пуст, и пользователь задаёт вопрос smart-агенту
- **THEN** система запускает сервер настроенного источника и предоставляет модели его
  инструменты; второй источник не запускается и не упоминается

#### Scenario: Каталог не задан

- **WHEN** оба параметра не заданы и пользователь задаёт вопрос smart-агенту
- **THEN** агент отвечает как раньше, без инструментов, ни один процесс не
  запускается, а пользователю не показывается ни предупреждений, ни упоминаний о
  недоступности данных

#### Scenario: Каталог задан неверно

- **WHEN** `MCP_BYBIT_DIR` задан, но указанного каталога не существует, а
  `MCP_MOEX_DIR` настроен верно
- **THEN** при запуске бота в журнал пишется предупреждение про источник Bybit, бот
  запускается и работает, вопросы smart-агенту получают инструменты MOEX, а Bybit
  обрабатывается по правилам недоступного источника

#### Scenario: Пользователь пытается подменить сервер

- **WHEN** пользователь присылает в чате путь, команду запуска или просьбу
  подключиться к другому серверу или выбрать источник
- **THEN** система не меняет источники и использует только те, что настроил оператор

#### Scenario: Сервер команды списка инструментов не затронут

- **WHEN** оператор задал каталоги источников рыночных данных
- **THEN** команда списка инструментов подключается к своему серверу, как и раньше, а
  не к источникам рыночных данных

### Requirement: Модель вызывает инструменты в ходе ответа

Пока слой инструментов включён и хотя бы один источник доступен, система SHALL
передавать модели описания инструментов ВСЕХ доступных источников при основном ответе
smart-агента, а модель SHALL решать сама, вызывать ли их и какого источника. Каждый
результат вызова система SHALL возвращать модели, а модель SHALL продолжать до
финального ответа. За один шаг модель может запросить несколько вызовов, в том числе
к разным источникам; система SHALL выполнить каждый и вернуть ответ на каждый.

Число шагов вызова инструментов на один вопрос SHALL быть ограничено одним общим
значением из конфигурации, независимо от того, к скольким источникам обращается
модель. Если лимит исчерпан, система SHALL всё равно завершить вопрос ответом модели,
сформированным без дальнейших вызовов, и SHALL сообщить пользователю, что лимит шагов
исчерпан. Вопрос NOT SHALL оставаться без ответа из-за лимита.

Система SHALL запускать процесс каждого настроенного и включённого источника один раз
на вопрос пользователя и использовать его для всех вызовов этого источника в рамках
этого вопроса.

#### Scenario: Вопрос о цене

- **WHEN** пользователь спрашивает, сколько сейчас стоит бумага или пара, слой
  инструментов включён и соответствующий источник доступен
- **THEN** модель вызывает инструмент этого источника, получает данные и отвечает на
  их основе, а пользователь видит ответ с ценой и временем котировки

#### Scenario: Несколько вызовов за один шаг

- **WHEN** модель в одном шаге запрашивает данные по двум бумагам одного источника
- **THEN** система выполняет оба вызова, возвращает оба результата, и модель отвечает
  по обеим бумагам

#### Scenario: Вызовы инструментов разных источников в одном шаге

- **WHEN** модель в одном шаге запрашивает и цену бумаги MOEX, и цену пары Bybit
- **THEN** система выполняет оба вызова к соответствующим источникам и возвращает оба
  результата, а модель отвечает по обоим вопросам

#### Scenario: Вопрос без рыночных данных

- **WHEN** пользователь задаёт вопрос, для которого модель не запрашивает инструменты
- **THEN** ответ формируется без вызовов, а пользователю не выводятся строки о
  вызовах

#### Scenario: Лимит шагов исчерпан

- **WHEN** модель продолжает запрашивать инструменты после достижения общего лимита
  шагов
- **THEN** система прекращает вызовы, запрашивает у модели финальный ответ без
  инструментов, отправляет его пользователю и сообщает, что лимит шагов исчерпан

### Requirement: Модели доступны только инструменты чтения

Система SHALL предоставлять модели только те инструменты каждого источника, которые
одновременно удовлетворяют двум условиям: сервер этого источника сам пометил их как
предназначенные только для чтения, и они входят в явный перечень разрешённых системой
инструментов ЭТОГО источника. У каждого источника — свой перечень разрешённых
инструментов (для MOEX: поиск бумаг, текущая цена, история цен, метрики по истории,
сравнение бумаги с индексом, сравнение двух бумаг; для Bybit: поиск пары, текущая
цена, история цен, метрики по истории, сравнение пары с эталоном, сравнение двух
пар). Инструмент, не удовлетворяющий любому из условий, NOT SHALL предоставляться
модели и NOT SHALL вызываться, даже если модель назовёт его имя. Оба сервера для
ответа smart-агента SHALL запускаться без режима расписания (сервер Bybit его вообще
не поддерживает), поэтому инструменты расписания им не публикуются; перечень
разрешённых инструментов — вторая линия защиты на случай ошибки конфигурации.

Имя инструмента, предоставляемое модели, SHALL нести признак источника (например,
префикс), чтобы модель могла однозначно выбрать, к какому источнику относится вызов,
даже когда два источника публикуют инструмент с одинаковым именем. Система SHALL
сопоставлять вызов модели с инструментом того источника, на который указывает
признак, и NOT SHALL вызывать инструмент другого источника по такому имени.

#### Scenario: Инструмент только для чтения

- **WHEN** сервер источника сообщает инструмент из перечня разрешённых этого
  источника с пометкой «только чтение»
- **THEN** инструмент предоставляется модели под именем с признаком этого источника

#### Scenario: Инструменты анализа предоставляются

- **WHEN** сервер источника сообщает метрики по истории, сравнение с эталоном и
  сравнение двух бумаг/пар с пометкой «только чтение»
- **THEN** все три инструмента этого источника предоставляются модели

#### Scenario: Инструмент без пометки

- **WHEN** сервер источника сообщает инструмент без пометки «только чтение»
- **THEN** инструмент не предоставляется модели, а попытка вызвать его по имени
  возвращается модели как ошибка, и вызова сервера не происходит

#### Scenario: Инструмент только для чтения вне перечня

- **WHEN** сервер источника сообщает инструмент с пометкой «только чтение», которого
  нет в перечне разрешённых этого источника
- **THEN** инструмент не предоставляется модели, а попытка вызвать его по имени
  возвращается модели как ошибка, и вызова сервера не происходит

#### Scenario: Инструменты расписания недоступны модели

- **WHEN** сервер какого-либо источника по какой-либо причине сообщает инструменты
  расписания опроса цен
- **THEN** ни один из них не предоставляется модели и не вызывается по её просьбе

#### Scenario: Одинаковое имя инструмента у двух источников

- **WHEN** оба источника публикуют инструмент с одинаковым именем (например,
  `get_current_price`)
- **THEN** модель получает два различимых по признаку источника инструмента и не
  может вызвать инструмент одного источника, указав признак другого

### Requirement: Результаты истории цен доступны модели по ссылке

Пока модели предоставлен хотя бы один инструмент анализа истории цен КАКОГО-ЛИБО
источника, система SHALL запоминать в памяти сессии одного вопроса каждый успешный
результат инструмента истории цен ЭТОГО источника под коротким именем в порядке
получения (`r1`, `r2`, …) и SHALL сообщать это имя модели в том же сообщении с
результатом. Реестр имён SHALL вестись ОТДЕЛЬНО по каждому источнику: имя выдаётся в
пределах результатов этого источника, и одноимённые ссылки разных источников
(например, `r1` у MOEX и `r1` у Bybit) относятся к разным сохранённым результатам.
Пометка с именем SHALL сохраняться, даже если результат передаётся модели усечённым
по пределу размера, и объём сообщения вместе с пометкой NOT SHALL превышать этот
предел. Хранимым значением SHALL быть полный результат в том виде, в каком его
вернул сервер, а не текст, переданный модели. Результат другого инструмента, а также
любая ошибка вызова NOT SHALL получать имя. Имена SHALL действовать только в
пределах вопроса, в котором они выданы: следующий вопрос начинается без имён, а
результаты NOT SHALL сохраняться на диск или в память агента. Если инструментов
анализа среди предоставленных модели для источника нет, имена для результатов этого
источника NOT SHALL выдаваться, а сообщения с его результатами SHALL оставаться
такими же, как до появления инструментов анализа.

#### Scenario: Успешная история получает имя

- **WHEN** модель вызывает инструмент истории цен источника, сервер возвращает
  результат, и модели предоставлены инструменты анализа этого источника
- **THEN** модель получает результат вместе с пометкой о том, под каким именем он
  сохранён

#### Scenario: Пометка не пропадает при усечении

- **WHEN** результат истории превышает предел размера и передаётся модели усечённым
- **THEN** сообщение по-прежнему содержит имя, под которым сохранён полный результат,
  а его объём вместе с пометками не превышает предела

#### Scenario: Ошибка и другие инструменты без имени

- **WHEN** вызов истории завершился ошибкой сервера или модель вызвала поиск бумаги
  либо текущую цену
- **THEN** результат не получает имени

#### Scenario: Имена не переживают вопрос

- **WHEN** пользователь задаёт следующий вопрос, а модель ссылается на имя из
  предыдущего вопроса
- **THEN** модель получает ошибку о неизвестной ссылке, вызова сервера не происходит

#### Scenario: Сервер без инструментов анализа

- **WHEN** сервер источника не публикует инструментов анализа и модель получает
  результат истории этого источника
- **THEN** сообщение с результатом не содержит пометки об имени, как до появления
  инструментов анализа

#### Scenario: Ссылки источников не пересекаются

- **WHEN** модель получила историю от MOEX под именем `r1` и историю от Bybit под
  именем `r1`
- **THEN** оба результата хранятся отдельно, и каждая ссылка `r1` разрешается в
  инструментах анализа именно того источника, чей результат под этим именем сохранён

### Requirement: Данные инструментов анализа передаются только по ссылке

Параметры инструментов анализа, принимающие историю цен (`history` у метрик,
`history` и `benchmark_history` у сравнения с эталоном, `history_a` и `history_b` у
сравнения двух бумаг/пар), SHALL принимать от модели только ссылку вида
`{"ref": "rN"}` на результат истории ТОГО ЖЕ источника, что и сам инструмент анализа,
полученный в этом же вопросе. Описание параметров этих инструментов, передаваемое
модели, SHALL представлять их именно как ссылку, а не как структуру истории. Перед
вызовом сервера система SHALL заменить каждую ссылку сохранённым результатом, так что
серверу SHALL передаваться результат в том виде, в каком сервер его выдал, без
изменений. Система NOT SHALL передавать серверу в этих параметрах данные,
сформированные моделью.

Ссылка, выданная в ответ на инструмент истории одного источника, SHALL приниматься
только инструментами анализа ТОГО ЖЕ источника; передача такой ссылки инструменту
анализа другого источника NOT SHALL приводить к обращению к серверу.

Система SHALL возвращать модели ошибкой, без обращения к серверу, вызов, где в таком
параметре передана история вместо ссылки, значение иного вида, ссылка на неизвестное
имя (в том числе имя из другого источника) или ссылка с лишними полями. Ссылку в
любом другом параметре любого инструмента система SHALL отклонять так же. Текст
ошибки SHALL называть параметр, объяснять, как передавать ссылку, и перечислять
доступные имена ЭТОГО источника. Одна и та же ссылка SHALL допускаться в нескольких
вызовах одного вопроса.

#### Scenario: Сравнение бумаги с индексом по ссылкам

- **WHEN** пользователь просит сравнить изменение цены бумаги за период с индексом
  Московской биржи, а модель нашла оба тикера, получила обе истории инструментом
  MOEX и вызвала сравнение MOEX с эталоном, передав ссылки на обе истории
- **THEN** серверу MOEX передаются обе истории целиком в том виде, в каком он их
  выдал, а модель отвечает по результату сравнения

#### Scenario: Данные вместо ссылки

- **WHEN** модель передаёт в параметр истории структуру со свечами вместо ссылки
- **THEN** модель получает ошибку с объяснением, что нужно передать ссылку, и вызова
  сервера не происходит

#### Scenario: Неизвестная ссылка

- **WHEN** модель передаёт ссылку на имя, которого нет среди выданных в этом вопросе
  для инструментов этого источника
- **THEN** модель получает ошибку со списком доступных имён этого источника, и вызова
  сервера не происходит

#### Scenario: Ссылка чужого источника отклонена

- **WHEN** модель передаёт инструменту анализа Bybit ссылку, выданную на результат
  истории MOEX (или наоборот)
- **THEN** модель получает ошибку о том, что ссылка относится к другому источнику, и
  вызова сервера не происходит

#### Scenario: Ссылка в постороннем параметре

- **WHEN** модель передаёт ссылку в параметр, не предназначенный для истории,
  например вместо тикера
- **THEN** модель получает ошибку, и вызова сервера не происходит

#### Scenario: Одна история в двух сравнениях

- **WHEN** модель вызывает два сравнения бумаг одного источника с эталоном и передаёт
  в обоих одну и ту же ссылку на историю эталона
- **THEN** оба вызова выполняются, и серверу этого источника в каждом уходит история
  эталона целиком

#### Scenario: Описание параметров говорит о ссылке

- **WHEN** модели передаются описания инструментов анализа любого источника
- **THEN** параметры с историей описаны как ссылка на результат истории цен этого
  источника, а не как структура со свечами

#### Scenario: Вызов показан коротко

- **WHEN** ответ построен с вызовом сравнения по ссылкам
- **THEN** в служебной строке вызов показан со ссылками, а не с подставленными
  данными

### Requirement: Сообщение слоя сообщает дату и правила цепочки анализа

Пока слой включён и хотя бы один источник доступен, система SHALL добавлять в
контекст основного ответа сообщение о работе с инструментами, которое называет
КАЖДЫЙ доступный источник по имени и назначению (Московская биржа — акции,
облигации, фонды и индексы РФ, тикеры вида `SBER`; Bybit — спотовые пары
криптовалют, символы вида `BTCUSDT`) и указывает, что имена инструментов несут
признак источника. Если доступен только один источник, сообщение SHALL называть
только его, без упоминания недоступных или ненастроенных источников.

Для КАЖДОГО источника, который опубликовал модели инструменты анализа истории,
сообщение SHALL дополнительно содержать отдельный абзац с правилами цепочки анализа
ЭТОГО источника:
- называть сегодняшнюю дату по московскому времени, определяемую в момент вопроса
  (единая дата для всех источников);
- предписывать получать историю инструментом истории цен ЭТОГО источника с одним и
  тем же интервалом и периодом и передавать её по ссылке ЭТОГО источника
  инструментам анализа ТОГО ЖЕ источника;
- для источника Московской биржи — правила выбора интервала по границам периода, дат
  начала и конца месячных/недельных свечей и умолчаний по бумаге/индексу, в точности
  как до появления второго источника;
- для источника Bybit — правила выбора интервала и периода истории, подходящие
  спотовому рынку, торгующемуся непрерывно, без выходных и праздничных пропусков
  торгов, и умолчание по эталону сравнения, если пользователь не назвал вторую пару;
- запрещать переносить имена ссылок и правила одного источника на другой (ссылка
  Bybit не подходит инструментам MOEX и наоборот, роль индекса/эталона у источников
  разная);
- обязывать называть пользователю источник, период расчёта и предупреждения из
  результата анализа и брать числа из результата, а не пересчитывать их
  самостоятельно.

Если у источника нет инструментов анализа среди предоставленных, абзац цепочки
анализа для НЕГО не добавляется; если ни у одного из доступных источников нет
инструментов анализа, сообщение не содержит ни даты, ни абзацев цепочки анализа и
совпадает с сообщением без анализа. Сообщение NOT SHALL отменять или ослаблять
обязательные предупреждения основного системного промпта, и это ограничение SHALL
по-прежнему быть прямо проговорено в самом сообщении; инварианты пользователя
сохраняют приоритет.

#### Scenario: Сообщение называет доступные источники

- **WHEN** собирается контекст основного ответа и доступны оба источника
- **THEN** сообщение называет и Московскую биржу, и Bybit, их назначение и то, что
  имена инструментов несут признак источника

#### Scenario: Доступен только один источник

- **WHEN** доступен только Bybit (MOEX не настроен или недоступен)
- **THEN** сообщение называет только Bybit и не упоминает MOEX

#### Scenario: Абзац анализа на каждый источник свой

- **WHEN** оба источника опубликовали инструменты анализа
- **THEN** сообщение содержит два отдельных абзаца с правилами цепочки анализа,
  каждый со своими именами инструментов и ссылок

#### Scenario: Сообщение содержит текущую дату

- **WHEN** собирается контекст основного ответа, слой включён и хотя бы для одного
  источника предоставлены инструменты анализа
- **THEN** сообщение о работе с инструментами содержит сегодняшнюю дату по Москве

#### Scenario: Интервал выбирается по границам периода

- **WHEN** собирается абзац MOEX
- **THEN** оно предписывает использовать `month` для периодов, совпадающих с
  границами месяцев, даже если разбивка по месяцам не запрошена
- **AND** оно не предписывает недельный интервал как обычный выбор для сравнений

#### Scenario: Правило начала и конца периода

- **WHEN** собирается абзац MOEX
- **THEN** оно предписывает брать для месячных свечей `date_from` с первого числа и
  `date_till` с последнего дня месяца

#### Scenario: Умолчания при неуточнённом названии

- **WHEN** собирается абзац MOEX
- **THEN** оно предписывает выбирать обыкновенные акции и ценовой индекс Московской
  биржи и называть выбранные тикеры

#### Scenario: Разделены два вида сравнения

- **WHEN** собирается абзац MOEX
- **THEN** оно указывает, что сравнение с индексом делает один инструмент, а
  сравнение двух бумаг — другой

#### Scenario: Старый сервер без инструментов анализа

- **WHEN** источник опубликовал только поиск, цену и историю, без инструментов
  анализа
- **THEN** абзац цепочки анализа для этого источника не добавляется, а остальная
  часть сообщения о нём совпадает с прежней (до появления инструментов анализа)

#### Scenario: Правила Bybit не путают источники

- **WHEN** собирается абзац Bybit
- **THEN** он предписывает использовать инструменты и ссылки именно Bybit и не
  описывает правила MOEX (индекс IMOEX, обыкновенные акции и т.п.)

#### Scenario: Ни у одного источника нет инструментов анализа

- **WHEN** ни MOEX, ни Bybit не опубликовали инструментов анализа
- **THEN** сообщение не содержит ни даты, ни абзацев цепочки анализа и совпадает с
  сообщением без анализа

#### Scenario: Ограничение на предупреждения сохраняется

- **WHEN** собирается сообщение слоя с правилами анализа
- **THEN** оно по-прежнему прямо говорит, что не отменяет и не ослабляет обязательные
  предупреждения основного системного промпта

### Requirement: Недоступный сервер не блокирует ответ

Если сервер какого-либо НАСТРОЕННОГО и включённого источника не удалось запустить или
он не ответил за отведённое конфигурацией время (в том числе из-за отсутствия
каталога или программы запуска), система SHALL ответить на вопрос без инструментов
ЭТОГО источника и SHALL показать пользователю предупреждение, называющее
недоступный источник — при этом инструменты ДРУГОГО, доступного источника SHALL
остаться предоставленными модели. Только если НИ ОДИН настроенный и включённый
источник не доступен, система отвечает на вопрос вовсе без инструментов.

Система SHALL добавить в контекст основного ответа правило не называть текущие цены
и котировки НЕДОСТУПНОГО источника по памяти как актуальные факты и говорить, что
получить их сейчас не удалось; это правило SHALL относиться только к недоступному
источнику и NOT SHALL распространяться на источник, который доступен. Сбой источника
NOT SHALL приводить к падению бота, потере вопроса или остановке обработки других
сообщений.

Система SHALL останавливать зависший процесс сервера недоступного источника по
истечении времени ожидания; это не влияет на процесс другого источника.

#### Scenario: Программа запуска недоступна

- **WHEN** на хосте бота нет программы, необходимой для запуска сервера источника, а
  слой инструментов включён и каталог этого источника задан
- **THEN** пользователь получает ответ без данных этого источника и предупреждение о
  его недоступности, а модель не называет его текущие цены как факт

#### Scenario: Один источник недоступен, другой доступен

- **WHEN** Bybit не запустился (например, нет каталога), а MOEX доступен, и
  пользователь спрашивает и про акцию, и про криптовалюту
- **THEN** модель отвечает по акции с помощью инструментов MOEX, а по криптовалюте —
  с предупреждением, что данные Bybit недоступны, не называя цену по памяти

#### Scenario: Все настроенные источники недоступны

- **WHEN** оба настроенных источника не удалось запустить
- **THEN** пользователь получает ответ без каких-либо инструментов и предупреждение о
  недоступности данных биржи

#### Scenario: Сервер не отвечает вовремя

- **WHEN** запуск или рукопожатие сервера источника не завершились за отведённое
  время
- **THEN** процесс этого источника останавливается, вопрос получает ответ без его
  инструментов (но с инструментами другого источника, если он доступен) и
  предупреждение

#### Scenario: Сбой не переживает вопрос

- **WHEN** один вопрос завершился недоступностью источника, а этот источник затем
  снова доступен
- **THEN** следующий вопрос снова запускает его и использует его инструменты

### Requirement: Слой инструментов включается и выключается пользователем

Система SHALL предоставлять слой инструментов как ещё один слой контекста
smart-агента наравне с остальными, переключаемый ОДНОЙ командой управления слоями
(`/smart_agent_toggle tools`), общей для ВСЕХ настроенных источников рыночных данных —
отдельного переключателя на каждый источник система NOT SHALL предоставлять. По
умолчанию слой SHALL быть включён. Выключение слоя NOT SHALL удалять чьи-либо данные;
пока слой выключен, система NOT SHALL запускать процесс ни одного источника,
предоставлять модели их инструменты или добавлять в контекст сообщение о работе с
инструментами.

Если при выключенном слое хотя бы один источник рыночных данных настроен оператором,
система SHALL добавлять в контекст основного ответа короткое сообщение о том, что
данные бирж выключены пользователем, называющее настроенные источники: актуальных
цен и истории у модели нет ни по одному из них, цены и котировки из прежних ответов
диалога NOT SHALL выдаваться за текущие и им NOT SHALL приписываться время котировки,
а на вопрос, требующий текущих данных любого из настроенных источников, модель SHALL
сказать, что данные выключены, и что их можно включить командой управления слоями.
Это сообщение, как и остальные сообщения слоя, NOT SHALL отменять или ослаблять
обязательные предупреждения основного системного промпта, и это ограничение SHALL
быть прямо проговорено в самом сообщении. Пользователю в чат при этом ничего
дополнительно не выводится: о выключении слоя его уже уведомила команда управления
слоями. Если ни один источник не настроен, сообщение NOT SHALL добавляться —
поведение чата не отличается от прежнего.

Настройка слоя SHALL действовать на весь чат и сохраняться между перезапусками бота,
как настройки остальных слоёв, и SHALL охватывать источники, добавленные позже
(включение Bybit оператором не требует отдельного включения слоя пользователем, если
слой уже был включён). Сохранённые состояния, созданные до появления этого слоя,
SHALL читаться как «слой включён». Очистка памяти (`/smart_agent_reset`) NOT SHALL
менять настройку слоя.

#### Scenario: Слой включён по умолчанию

- **WHEN** чат впервые обращается к smart-агенту, а хотя бы один источник настроен
- **THEN** агент использует инструменты доступных источников без дополнительных
  действий пользователя

#### Scenario: Пользователь выключает слой

- **WHEN** пользователь выключает слой командой управления слоями и задаёт вопрос о
  цене
- **THEN** ни один процесс источника не запускается, агент отвечает без инструментов,
  а команда показа состояния сообщает, что слой выключен

#### Scenario: Выключение слоя действует на все источники сразу

- **WHEN** настроены и MOEX, и Bybit, а пользователь выключает слой `tools`
- **THEN** ни MOEX, ни Bybit не предоставляют инструментов, и отдельного
  переключателя на каждый источник не требуется

#### Scenario: Цена из прежнего ответа при выключенном слое

- **WHEN** хотя бы один источник рыночных данных настроен, в диалоге уже есть ответ с
  ценой, полученной от инструмента, пользователь выключил слой и снова спрашивает
  цену той же бумаги или пары
- **THEN** в контекст ответа добавлено сообщение о том, что данные бирж выключены, и
  модель не выдаёт прежнюю цену за текущую, не приписывает ей время котировки и
  сообщает, что данные выключены

#### Scenario: Слой выключен, сервер не настроен

- **WHEN** ни один источник не настроен, слой выключен и пользователь задаёт вопрос
  smart-агенту
- **THEN** в контекст не добавляется ни сообщение о работе с инструментами, ни
  сообщение о выключенных данных, и ответ строится как раньше

#### Scenario: Пользователь включает слой обратно

- **WHEN** пользователь снова включает слой
- **THEN** следующий вопрос снова использует инструменты доступных источников

#### Scenario: Старое сохранённое состояние

- **WHEN** у чата есть файл памяти, созданный до появления слоя инструментов
- **THEN** слой считается включённым, а остальные сохранённые настройки слоёв не
  меняются

### Requirement: Вызовы инструментов видны пользователю

Система SHALL сообщать в чате, какие инструменты (с именем, несущим признак
источника) были вызваны при ответе на вопрос и с какими аргументами, отдельно от
самого ответа и в той же служебной строке, что и прочая служебная информация об
ответе. Число обращений к модели за один вопрос SHALL быть отражено в статистике
токенов вопроса, а токены всех обращений SHALL учитываться в ней, независимо от
того, к скольким источникам обращался вопрос. Команда показа состояния smart-агента
SHALL показывать статус КАЖДОГО настроенного источника рыночных данных ОТДЕЛЬНО
(включён, выключен, недоступен, не настроен) и вызовы последнего вопроса.

#### Scenario: Вызовы показаны

- **WHEN** ответ построен с использованием инструментов
- **THEN** после ответа пользователь видит, какие инструменты (с признаком источника
  в имени) вызывались и с какими аргументами

#### Scenario: Статус слоя в показе состояния

- **WHEN** пользователь запрашивает показ состояния smart-агента, а настроены оба
  источника
- **THEN** в нём указан статус MOEX и статус Bybit отдельными строками, и вызовы
  последнего вопроса, если они были

### Requirement: Границы данных и хранения

Серверу каждого источника рыночных данных SHALL передаваться только аргументы
вызовов, сформированные моделью (например, тикер или символ, поисковый запрос,
даты), и, в параметрах инструментов анализа, результаты истории цен, которые сам
СЕРВЕР ЭТОГО ЖЕ источника выдал на прежние вызовы того же вопроса и которые система
подставила вместо ссылки модели. Система NOT SHALL передавать серверу историю
диалога, память агента, профиль, инварианты или иные пользовательские данные.
Аргументы и результаты одного источника NOT SHALL передаваться серверу другого
источника ни в каком виде — источники изолированы друг от друга так же, как от
истории диалога и памяти агента. Промежуточные сообщения цикла вызовов и результаты
инструментов, включая запомненные для ссылок, NOT SHALL сохраняться на диск: в
краткосрочную память SHALL записываться только итоговая пара «вопрос — ответ». Ответ
модели при этом сохраняется как обычно и может содержать данные, полученные от
любого из источников.

Доступ к инструментам SHALL действовать только для основного ответа smart-агента.
Служебные вызовы модели (ведение рабочей задачи, определение старта задачи, проверка
инвариантов), а также остальные режимы бота — обычный поток вопросов, `/agent`,
`/agent_compare` и исследовательские режимы — NOT SHALL получать инструменты ни
одного источника. Доступ NOT SHALL зависеть от флага исследовательских команд. Это
ограничение относится к доступу модели: команды опроса цен (возможность
`price-watch`, доступная только для MOEX) и их фоновая выдача сводок вызывают сервер
сами, без участия какой-либо модели, и не расширяют набор инструментов, доступный
модели.

#### Scenario: История не уходит серверу

- **WHEN** пользователь задаёт вопрос в чате с непустой историей и памятью
- **THEN** серверам источников уходят только аргументы вызовов, сформированные
  моделью, и собственные результаты каждого сервера, подставленные по ссылке, без
  истории, памяти, профиля и инвариантов

#### Scenario: Подставленные данные — только результаты сервера

- **WHEN** модель вызывает инструмент анализа источника со ссылкой на результат
  истории этого же источника
- **THEN** серверу этого источника уходит ровно тот результат, который он выдал на
  вызов истории в этом вопросе, и никаких данных, изменённых или сформированных
  моделью

#### Scenario: Источники не обмениваются данными между собой

- **WHEN** модель вызывает инструменты и MOEX, и Bybit в рамках одного вопроса
- **THEN** серверу каждого источника уходят только аргументы, сформированные моделью
  для этого вызова, и собственные результаты этого же источника по ссылке — без
  данных другого источника

#### Scenario: Промежуточные сообщения не сохраняются

- **WHEN** ответ построен за несколько шагов вызова инструментов, в том числе разных
  источников
- **THEN** в краткосрочную память записывается ровно одна пара — вопрос и итоговый
  ответ, без сообщений вызовов, результатов и запомненных для ссылок данных

#### Scenario: Служебные вызовы без инструментов

- **WHEN** после ответа выполняется служебный вызов модели, ведущий рабочую задачу
- **THEN** этот вызов выполняется без инструментов какого-либо источника

#### Scenario: Другие режимы без инструментов

- **WHEN** пользователь работает с `/agent`, `/agent_compare` или обычным потоком
  вопросов
- **THEN** инструменты рыночных данных ни одного источника этим режимам не
  предоставляются

#### Scenario: Флаг исследовательских команд

- **WHEN** оператор выключил флаг технических/исследовательских команд
- **THEN** доступ smart-агента к инструментам рыночных данных остаётся включённым для
  всех настроенных источников

#### Scenario: Команды опроса цен не расширяют доступ модели

- **WHEN** пользователь задаёт опрос командой `/watch` (только для MOEX) и затем
