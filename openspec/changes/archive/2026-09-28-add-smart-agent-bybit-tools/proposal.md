# Proposal

## Why

Слой `tools` `/smart_agent` сейчас даёт основному ответу данные только Московской
биржи (`mcp-moex`) — акции, облигации, индексы. Пользователи всё чаще спрашивают про
криптовалюту, и локально уже готов независимый MCP-сервер `mcp-bybit`
(`/media/alexey/DATA/Projects/Python/mcp-bybit/`), устроенный по тому же принципу:
публичный read-only доступ к спотовому рынку Bybit (поиск пары, текущая цена, история
цен, три инструмента анализа истории — метрики, сравнение с индексом, сравнение двух
бумаг), без ключей и без записи. Подключить его тем же способом, каким уже подключён
`mcp-moex`, закрывает этот пробел без новых доменных рисков: доступ остаётся
read-only, деньги и позиции пользователя не собираются, торговых/приватных эндпоинтов
сервер не поддерживает.

## What Changes

- В слой `tools` `/smart_agent` добавляется ВТОРОЙ источник рыночных данных —
  `mcp-bybit` — независимо конфигурируемый оператором через новую переменную
  окружения `MCP_BYBIT_DIR` (по аналогии с `MCP_MOEX_DIR`), по умолчанию не заданную
  (возможность неактивна и молчит, как и MOEX).
- Слой перестаёт предполагать РОВНО ОДИН сервер: за один вопрос он открывает сессию с
  каждым НАСТРОЕННЫМ и включённым источником (MOEX, Bybit — оба, один или ни одного),
  и модель получает объединённый набор инструментов сразу от всех доступных
  источников.
- Имена инструментов, отдаваемые модели, получают префикс источника (`moex__...`,
  `bybit__...`) — у пяти из шести инструментов Bybit имена совпадают с именами MOEX
  (`get_current_price`, `get_price_history`, `compute_price_metrics`,
  `compare_with_benchmark`, `compare_securities`), поэтому без префикса модель не
  могла бы различить, к какой бирже относится вызов.
- Реестр ссылок на результаты истории (`r1`, `r2`, …) становится независимым для
  каждого источника: ссылка, выданная в ответ на `moex__get_price_history`, годится
  только для `moex__...`-инструментов анализа, и наоборот для Bybit — источники не
  путают друг друга данными.
- Доступность источников становится частичной, а не общей на весь слой: если один
  сервер не запустился, а другой доступен, модель всё равно получает инструменты
  доступного источника; предупреждение пользователю и правило «не выдавай цены по
  памяти» называют конкретный недоступный источник, а не оба сразу.
- Сообщение слоя о работе с инструментами и правила цепочки анализа истории
  формулируются раздельно по источнику (какие тикеры для чего, какой инструмент к
  какой бирже относится); абзац с датой и правилами анализа добавляется для каждого
  источника, который опубликовал свои инструменты анализа.
- `/smart_agent_show` показывает статус каждого настроенного источника отдельно, а не
  один статус слоя в целом.
- **Не меняется и явно не предлагается**: команды опроса цен (`/watch*`,
  `price-watch`) остаются только для MOEX — у `mcp-bybit` нет режима расписания;
  диагностический режим `/mcp_tools` не привязан ни к одному из этих серверов и не
  затрагивается; инструменты записи/торговли и сбор сумм/позиций пользователя не
  добавляются ни для одного источника.

## Capabilities

### New Capabilities

(нет — возможность расширяет существующий слой `tools`, а не вводит новый)

### Modified Capabilities

- `smart-agent-market-tools`: капабилити обобщается с «один сервер MOEX» на «один или
  несколько независимо настраиваемых read-only источников рыночных данных»: конфигурация
  и запуск источника, выбор инструментов, ссылки на историю, сообщение слоя и правила
  цепочки анализа, обработка недоступности, видимость статуса — везде, где текущая
  формулировка требований предполагает единственный сервер, требование меняется, чтобы
  описывать множество источников и добавление Bybit как второго из них.

## Impact

- `src/config.py` — новая переменная `MCP_BYBIT_DIR` (и её мягкая валидация по образцу
  `MCP_MOEX_DIR`/`_warn_if_moex_dir_invalid`); общие `MCP_TIMEOUT_SECONDS`/
  `MCP_MAX_TOOL_STEPS`/`MCP_TOOL_RESULT_MAX_CHARS` остаются едиными на оба источника.
- `src/mcp_integration/market_session.py` — механика подключения обобщается на
  несколько источников (по одному процессу на источник на вопрос), префиксация имён
  инструментов, диспетчеризация вызова по префиксу, независимые реестры ссылок на
  источник.
- `src/agents/market_tools.py` — тексты и правила слоя (сообщение о работе с
  инструментами, абзацы цепочки анализа, статусы, предупреждения) переписываются для
  произвольного набора источников вместо одного MOEX.
- `src/agents/smart_agent.py` — сборка контекста и цикла инструментов работает с
  набором источников вместо одного; `/smart_agent_show` (через
  `agents/smart_agent_command.py`) показывает статус каждого источника.
- `tests/test_market_tools.py` — новые тесты на префиксацию, диспетчеризацию,
  изоляцию ссылок между источниками, частичную доступность.
- `.env.example`, `README.md`, `CLAUDE.md` — документация новой переменной и
  обновлённого механизма слоя.
- Не затрагивается: `src/price_watch/`, `src/mcp_integration/watch_session.py`,
  `src/mcp_integration/tools_command.py`/`client.py` (`/mcp_tools`), `MAIN_CLIENT`/
  `MAIN_MODEL`/`SYSTEM_PROMPT`.
