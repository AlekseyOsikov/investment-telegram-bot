# Proposal

## Why

У бота сейчас есть ровно один способ получить что-либо извне — вызов LLM-провайдера
через SDK `openai` (`providers/main_client.py`). Ни агенты (`/agent`, `/smart_agent`),
ни research-режимы не умеют обращаться к внешним инструментам: рабочая задача
`/smart_agent` строит портфель исключительно из того, что модель знает сама.
Первый шаг к устранению этого ограничения — освоить протокол MCP (Model Context
Protocol): научиться устанавливать соединение с MCP-сервером и получать от него
список доступных инструментов. Это самостоятельная, проверяемая веха: пока бот не
умеет хотя бы подключиться и перечислить инструменты, обсуждать их вызов из агентов
преждевременно.

## What Changes

- Новый пакет `src/mcp_integration/` — подключение к MCP-серверу по транспорту stdio
  через официальный Python MCP SDK (пакет `mcp`) и получение списка инструментов
  (`session.list_tools()`). Слой не знает ни про Telegram, ни про LLM — по тому же
  принципу, что `providers/` и `agents/agent.py` отделены от своих команд.
- Новая команда бота `/mcp_tools` — подключается к настроенному MCP-серверу и
  присылает в чат список его инструментов (имя, описание, обязательные параметры из
  `inputSchema`) плюс строку с именем/версией сервера. Регистрируется в `main.py`
  под флагом `RESEARCH_ENABLED` наравне с `/research_*`: это техническая
  диагностика, а не часть инвестиционного сценария.
- Новые переменные окружения в `config.py` и `.env.example`: команда запуска
  MCP-сервера и её аргументы (по умолчанию — `npx -y
  @modelcontextprotocol/server-everything`) плюс тайм-аут подключения. Значение
  задаёт ОПЕРАТОР бота через `.env`; пользователь чата выбрать сервер не может — то
  же ограничение, что и на `MAIN_CLIENT`/`MAIN_MODEL` (см. «Ограничения
  безопасности» в CLAUDE.md).
- Новая зависимость в `requirements.txt`: `mcp` (официальный Python SDK). Появляется
  внешнее требование к окружению — Node.js с `npx` на хосте бота (уже нужен для
  OpenSpec CLI, но теперь становится требованием рантайма, а не только процесса
  разработки).
- Обновление `/help`, `README.md` и CLAUDE.md под новую команду, новый пакет и новые
  переменные окружения.

Не входит в объём (явные не-цели, чтобы не расползлось):

- **Вызов** инструментов MCP (`call_tool`) — только перечисление.
- Подключение MCP к `/agent`/`/smart_agent` и к рабочей задаче: инструменты не
  попадают ни в контекст LLM, ни в конечный автомат.
- Транспорты, кроме stdio (HTTP/SSE), и подключение нескольких серверов сразу.
- Ресурсы и промпты MCP (`list_resources`/`list_prompts`) — только инструменты.

## Capabilities

### New Capabilities

- `mcp-integration`: подключение бота к MCP-серверу по stdio и получение от него

  обработку ошибок подключения и показ результата пользователю в Telegram.

## Impact

Код:
- `src/mcp_integration/__init__.py`, `src/mcp_integration/client.py` (соединение и
  `list_tools`), `src/mcp_integration/tools_command.py` (команда `/mcp_tools`) — новые.
- `src/config.py` — новые переменные окружения MCP.
- `src/main.py` — регистрация обработчика под `RESEARCH_ENABLED` и строка в `/help`.

Зависимости и окружение:
- `requirements.txt` — добавляется `mcp`.
- Хост бота: Node.js + `npx` (иначе `/mcp_tools` отвечает понятной ошибкой, а
  остальной бот продолжает работать как раньше).
- Каждый вызов `/mcp_tools` порождает дочерний процесс `npx` и завершает его после
  ответа — новый для проекта класс сбоев (процесс не стартовал, завис, недоступна
  сеть npm), который обрабатывается отдельно от ошибок OpenAI SDK.

Доменные ограничения:
- В MCP-сервер не отправляются ни текст пользователя, ни история диалога — команда
  выполняет только рукопожатие и `list_tools`. Ничего на диск не сохраняется, памяти
  у команды нет.
