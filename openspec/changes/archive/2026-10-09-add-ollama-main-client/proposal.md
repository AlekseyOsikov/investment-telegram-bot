# Proposal

## Why

Основной поток бота и всё, что использует `main_client`/`MAIN_MODEL` (`/agent`, `/smart_agent`,
research-режимы без собственного выбора модели), работает только через облачных провайдеров
(DeepSeek, Kimi): текст вопроса, память агента и результаты инструментов покидают машину
оператора, а работа зависит от платного API. Оператору нужна возможность запускать бота целиком
на локальной модели через уже используемый в проекте Ollama — для приватности, офлайн-работы и
экспериментов без расходов на токены.

## What Changes

- `MAIN_CLIENT` принимает третье значение `ollama`; клиент — существующий `ollama_client`
  (`providers/ollama_client.py`, адрес из `OLLAMA_BASE_URL`), `main_client` указывает на него.
- `MAIN_MODEL` при `MAIN_CLIENT=ollama` обязателен и задаётся явно (осмысленного значения по
  умолчанию нет — набор локальных моделей зависит от оператора); пустое значение — ошибка
  конфигурации при запуске.
- Ключ API для `ollama` не нужен: проверки обязательности `DEEPSEEK_API_KEY`/`KIMI_API_KEY` не
  срабатывают, отсутствие обоих ключей не мешает запуску (остаётся лишь предупреждение про
  `/research_models`).
- `MAIN_CLIENT_LABEL` = «Ollama»; тексты ошибок основного потока называют Ollama, а для
  недоступного сервера подсказывают проверить, что Ollama запущен и модель загружена
  (вместо подсказки про API-ключ).
- Провайдер-специфичные параметры вызовов (`extra_body={"thinking": ...}` и т. п.) не
  отправляются в Ollama; возможности, зависящие от модели (tool calling для слоя `tools`,
  `response_format=json_object` для автоматической памяти), деградируют по существующим
  правилам обработки сбоев, а не роняют бот.
- Смена провайдера по-прежнему только через `.env` и перезапуск; команд для рантайм-смены нет.
- Обновляются `.env.example`, `CLAUDE.md`, `README.md`.

## Capabilities

### New Capabilities
- `main-llm-provider`: выбор оператором провайдера и модели основного потока
  (`MAIN_CLIENT` = `deepseek` | `kimi` | `ollama`, `MAIN_MODEL`), обязательность ключей и модели,
  подписи провайдера в сообщениях. Раньше требований к этому в `openspec/specs/` не было —
  спека фиксирует действующее поведение для `deepseek`/`kimi` и добавляет `ollama`.

### Modified Capabilities

(нет — существующие требования других спек не меняются; `rag-query-rewrite` и эмбеддинги
независимы от `MAIN_CLIENT`)

## Impact

- Код: `src/config.py` (допустимые значения, дефолт модели, `MAIN_CLIENT_LABEL`,
  `MAIN_API_KEY_ENV_VAR`, `_validate_config`), `src/providers/main_client.py`,
  `src/providers/deepseek_client.py`/`kimi_client.py` (условия «обязательный ключ» — без
  изменений логики, но проверить сообщения), `src/main.py`/`src/research/_shared.py` (тексты
  ошибок для Ollama), места с провайдер-специфичными параметрами вызовов.
- Конфигурация: `.env.example` (`MAIN_CLIENT=ollama`, `MAIN_MODEL`, общий `OLLAMA_BASE_URL`).
- Документация: `CLAUDE.md`, `README.md`.
- Приватность: при `ollama` и локальном `OLLAMA_BASE_URL` данные основного потока не покидают
  машину; при удалённом `OLLAMA_BASE_URL` — уходят на этот сервер (решение оператора, как с
  `EMBEDDINGS_BASE_URL`). `OLLAMA_BASE_URL` теперь общий для основного потока и переписывания.
- Новых зависимостей, команд и пользовательских настроек нет; доменные правила (дисклеймер,
  `SYSTEM_PROMPT`) не затрагиваются.
