# Design

## Context

Судья цитат (`rag_compare.judge_citations`, промпт — `config.RAG_COMPARE_CITATION_JUDGE_SYSTEM_PROMPT`,
вход собирает `rag_compare_eval.build_citation_judge_user_content`) вызывается в
`_answer_and_judge` ПОСЛЕ `run_mode`, то есть вне `SmartAgent`. К этому моменту у него есть
`ModeResult.citations` — словари `{quote, title, chunk_index, chunk_id}`, а текстов фрагментов нет:
`VerifiedCitation` хранит `quote` и `RagSource` (без текста), а `SmartAgentAnswer` не отдаёт чанки.
Мотивация — см. proposal.md («Why»): судья видит отрывки, ответ опирается на фрагмент целиком.

## Goals / Non-Goals

**Goals:**
- Судья оценивает опору ответа на полный текст фрагментов, из которых взяты проверенные цитаты.
- Тексты фрагментов не попадают в отчёт на диск и в рантайм основного ответа.
- Вердикты разных версий оценки не смешиваются при чтении отчётов.

**Non-Goals:**
- Подавать судье ВСЕ поданные модели фрагменты (оценивается опора на то, что модель указала цитатой;
  ответ по неуказанным фрагментам — отдельный вопрос).
- Менять рантайм `/smart_agent`, проверку цитат по подстроке, пороги и отбор.
- Менять набор вердиктов и формат сводки.

## Decisions

### 1. Текст фрагмента едет в `VerifiedCitation`

`VerifiedCitation` получает необязательное поле `fragment: str = ""`; `build_citation_result()`
заполняет его текстом `chunks[n-1].text`. `SmartAgentAnswer.citations` и так живёт только в памяти
результата `ask()`, а `short_term` пишется без цитат и текстов, поэтому правило «тексты чанков не
сохраняются» не нарушается (проверка — тест на память и `rag_compare` не пишет поле в отчёт, см. п.2).
Альтернативы: отдавать из `SmartAgent` список поданных чанков (шире, чем нужно судье, и тянет в
результат ответа лишнее); искать текст по `chunk_id` в индексе при вызове судьи (лишнее обращение к
диску и индексу и зависимость от того, что индекс не пересобран между ответом и оценкой).

### 2. Перенос к судье через временное поле `ModeResult.fragments`, вне `to_dict()`

`run_mode` собирает `fragments` — тексты фрагментов проверенных цитат без повторов (ключ — `chunk_id`,
а при пустом — пара «заголовок, номер»), в порядке первого упоминания. Поле объявлено в `ModeResult`,
но `to_dict()` его убирает, а `from_dict()` не читает: отчёт на диск и из диска идёт без текстов.
Судья принимает `fragments` аргументом. Альтернатива — хранить тексты в отчёте для
воспроизводимости оценки: отвергнута (корпус не должен жить в отчётах и расходиться по файлам;
прежний принцип: в отчёте только цитаты и вердикт).

### 3. Вход судьи и промпт

`build_citation_judge_user_content(question, answer, quotes, fragments)`: вопрос, пронумерованные
фрагменты (источник истины), пронумерованные цитаты (указатели), ответ. Каждый фрагмент усекается
до `CITATION_JUDGE_FRAGMENT_MAX_CHARS` (константа в `rag_compare_eval.py`, порядка 3000 символов) с
пометкой «усечён», чтобы вход не раздувался: размер чанка зависит от стратегии. Указания на режим
по-прежнему нет. Промпт обновляется так: опора оценивается по ФРАГМЕНТАМ, а не по цитатам;
утверждение, присутствующее в тексте фрагмента, считается подтверждённым, даже если не входит в
цитату; оговорки общего характера утверждениями не считаются (как раньше); собственные знания судьи
не используются. Набор вердиктов (`supported/partial/unsupported`) и формат JSON не меняются, поэтому
`parse_citation_judge_response` остаётся прежним.

### 4. Версия оценки в отчёте

В `settings` отчёта (`_settings()`) добавляется ключ `citation_judge: "fragments"`; в старых отчётах
его нет (они читаются как оценка по одним отрывкам). `format_summary()` показывает в строке блока
цитат, по чему оценивалась опора: «по тексту фрагментов» либо — для старого отчёта — «по цитатам
(прежняя версия оценки)». Чтение старых отчётов не ломается.

### 5. Какие фрагменты передаются

Только фрагменты с проверенными цитатами (решение пользователя). Следствие: если ответ использует
факты из поданного, но не процитированного фрагмента, судья пометит их как утверждения без опоры.
Это сознательно: вердикт отвечает на вопрос «подтверждается ли ответ тем, на что модель указала».
Если это окажется слишком строгим, расширение до всех поданных фрагментов — отдельное изменение.

## Risks / Trade-offs

- [Судья всё равно строг к деталям из неуказанных фрагментов] → задокументировано в п.5; по
  результатам прогона решить, расширять ли вход.
- [Больше токенов у судьи (до трёх фрагментов)] → усечение фрагментов; число вызовов не растёт.
- [Старые и новые вердикты несопоставимы] → пометка версии в отчёте и в сводке.
- [Судья по-прежнему тот же LLM, что и отвечал, и может быть снисходителен к собственным
  формулировкам] → известное ограничение метода (как и в судье фактов); ручная выборочная сверка
  утверждений «без опоры» с текстом фрагментов на 2–3 вопросах после прогона.
- [Тексты корпуса уходят провайдеру основной модели] → не новый получатель: те же фрагменты уже
  отправлялись ему как материалы основного ответа.

## Migration Plan

Миграция данных не нужна: старые отчёты читаются как есть (без `citation_judge`). Откат —
возврат коммита. После внедрения оператор повторно запускает `/research_rag_compare` на том же
наборе, сравнивает распределение вердиктов с первым прогоном (подтверждается — 0, частично — 7,
не подтверждается — 0) и записывает результат в раздел «Результаты проверки» этого файла.

## Результаты проверки

Повторный прогон `/research_rag_compare` (`RAG_COMPARE_LEVEL=answers`, 3 октября 2026, те же 10
вопросов: 8 по корпусу и 2 вне корпуса; отчёт помечен `citation_judge = fragments`). Один прогон
недетерминирован, числа — ориентир.

| Показатель | До (по цитатам) | После (по тексту фрагментов) |
|---|---|---|
| Опора ответа на материалы: подтверждается / частично / не подтверждается | 0 / 7 / 0 | 3 / 4 / 0 |
| С источниками | 8 из 8 | 8 из 8 |
| С проверенными цитатами | 7 из 8 | 7 из 8 |
| Доля проверенных цитат среди написанных | 60% | 58% |
| Верные отказы «не знаю» | 2 из 2 | 2 из 2 |

Выборочная сверка утверждений «без опоры» с текстом фрагментов из индекса (грубая лексическая
проверка по словам и числам, не строгая): у вопросов с вердиктом «частично» большая часть слов
утверждений отсутствует и в цитированных, и во всех поданных фрагментах, то есть это в основном
знания модели вне материалов, а не придирка судьи. Исключения: на двух вопросах часть слов
утверждений есть во фрагментах (вероятно, перефразирование — судья строг), а на одном числа из
утверждения нашлись только в поданных, но не процитированных фрагментах (следствие решения
передавать судье только цитированные фрагменты, п.5).

Выводы:
- Доработка сняла артефакт метода: «подтверждается» стало достижимо (3 из 7 оценённых), и остаток
  «частично» в основном отражает реальный выход ответа за пределы материалов.
- Доля проверенных цитат и вопрос 3 без проверенных цитат не изменились — это не связано с судьёй.
- Если нужно ещё точнее различать опору на поданное и на знания модели, следующий шаг — передавать
  судье все поданные фрагменты (отдельное изменение).
