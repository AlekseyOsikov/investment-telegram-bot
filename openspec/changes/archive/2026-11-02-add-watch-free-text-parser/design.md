# Design

## Context

Мотивация — в proposal.md. Ключевые ограничения, определяющие подход:

- Модель `qwen25-watch-v3` обучена и замерена в `finetuning/watch_parser/`; её качество
  (96.7% exact на holdout) получено на нативном эндпоинте Ollama `/api/chat` со строгими
  жадными параметрами и поверх ответа модели — детерминированным guard.
- Бот уже умеет работать с локальным Ollama: `OLLAMA_BASE_URL` (OpenAI-совместимый `/v1`),
  `providers/ollama_client.py`, паттерн вторичной модели по образцу `REWRITE_*`/`NEWS_*`.
- Задокументированная граница: `src/` не импортирует `finetuning/`.
- Доменное правило: модель не участвует в подготовке сводки; сервер расписания получает
  только тикеры и периоды, а не свободный текст.

## Goals / Non-Goals

**Goals:**

- Дать `/watch` принимать свободный русский текст, сохранив строгий синтаксис как первый
  (быстрый) путь и прежнее поведение, когда функция не настроена.
- Воспроизвести качество, замеренное в `finetuning/` (те же параметры генерации, тот же guard).
- Оставить функцию полностью настройкой оператора, без участия пользователя чата.

**Non-Goals:**

- Не менять подготовку сводки (она остаётся на сервере) и не передавать модели историю/память.
- Не добавлять выбор облачного провайдера для парсера — модель существует только локально.
- Не строить рантайм-переключение модели пользователем: переключение тюненая/база — операция
  оператора в Ollama (стабильный алиас), вне кода бота.

## Decisions

### 1. Парсер — только локальный Ollama, настройка оператора
Новые переменные окружения `WATCH_PARSER_MODEL` (пусто = функция выключена) и
`WATCH_PARSER_TIMEOUT_SECONDS`; адрес берётся из `OLLAMA_BASE_URL`. Провайдер не выбирается
(в отличие от `REWRITE_PROVIDER`/`NEWS_PROVIDER`): модель обучена и выкатывается только в
Ollama, а локальность оставляет свободный текст команды на машине оператора.

*Альтернатива*: провайдерный шаблон `ollama|deepseek|kimi`. Отклонено — на облачных
провайдерах модели нет, а передача свободного текста наружу противоречит духу границ данных.

### 2. Промпт и guard копируются в `src/price_watch/`, не импортируются из finetuning
Новый самодостаточный модуль `src/price_watch/nl_parse.py` содержит SYSTEM_PROMPT, FEWSHOT,
словарь тикеров, коды ошибок, `validate_output` и guard — это перенос из
`finetuning/watch_parser/scripts/{spec,guard}.py`. Так сохраняется граница «`src/` не зависит
от `finetuning/`». Чистые функции покрываются тестами в `tests/`.

*Альтернатива*: импорт `finetuning/` из `src/` — нарушает задокументированную границу и тянет
в бот учебный подпроект с отдельным `.venv`.

### 3. Вызов — нативный `/api/chat` с жадными параметрами eval
Замер качества в `finetuning/` получен на нативном `/api/chat` с `options`: `temperature=0`,
`num_predict=128`, `num_ctx=4096`, `repeat_penalty=1.0`, `top_k=1`, `top_p=1.0`, `seed=42`.
OpenAI-совместимый `/v1` не пробрасывает `repeat_penalty`/`top_k`/`num_ctx`, а Ollama по
умолчанию ставит `repeat_penalty=1.1`, из-за чего few-shot «ломается» (зафиксировано в
`finetuning/watch_parser/README.md`). Поэтому парсер обращается к нативному эндпоинту
(хост из `OLLAMA_BASE_URL` без `/v1`) с теми же `options`, чтобы воспроизвести замеренное
качество. Тонкий синхронный вызов (httpx, `trust_env=False`, как в `ollama_client`) исполняется
из обработчика через `asyncio.to_thread`.

*Альтернатива*: переиспользовать OpenAI-совместимый `ollama_client`, «зашив» параметры в
Modelfile. Отклонено как основной путь — зависимость от неочевидного проброса параметров и
риск не воспроизвести качество; при этом Modelfile всё равно документируется в выкате.

### 4. Порядок разбора в `/watch`
`watch_command` сначала пробует строгий `parse_watch_args` (как сейчас). При `ParseError` и
заданном `WATCH_PARSER_MODEL` — разбор свободного текста моделью с guard; результат
конвертируется в `WatchRequest` и выполняется как обычно, либо (ошибка разбора) показывается
понятное сообщение. Пустая команда и недоступность модели дают прежнюю `USAGE_TEXT` без
обращения к серверу расписания.

### 5. Сообщения об ошибках разбора
Коды ошибок модели (`empty`, `not_watch`, `missing_tickers`, `missing_intervals`,
`missing_poll_interval`, `missing_report_interval`, `bad_interval`, `bad_ticker`, `ambiguous`)
переводятся в короткие русские сообщения в `texts.py`; `not_watch` и неизвестный ответ — общий
текст «не похоже на опрос» + `USAGE_TEXT`.

## Risks / Trade-offs

- [Свободный текст добавляет задержку (модель ~1.3 с на F16, холодный старт дольше)] →
  модель вызывается только при неудачном строгом разборе; есть `WATCH_PARSER_TIMEOUT_SECONDS`;
  в выкате документируется `OLLAMA_KEEP_ALIVE=-1` для устранения холодного старта.
- [Модель узкая: 20 тикеров, синтетический корпус] → guard и валидация на сервере остаются
  последней инстанцией (неизвестный тикер отклоняет сервер); ограничение фиксируется в выкате.
- [Расхождение копии в `src/` с оригиналом в `finetuning/`] → тесты пиннеют SYSTEM_PROMPT, коды
  ошибок и поведение guard; в `finetuning/watch_parser/README.md` — пометка, что правки переносятся.
- [Качество зависит от `repeat_penalty=1.0`/`top_k=1`] → нативный `/api/chat` с фиксированными
  `options` + шаг проверки, сверяющий вывод бота с `ollama_ask.py` на контрольных фразах.

## Migration Plan

- Оператор квантует и загружает модель в Ollama (см. `finetuning/watch_parser/rollout.md`),
  задаёт `WATCH_PARSER_MODEL` и перезапускает бота; строгий синтаксис продолжает работать.
- Переключение тюненая/база — смена стабильного алиаса в Ollama без перезапуска бота.
- Откат функции — очистить `WATCH_PARSER_MODEL`; бот возвращается к строгому синтаксису и
  прежней подсказке.
