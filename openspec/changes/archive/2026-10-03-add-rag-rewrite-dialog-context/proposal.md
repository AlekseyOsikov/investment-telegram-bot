# Proposal

## Why

Переписывание вопроса в слое `rag` (изменение `add-rag-rerank-and-rewrite`) видит только последнюю
реплику, поэтому не восстанавливает смысл неполных вопросов-продолжений: после «Как выбирать
облигации?» вопрос «А акции?» уходит в поиск как есть, эмбеддинг этих двух слов не находит
ничего подходящего, и порог отсекает материалы. Измерения прошлого изменения этого не показали:
оба набора вопросов односложные и самодостаточные. В диалоге с `/smart_agent` такие продолжения
— обычное дело, а история диалога у агента уже есть (`short_term` активного профиля).

## What Changes

- Модель переписывания получает, кроме текущего вопроса, несколько ПРЕДЫДУЩИХ ВОПРОСОВ
  пользователя из `short_term` активного профиля — только тексты вопросов, без ответов модели,
  без памяти (`long_term`, рабочая задача), профиля (`meta`), инвариантов и найденных
  фрагментов. Число вопросов — настройка оператора `REWRITE_HISTORY_QUESTIONS` (0 — не
  передавать историю; по умолчанию значение выбирается по результатам измерений этого
  изменения, до них — 0).
- Промпт требует использовать историю ТОЛЬКО чтобы дополнить неполный вопрос (местоимение,
  «а …?», «и что там с…?»); самодостаточный вопрос переписывается без неё, смена темы не должна
  тянуть старый контекст.
- Если пользователь выключил слой `short_term` (`/smart_agent_toggle short`) или очистил его
  (`/smart_agent_reset`), история в переписывание не передаётся.
- Переписанный запрос по-прежнему идёт ТОЛЬКО в поиск; в ответ, память и строки источников — исходный
  вопрос. `/smart_agent_show` показывает, сколько прошлых вопросов использовано.
- **Меняется граница данных.** Прежнее требование «история диалога провайдеру переписывания не
  передаётся» заменяется точным: передаётся только текст последних N вопросов пользователя
  текущего профиля. Новый канал данных: при `ollama` — на сервер оператора (по умолчанию
  локальный), при `deepseek`/`kimi` — облачному провайдеру на шаг раньше основного ответа (основной
  провайдер историю и так получает, но провайдер переписывания может быть другим). Запись в
  `CLAUDE.md`, `README.md`, `.env.example`.
- **Измерения** в `/research_rag_compare`: у контрольного вопроса появляется необязательное поле
  `history` (прошлые вопросы диалога; файл набора по-прежнему в `data/`, не в репозитории);
  новые режимы поиска «с контекстом диалога» (переписывание с историей) и «склейка» (без LLM:
  эмбеддинг по прошлому вопросу, склеенному с текущим) сравниваются с режимами без истории на
  уровне `search`. На уровне `answers` вопросы с `history` пропускаются (ответы на них без
  настоящей предыстории были бы несравнимы).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `rag-query-rewrite`: границы данных (какие прошлые вопросы уходят провайдеру и когда не уходят),
  новое требование к истории диалога в переписывании и промпту, настройка оператора.
- `smart-agent-rag`: уточнение запрета на историю в поисковых запросах и границ данных слоя
  (серверу эмбеддингов по-прежнему только поисковый текст), показ числа использованных прошлых
  вопросов в состоянии.
- `rag-answer-comparison`: необязательное поле `history` в контрольном наборе и его проверка.
- `rag-retrieval-comparison`: режимы «с контекстом диалога» и «склейка», многоходовые вопросы,
  метрики по ним.

## Impact

- Код: `config.py` (`REWRITE_HISTORY_QUESTIONS`, проверка), `agents/rag_rewrite.py` (промпт и
  сборка сообщений с историей, нормализация без изменений), `agents/smart_agent.py` (выборка
  прошлых вопросов из `short_term`, передача в `_rewrite_query`, `search_materials` принимает
  историю явно для сравнения), `agents/rag_context.py` (`SearchInfo` — число вопросов истории),
  `/smart_agent_show`, `research/rag_compare_eval.py` (`Question.history`),
  `research/rag_modes_eval.py` и `research/rag_compare.py` (новые режимы, пропуск многоходовых
  вопросов на уровне `answers`), `scripts/rag_calibrate.py` (без изменений).
- Конфигурация и документация: `.env.example`, `README.md`, `CLAUDE.md` (корневой, `src/agents/`,
  `src/research/`).
- Поведение: при `REWRITE_HISTORY_QUESTIONS > 0` в служебный вызов переписывания добавляется
  несколько коротких вопросов (задержка вырастает незначительно); при значении по умолчанию 0
  поведение прежнее.
- Зависимости: новых нет. Хранилища: нет (история только читается из `short_term`, результат
  переписывания по-прежнему не сохраняется).
- Не затрагивается: основной ответ, формат `short_term` и индекса, основной поток, `/agent`,
  `/agent_compare`, служебные вызовы агента.
