# Design

## Context

После изменения `add-smart-agent-bybit-tools` (архивировано, спека
`smart-agent-market-tools` уже описывает MOEX+Bybit) слой `tools` устроен так:
- `mcp_integration/market_session.py`: `MarketSource(id, label, directory, program,
  allowlist)` — постоянные данные источника; `build_server_params(directory,
  program="mcp-moex")` строит `StdioServerParameters(command="uv", args=["run",
  "--directory", directory, program])`; `open_market_tools(directory, timeout,
  max_result_chars, program, allowlist)` открывает ОДНУ сессию; `is_model_tool(tool,
  allowlist)` требует ОБА условия — `is_read_only(tool)` И имя в `allowlist`;
  `open_multi_market_tools(sources, ...)` открывает список `MarketSource`
  ПОСЛЕДОВАТЕЛЬНО (не конкурентно — anyio не позволяет закрывать cancel scope в
  другом таске, см. решение 2 design.md изменения `add-smart-agent-bybit-tools`) в
  один `MultiMarketTools` с префиксацией `<source.id>__<имя>`.
- `agents/smart_agent.py`: `self._source_dirs = {SOURCE_MOEX: ..., SOURCE_BYBIT:
  ...}`; `_configured_sources()` строит список `MarketSource` из тех, чей каталог
  непуст, беря программу/allowlist из модульных словарей `_SOURCE_PROGRAMS`/
  `_SOURCE_ALLOWLISTS`; `get_tools_status()` возвращает статус по каждому
  ИЗВЕСТНОМУ источнику (включая «не настроен» для источника без каталога).
- `agents/market_tools.py`: `AvailableSource(id, analytics_available)`,
  `SOURCE_LABELS`/`SOURCE_DESCRIPTIONS`, `build_context_message(sources, today=None)`
  добавляет абзац цепочки анализа ТОЛЬКО источникам с `analytics_available=True`.

Новый источник — Банк России (пакет PyPI `atomno-mcp-cbr-rates`, проверено вручную:
`uvx atomno-mcp-cbr-rates` устанавливает и запускает сервер по stdio; 5 инструментов —
`get_rate`, `history_rates`, `key_rate`, `inflation`, `statistics`; НИ У ОДНОГО нет
аннотации `read_only_hint`, хотя по смыслу и сигнатуре все пять — параметризованные
чтения публичных данных cbr.ru без побочных эффектов) — не вписывается в текущую
модель по двум осям:
1. **Способ запуска**: `uvx <пакет>`, без локального каталога и без `uv run
   --directory`. `MarketSource.directory`/`build_server_params(directory, program)`
   предполагают ИМЕННО uv-каталог — этой форме `uvx` не соответствует.
2. **Отсутствие `read_only_hint`**: `is_model_tool()` сегодня безусловно требует
   аннотацию, у CBR её нет ни у одного инструмента. Решено (см. proposal.md,
   «Открытые вопросы») ДОВЕРИТЬ этому источнику как узкому, документированному
   исключению — механизм такого доверия в коде сейчас не существует вовсе.

## Goals / Non-Goals

**Goals:**
- Дать основному ответу `/smart_agent` доступ к официальным данным ЦБ РФ (курс валюты,
  ключевая ставка, инфляция, макро-снимок) третьим независимым источником, включаемым
  оператором булевым флагом, без локального каталога.
- Обобщить механику запуска источника (`MarketSource`/`open_market_tools`) на ЛЮБОЙ
  способ старта дочернего процесса (uv-каталог ИЛИ `uvx`-пакет), не что-то одно, чтобы
  четвёртый источник в будущем не потребовал такого же рефакторинга снова.
- Ввести узкий, явно промаркированный по идентификатору источника механизм «эта
  пометка (`read_only_hint`) необязательна для ЭТОГО источника» — без ослабления
  проверки для MOEX/Bybit и без auto-doверия по умолчанию для новых источников.

**Non-Goals:**
- Никакого версионирования/пиннинга пакета `atomno-mcp-cbr-rates` отдельной переменной
  — оператор решил обойтись простым булевым флагом (proposal.md, решённый вопрос);
  `uvx` использует свой обычный механизм резолюции/кэша.
- Никакого режима записи или расписания для CBR — сервер таким не является; `/watch*`
  остаётся только для MOEX.
- Никакого автоматического или выводимого «доверия» read-only по описанию/имени
  инструмента — исключение вводится ТОЛЬКО поимённо, для конкретного `source.id`, в
  коде этого изменения, не как общее правило.
- Никакой цепочки ссылок на историю (`rN`) для CBR — у источника нет инструментов
  анализа, которые могли бы принимать такую ссылку, и добавлять её ради источника,
  где она не нужна, — не предмет этого изменения.

## Decisions

### 1. `MarketSource` несёт готовые `StdioServerParameters`, а не `directory`/`program`

Заменить `MarketSource.directory: str` и `.program: str` на `.params:
StdioServerParameters` — уже готовую команду запуска. `open_market_tools()` принимает
`params` напрямую вместо `(directory, program)` и просто передаёт их в `stdio_client`;
он больше не знает, как источник собрал свою команду. Две чистые функции строят
`params` для двух существующих способов запуска:
- `build_server_params(directory, program="mcp-moex")` — СУЩЕСТВУЮЩАЯ функция (MOEX/
  Bybit), сигнатура и поведение НЕ меняются (тесты на неё продолжают проходить как
  есть) — `StdioServerParameters(command="uv", args=["run", "--directory", directory,
  program])`.
- `build_uvx_server_params(package)` — НОВАЯ, для источников без каталога:
  `StdioServerParameters(command="uvx", args=[package])`. Значение `package` — это
  ИМЯ ПАКЕТА, известное системе (константа в коде), а не то, что задаёт оператор —
  единственный операторский параметр источника такого типа — булев флаг включения,
  поэтому инъекция через переменную окружения здесь невозможна даже теоретически (в
  отличие от MOEX/Bybit, где хотя бы каталог — операторская строка, хоть и не
  подверженная инъекции благодаря списку аргументов без shell).

Альтернатива (оставить `directory: str = ""` и ветвиться внутри `MarketSource`/
`open_market_tools` по тому, пусто ли поле) отклонена: поле `directory` для
источника, у которого каталога в принципе нет, вводит в заблуждение (пустая строка
означает и «источник не настроен», и «источник настроен, но без каталога» — два разных
факта одним и тем же значением), а `open_market_tools` тогда должен бы сам решать, вызывать
ли `uv run --directory` или `uvx`, зная детали каждого способа — то, что сейчас явно и
намеренно вынесено в отдельные чистые функции сборки команды.

### 2. Отдельное поле `require_read_only: bool = True` в `MarketSource`, `is_model_tool()`, `MarketTools`

`MarketSource` получает пятое поле `require_read_only: bool = True` (значение по
умолчанию — MOEX/Bybit не меняют вызовы своего конструктора). `is_model_tool(tool,
allowlist, require_read_only=True)` — при `require_read_only=False` условие
`is_read_only(tool)` не проверяется, остаётся только вхождение в `allowlist`.
`MarketTools.__init__` получает тот же параметр (по умолчанию `True`, существующие
вызовы без него не меняются) и передаёт его в `is_model_tool()` при фильтрации.
`open_market_tools()`/`open_multi_market_tools()` прокидывают `source.require_read_only`
в конструктор `MarketTools` так же, как сегодня прокидывают `allowlist`.

Значение `require_read_only=False` задаётся ТОЛЬКО там, где строится `MarketSource`
для источника CBR (`agents/smart_agent.py`, `_configured_sources()`) — по имени
источника (`source_id == SOURCE_CBR`), а не выводится из чего-либо, что сообщает сам
сервер. Это ключевое свойство исключения: его нельзя получить, просто не выставив
аннотацию, — его явно проставляет код этого изменения для ОДНОГО заранее решённого
идентификатора источника. Перечень разрешённых имён (`allowlist`) при этом остаётся
обязательным для CBR так же, как для MOEX/Bybit — `require_read_only` отключает
ТОЛЬКО одну из двух проверок `is_model_tool()`.

Альтернатива (пометить read-only на СТОРОНЕ клиента постфактум — обернуть каждый
`Tool`, полученный от CBR, в объект с искусственно выставленной `read_only_hint=True`
до передачи в `is_model_tool()`) отклонена: она достигает того же результата более
запутанным способом (подделка ответа сервера вместо явного условия в коде фильтра) и
не даёт по логам/коду сразу видеть, что именно и почему разрешено — тогда как булев
параметр `require_read_only` виден прямо в месте фильтрации.

### 3. Абзац CBR в сообщении слоя — НЕ через `analytics_available`

`AvailableSource` (сейчас `id, analytics_available`) не подходит для CBR буквально:
`analytics_available` спрашивает «есть ли у источника инструменты АНАЛИЗА ИСТОРИИ» —
у CBR таких нет и не будет, но у него ЕСТЬ собственные всегда нужные правила (курс —
не рыночная цена, дата курса, предел 366 дней у `history_rates`). Добавить третье
булево поле `has_own_notes`/аналог в `AvailableSource`, независимое от
`analytics_available`, и отдельную функцию `_cbr_notes_block()` (по образцу
`_moex_analytics_block`/`_bybit_analytics_block`, но не завязанную на `today` — CBR
не нуждается в сегодняшней дате для этих правил, в отличие от цепочки анализа MOEX/
Bybit). `build_context_message()` добавляет абзац CBR, если источник CBR присутствует
в списке `sources` — БЕЗ проверки какого-либо флага анализа, потому что для CBR
показ этого абзаца не обусловлен наличием отдельных инструментов анализа: он про сам
факт присутствия источника.

Альтернатива (переиспользовать `analytics_available=True` для CBR, чтобы абзац
показывался через существующий механизм) отклонена: это исказило бы смысл поля
(`analytics_available` перестало бы означать «есть отдельные инструменты
compute/compare» и стало бы означать «есть хоть какой-то текст про источник») и
сломало бы существующую логику `MultiMarketTools.analytics_available_for()`, которая
физически проверяет наличие инструментов анализа У ЭТОГО источника — у CBR их нет.

### 4. `_configured_sources()`/`get_tools_status()` явно перечисляют источник CBR отдельной веткой, без общей абстракции

`SmartAgent` получает `self._cbr_enabled: bool` (из `MCP_CBR_RATES_ENABLED`) РЯДОМ с
`self._source_dirs` (не внутри него — семантика разная: словарь путей vs булев флаг).
`_configured_sources()` собирает список `MarketSource` из каталожных источников (как
сейчас) и ДОБАВЛЯЕТ CBR явной строкой, если `self._cbr_enabled`, используя
`build_uvx_server_params(CBR_PACKAGE)`, `CBR_MODEL_TOOL_ALLOWLIST`,
`require_read_only=False`. Аналогично `get_tools_status()` — словарь по `_source_dirs`
плюс отдельная запись для CBR по `self._cbr_enabled`.

Явные три ветки (MOEX, Bybit, CBR) вместо общей таблицы-реестра источников с
одинаковой формой конфигурации — сознательный выбор по тому же принципу, что и в
`add-smart-agent-bybit-tools`: три источника с двумя разными формами конфигурации
(каталог vs булев флаг) не оправдывают раннюю абстракцию «реестр источников», которая
скрыла бы именно то различие, которое здесь важно видеть в коде явно.

## Risks / Trade-offs

- **[Risk] Доверие источнику без аннотации — это решение человека, не проверка
  кода.** Если `atomno-mcp-cbr-rates` в будущей версии добавит пишущий инструмент, тот
  автоматически попадёт под `require_read_only=False`, если его имя окажется в
  `CBR_MODEL_TOOL_ALLOWLIST` (например, случайно совпадёт с уже разрешённым именем при
  смене поведения сервера без смены имени метода — маловероятно, но не невозможно). →
  **Mitigation**: перечень разрешённых имён остаётся ОБЯЗАТЕЛЬНЫМ (решение 2) — новый
  инструмент сервера, даже пишущий, не пройдёт фильтр, пока имя не добавлено в
  `CBR_MODEL_TOOL_ALLOWLIST` явно человеком; сама эта переменная — единственное место
  добавления новых инструментов CBR, что и есть желаемое трение.
- **[Risk] `uvx` при первом запуске скачивает пакет из PyPI — сетевая зависимость и
  задержка, которых нет у MOEX/Bybit (те тоже используют `uv`, но из уже
  подготовленного локального каталога с `uv.lock`).** Первый вопрос после включения
  флага может упереться в `MCP_TIMEOUT_SECONDS`, если сеть медленная. →
  **Mitigation**: тот же принцип, что у медленного первого `npx` для `/mcp_tools`
  (см. CLAUDE.md, `MCP_TIMEOUT_SECONDS`) — задержка вложена в общий тайм-аут, а
  «прогреть» кэш `uvx` можно вручную при развёртывании; отдельный больший тайм-аут
  для CBR не вводится (Non-Goals).
- **[Trade-off] Обобщение `MarketSource` на `params: StdioServerParameters` меняет
  внутреннее поле, которого касаются `_configured_sources()`/тесты, построенные под
  Bybit.** Это более широкий рефакторинг, чем «просто добавить источник» — но
  необходимый, раз способ запуска действительно другой; альтернатива (специальный
  частный случай только для CBR в `open_market_tools`) хуже: два способа собрать
  команду внутри одной функции только ради одного источника без общей формы, которая
  пригодится и следующему источнику без локального каталога.

## Migration Plan

- `MCP_CBR_RATES_ENABLED` необязателен и по умолчанию выключен — без него поведение
  бота не меняется. Включение — правка `.env` и перезапуск процесса, без окна отказа.
- Существующие файлы памяти `/smart_agent` не требуют миграции: `get_tools_status()`
  просто получает третий ключ в словаре, который раньше не существовал.
- Откат — выключить `MCP_CBR_RATES_ENABLED` и перезапустить бота; MOEX/Bybit не
  затрагиваются.
