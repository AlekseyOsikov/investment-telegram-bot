# Proposal

## Why

Сегодня `/dev` только отвечает текстом: документацию он видит лишь через офлайн-индекс, `mcp-git`
отдаёт имя ветки и список файлов, а содержимое файлов модели не доступно и менять что-либо нечем.
Нужен ассистент, который по цели («найди все места, где используется X», «приведи `.env.example` и
README в соответствие с `config.py`») сам читает и ищет по нескольким файлам проекта, анализирует их
и готовит правки, которые разработчик видит как diff и сохраняет осознанно.

## What Changes

- `/dev` получает файловый слой: модель сама вызывает инструменты `list_dir`, `read_file`,
  `search_text` (только чтение) и `propose_change` (готовит предложение правки, на диск ничего не
  пишет). Задача ставится на уровне цели, а не «открой файл X».
- Новый MCP-сервер файлов проекта (отдельный процесс по stdio, вне `src/`, по образцу мока CRM). Все
  границы доступа — на стороне сервера: корень репозитория, denylist (`.env*`, `data/`, `.git/`,
  `.venv`, ключи), лимиты, запись только в allowlist документации.
- Предложенная правка показывается в чате как unified diff с кнопками «Применить» и «Отклонить».
  Запись выполняет код бота по нажатию кнопки (проверяется id пользователя из списка оператора),
  а не модель. Инструмента применения у модели нет.
- Перед записью сервер сверяет хэш исходного файла с тем, по которому построен diff: изменившийся
  файл правка не перезаписывает. Применённый diff сохраняется как `.patch`, поэтому результат можно
  повторить и разобрать.
- Два основных сценария: (1) поиск всех мест использования API/компонента по нескольким файлам с
  ответом в виде ссылок `файл:строка`; (2) обновление документации по коду (например, `.env.example`
  и README по `config.py`) с diff по 2–3 файлам.
- **BREAKING (для текущих инвариантов)**: прежнее правило «содержимое файлов в модель не уходит»
  заменяется на «содержимое доступных файлов уходит модели через файловый слой». При облачном
  `MAIN_CLIENT` это покидает машину оператора; для режима рекомендуется `MAIN_CLIENT=ollama`.
  `get_diff` и `list_roots` сервера `mcp-git` по-прежнему модели не отдаются.
- Обновляются `CLAUDE.md` (корневой и `src/dev_assistant/`), README, `.env.example`.

## Capabilities

### New Capabilities
- `project-files-server`: MCP-сервер файлов проекта: инструменты чтения/поиска, подготовка
  предложения правки с diff, применение по идентификатору предложения, границы доступа (корень,
  denylist, allowlist записи, лимиты, сверка хэша, атомарная запись).

### Modified Capabilities
- `dev-assistant`: требования о git-контексте (содержимое изменений остаётся закрытым, файлы теперь
  через файловый слой) и о границах данных (содержимое файлов уходит модели); добавляются требования
  о файловых инструментах, предложении правки с кнопками «Применить»/«Отклонить» и о
  воспроизводимости результата.

## Impact

- Код: `src/dev_assistant/` (новый `files_session.py` по образцу `git_session.py`, `proposals.py` —
  чистые правила предложений и форматирования diff; правки `core.py`, `command.py`, `prompts.py`,
  `rules.py`), `src/config.py` (настройки оператора), новый каталог сервера вне `src/`.
- Тесты: чистые функции сервера и `proposals.py`, фасад инструментов (подстановка корня, allowlist).
- Данные: `data/dev_patches/` (применённые патчи) и каталог ожидающих предложений, не коммитятся.
- Зависимости: используется уже установленный `mcp`; новых пакетов нет.
- Документация: CLAUDE.md, `src/dev_assistant/CLAUDE.md`, README, `.env.example`.
