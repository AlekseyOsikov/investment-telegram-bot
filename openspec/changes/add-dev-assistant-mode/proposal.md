# Proposal

## Why

Проект вырос до README в ~1700 строк, семи вложенных `CLAUDE.md` и четырнадцати спек, и
ответы на вопросы «где собирается `main_client`», «какие переменные у очереди», «на какой ветке
идёт работа» требуют ручного поиска по документации. Бот уже умеет индексировать документы (`rag/`)
и ходить в MCP-серверы по stdio; не хватает ассистента разработчика, который отвечает о САМОМ
проекте: по его документации и по текущему состоянию git-репозитория.

Появился готовый read-only MCP-сервер `mcp-git` (ветка, список файлов, diff репозиториев из
разрешённого корня), поэтому сервер писать не нужно.

## What Changes

- Новый режим бота «ассистент разработчика» (диалог по образцу `/agent`, `/smart_agent`): вход
  командой `/dev`, вопросы — обычными сообщениями, выход — `/cancel`. Ответ строится по фрагментам
  документации проекта и результатам git-инструментов.
- **Доступ по списку id пользователей** из конфигурации оператора (`DEV_ASSISTANT_USER_IDS`).
  Пустой список — режим выключен (обработчики не регистрируются). Пользователь вне списка не
  получает ответа и не запускает ни поиск, ни модель, ни MCP — команда ведёт себя как
  незарегистрированная. Проверка — и при входе, и на каждом сообщении режима.
- **В `/help` режим НЕ добавляется**: справка остаётся как есть (решение владельца проекта). Режим
  описывается в README и CLAUDE.md.
- Отдельный индекс документации проекта (`DEV_ASSISTANT_INDEX_DIR`, по умолчанию
  `data/dev_index`), независимый от инвестиционного корпуса `data/rag_index`; собирается вручную
  `make dev-index` из `README.md`, `CLAUDE.md` (корневого и вложенных), `docs/**/*.md` (если есть)
  и `openspec/specs/**/spec.md`. Чанкер Markdown — по заголовкам.
- Git через MCP-сервер `mcp-git`, каталог которого задаёт оператор (`MCP_GIT_DIR`); корень доступа
  сервера — каталог этого репозитория, `repo_path` подставляет бот, модель его не выбирает.
  Модели отдаются ТОЛЬКО `get_current_branch` и `list_files`.
  **`get_diff` и `list_roots` модели не отдаются**: содержимое изменений (patch) в модель не
  попадает.
- Вызовы модели идут через очередь `llm_queue` как интерактивные задачи; память режима — только в
  процессе на время диалога, на диск не пишется.
- Системный промпт ассистента — константа в коде, отдельным системным сообщением; он не заменяет
  `SYSTEM_PROMPT` основного потока и ограничивает ассистента вопросами о проекте.

Не входит (non-goals): инструмент `get_diff` для модели (отдельное решение: через него код уходит
облачному провайдеру); авто-переиндексация и слежение за файлами; запись в репозиторий, любые
мутирующие git-операции; индексация исходного кода (`src/**/*.py`); долговременная память режима;
выбор модели/промпта пользователем; показ режима в `/help`; вопросы об инвестициях (их обслуживает
основной поток).

## Capabilities

### New Capabilities
- `dev-assistant`: доступ по списку id, режим диалога, индекс документации проекта и его сборка,
  git-инструменты `mcp-git` (ветка и список файлов), границы данных и поведение при недоступных
  индексе или git-сервере.

## Impact

- Код: новый пакет `src/dev_assistant/` (чистые правила, чанкер Markdown, сборка индекса, git-слой,
  командный слой), регистрация в `src/main.py`, переменные в `src/config.py` и `.env.example`,
  цель `dev-index` в `Makefile`, вложенный `src/dev_assistant/CLAUDE.md`.
- Зависимости: новых Python-пакетов нет (`mcp`, `faiss`, `numpy` уже есть); внешний проект
  `mcp-git` (`uv`) и локальный Ollama с `EMBEDDINGS_MODEL` для сборки индекса и поиска.
- Данные: `data/dev_index/` (не коммитится); история режима — только в памяти процесса.
- Приватность: текст вопроса уходит embeddings-бэкенду (`EMBEDDINGS_BASE_URL`) и основной модели
  (`MAIN_CLIENT`) вместе с фрагментами документации и именами файлов; при облачном провайдере это
  покидает машину оператора — фиксируется в спеке.
- Документация: README.md и CLAUDE.md (карта `src/`, конфигурация, правила безопасности).
