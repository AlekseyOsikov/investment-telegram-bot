# Proposal

## Why

У бота много независимых функций (`/watch*`, `/smart_agent`, очередь LLM-задач, слой `rag`), и у
пользователя регулярно возникают вопросы «почему не работает…»: не пришла сводка, бот долго
молчит, агент пишет «данные недоступны». Сегодня ответ можно получить только из README или от
оператора, а картину конкретного обращения (что именно сломалось у этого пользователя) не видит
никто, кроме оператора. Нужен ассистент поддержки: отвечает на вопросы о продукте по FAQ и
документации (RAG) и учитывает данные тикета пользователя, полученные через MCP.

## What Changes

- Новая команда `/support` (личные чаты, видна в `/help`, вне флага `RESEARCH`): диалоговый режим
  поддержки по образцу `/dev` — вопросы обычными сообщениями, выход `/cancel`.
- Ответ строится по фрагментам FAQ и документации из ОТДЕЛЬНОГО индекса (`SUPPORT_INDEX_DIR`,
  сборка `make support-index`) и по данным тикетов пользователя; в конце — перечень источников.
- Данные пользователя и тикетов приходят через MCP-сервер «CRM». Для этого изменения сервер —
  мок над JSON-файлами (`users.json`, `tickets.json`) с вымышленными данными; замена на настоящую
  CRM — настройка оператора без правок режима.
- На каждый вопрос код сам запрашивает у CRM открытые тикеты ЭТОГО пользователя и подаёт их
  модели отдельным системным сообщением как данные; модель дополнительно получает 2–3 read-only
  инструмента CRM. Идентификатор пользователя подставляет код (из Telegram), модель его не
  выбирает и чужие тикеты получить не может.
- Привязка тестового пользователя к мок-данным — настройка оператора `SUPPORT_DEMO_USER_ID`;
  остальные пользователи получают пустой профиль («обращений нет»).
- Режим не даёт инвестиционных рекомендаций, не ослабляет `SYSTEM_PROMPT`, историю держит только в
  памяти процесса; ставится в общую очередь LLM-задач новым видом задачи `support`.
- Не-цели: изменение/создание тикетов, роль оператора поддержки, связь с брокером, сбор
  персональных и финансовых данных, подключение реальной CRM, автоматическое открытие тикета из
  чата.

## Capabilities

### New Capabilities
- `support-assistant`: режим `/support` — доступ, диалог, поиск по FAQ/документации, контекст
  тикетов пользователя, границы безопасности, память, очередь, справка.
- `support-crm-mock`: MCP-сервер «CRM» над JSON с вымышленными пользователями и тикетами —
  контракт инструментов, изоляция по пользователю, read-only.

## Impact

- Код: новый пакет `src/support_assistant/` (правила, чанкер FAQ/индекс, поиск, промпты, CRM-слой,
  ядро, командный слой), регистрация обработчиков и строка в `/help` в `src/main.py`, вид задачи
  `support` в `src/llm_queue/rules.py`, новые настройки в `src/config.py` и `.env.example`, цель
  `make support-index`.
- Данные и мок: каталог с мок-сервером и вымышленными JSON, FAQ в `docs/support/`.
- Зависимости: используются уже подключённые `mcp` и `openai`; новых пакетов нет.
- Документация: `README.md`, корневой `CLAUDE.md`, новый `src/support_assistant/CLAUDE.md`.
- Данные наружу: вопрос — серверу эмбеддингов и основной модели; вместе с вопросом модели уходят
  фрагменты FAQ и тикеты пользователя. При облачном `MAIN_CLIENT` это покидает машину оператора.
- Безопасность и домен: мок-данные без персональных и финансовых сведений; текст тикета — недоверенные данные.
