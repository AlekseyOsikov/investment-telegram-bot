# Proposal

## Why

Изменения в бот (обработчики, правила предметной области, ограничения безопасности) проверяются
только автором: во всём репозитории нет CI, а инварианты проекта (`load_dotenv()` только в
`config.py`, нет рантайм-смены модели, не хранить чувствительные данные, дисклеймеры) легко
нарушить незаметно. Нужен автоматический первый проход по каждому новому PR, который знает и diff,
и документацию с кодом проекта, и честно говорит, что он проверить не смог.

## What Changes

- Новый пайплайн AI-ревью PR: при открытии/обновлении PR из ЭТОГО ЖЕ репозитория self-hosted
  runner собирает diff и содержимое изменённых файлов, ищет релевантные фрагменты документации и
  кода в индексе `main` (RAG) и публикует в PR один обновляемый комментарий с разделами
  «Потенциальные баги», «Архитектурные проблемы», «Рекомендации» и «Что не удалось проверить».
- Модель угроз «код PR — только данные»: workflow и скрипт берутся из `main`
  (`pull_request_target`), содержимое PR читается как текст и никогда не исполняется, модели не
  отдаются инструменты.
- Отдельный индекс для ревью: документация (как у `/dev`) плюс исходники `src/` и `scripts/`,
  разбитые по функциям и классам; собирается из `main` по `push`, содержимое PR в индекс не попадает.
- Провайдер и модель ревью — настройка оператора (локальный Ollama по умолчанию, облачный
  провайдер — по решению оператора), в комментарии указываются.
- Оснастка вне бота: `scripts/pr_review.py` + чистые правила `scripts/pr_review_lib.py` (по образцу
  `ollama_tune`), два workflow в `.github/workflows/`, инструкция по развёртыванию runner на ПК и
  последующему переносу на VPS.

Не делается: исполнение кода PR, автоматические исправления и коммиты, блокировка merge,
многопроходное ревью по файлам, выбор модели через комментарии в PR, ревью PR из форков.

## Capabilities

### New Capabilities
- `pr-ai-review`: автоматическое ревью PR — триггер и условия запуска, «код PR как данные», границы
  индекса, состав и формат комментария, поведение на больших PR и при недоступных зависимостях.

### Modified Capabilities

(нет: бот, `/dev`, `rag-indexing` и слой `rag` не меняются; существующие индексы не затрагиваются)

## Impact

- Новые файлы: `.github/workflows/ai-review.yml`, `.github/workflows/ai-review-index.yml`,
  `scripts/pr_review.py`, `scripts/pr_review_lib.py`, чанкер исходников и сборщик индекса ревью,
  `tests/test_pr_review_lib.py`.
- `Makefile` (цель сборки индекса ревью), `.env.example` (переменные ревью, если читаются из
  `.env`), `CLAUDE.md` и `README.md` (раздел про оснастку и модель угроз).
- Каталог `src/` бота не меняется; `rag.index_store` переиспользуется как есть.
- Внешнее: self-hosted runner с меткой `ai-review`, локальный Ollama, права `pull-requests: write`
  у `GITHUB_TOKEN`, настройка репозитория «требовать одобрения для outside collaborators».
- Данные наружу: diff и фрагменты уходят выбранному оператором провайдеру ревью; репозиторий
  публичный, но при облачном провайдере это новый канал, решение оператора.
