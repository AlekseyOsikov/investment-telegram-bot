# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием. Детали подсистем лежат во вложенных
`CLAUDE.md` (подгружаются при работе с файлами соответствующего каталога):
`src/agents/`, `src/mcp_integration/`, `src/price_watch/`, `src/rag/`, `src/research/`.
Что система должна делать (требования) — в `openspec/specs/`; здесь — как устроен код и почему.

## Что это за проект

Telegram-бот для инвестиционных рекомендаций на `python-telegram-bot` (v20+, async). Основной
поток — stateless-прокси: вопрос в личном чате → LLM (OpenAI-совместимый DeepSeek, Kimi или локальный Ollama) →
ответ как есть. Поверх — независимые функции со своими правилами (агенты с памятью, research-режимы,
MCP-инструменты, опрос цен, RAG-индексация). Проект развивается в сторону инвестиционного
ассистента — архитектурные решения пересматривай по мере роста, а не считай окончательными.

## Карта `src/`

- `config.py` — все переменные окружения и константы не-провайдерного уровня (`SYSTEM_PROMPT`,
  лимиты, логирование, `MAIN_CLIENT`/`MAIN_MODEL`). Единственное место с `load_dotenv()`.
- `providers/` — `deepseek_client.py`, `kimi_client.py` (клиенты и модели для `/research_models`),
  `main_client.py` (выбор `main_client` по `MAIN_CLIENT`; основной поток и research-режимы без
  собственного выбора модели импортируют клиента отсюда), `embeddings_client.py` (Ollama-эмбеддинги
  для `rag/`; НЕ связан с `MAIN_CLIENT`), `ollama_client.py` (чат-клиент Ollama; он же `main_client` при `MAIN_CLIENT=ollama`) и
  `rewrite_client.py` (клиент и модель переписывания вопроса по `REWRITE_PROVIDER`; не связан с
  `MAIN_CLIENT` и эмбеддингами).
- `main.py` — `/start`, `/help`, `handle_message`, точка входа, регистрация всех обработчиков.
- `research/` — технические режимы исследования API (`RESEARCH`).
- `agents/` — `Agent` (`/agent`), `/agent_compare`, `SmartAgent` (`/smart_agent`, в т.ч. слой `rag` —
  справочные материалы из индекса `rag/`).
- `mcp_integration/` — MCP-клиенты: `/mcp_tools`, инструменты рыночных данных для `/smart_agent`,
  инструменты расписания для `/watch*`.
- `price_watch/` — `/watch*`, опрос цен и сводки по расписанию.
- `rag/` — офлайн-индексация документов (`make index`); индекс читают research-команды и слой `rag`
  у `/smart_agent`.
- `scripts/` — одноразовая оснастка (не часть бота): `rag_calibrate.py` — калибровка `RAG_MIN_SCORE` (запросы — в `data/rag_eval/`, не коммитятся); `dialog_eval.py` — прогон длинных диалогов `/smart_agent` с задачей и материалами (сценарии и отчёты — в `data/dialog_eval/`, не коммитятся; правила — `src/research/dialog_eval.py`).

## Команды

```bash
make install   # pip install -r requirements.txt
make run       # python src/main.py
make test      # pytest tests/
make index     # python -m rag.cli (нужен локальный Ollama с EMBEDDINGS_MODEL)
make clean     # удаляет __pycache__, .pytest_cache, .ruff_cache, build/dist
python3 -m compileall -q src   # проверка синтаксиса без запуска
```

`ruff` и `pytest` не входят в `requirements.txt` (`pip install ruff pytest`); ruff настроен в
`pyproject.toml`. `ruff check src/` на старом коде не проходит начисто (в основном `E501`), а
`ruff format` переформатировал бы половину проекта — сверяй, что твои изменения не ДОБАВЛЯЮТ
замечаний, не гонись за нулём на всём репозитории.

**Тесты** (`tests/`, `conftest.py` добавляет `src/` в `sys.path`; пакета нет, запуск `python
src/main.py`) покрывают только чистые функции без сети, Telegram и LLM — без моков клиентов и
`SmartAgent`. Новые правила покрывай тестами чистых функций. Всё остальное (`SmartAgent`, обработчики,
живые MCP-серверы, Ollama, `pdftotext`) проверяется вручную. Перечень тестов по подсистемам — во
вложенных `CLAUDE.md`.

## Процесс: OpenSpec

Заметные изменения наблюдаемого поведения бота (новая команда, слой памяти, сценарий задачи,
стратегия контекста) идут через OpenSpec; опечатки, документация, мелкий рефакторинг и вопросы по
коду — обычным порядком. Процесс не влияет на рантайм: `src/` от `openspec/` не зависит.

- Порядок: `/opsx:explore` → `/opsx:propose` → (`/opsx:update`) → `/opsx:apply` → (`/opsx:sync`) →
  `/opsx:archive`. Изменение лежит в `openspec/changes/<id>/` (`proposal.md`, `design.md`,
  `specs/<capability>/spec.md` — ДЕЛЬТА, `tasks.md`), завершённые — в `openspec/changes/archive/`,
  главные спеки — `openspec/specs/<capability>/spec.md`. `.claude/skills/openspec-*` и
  `.claude/commands/opsx/*` генерирует `openspec init` — вручную не правь.
- **Граница планирования**: `explore`/`propose`/`update` не трогают код, даже если просьба звучит
  как «сделай/почини». После готовых артефактов остановись и жди явной просьбы на `/opsx:apply`.
- **Нужен CLI `openspec`** (`@fission-ai/openspec`, Node 20.19+). Если его нет — не имитируй: не
  создавай файлы в `openspec/` руками и не воспроизводи формат по памяти; сообщи и либо поставь по
  просьбе пользователя, либо делай задачу без OpenSpec.
- **Формат дельта-спеки**: `## ADDED|MODIFIED|REMOVED|RENAMED Requirements`; внутри `### Requirement:
  <название>` и минимум один `#### Scenario:` на требование. В MODIFIED требование переносится
  ЦЕЛИКОМ (урезанный блок `validate`/`archive` отклонят). В главных спеках один раздел
  `## Requirements`, без заголовков операций.
- После `/opsx:archive` (или вместе с реализацией) обновляй CLAUDE.md и README.md, если изменились
  архитектура, конфигурация или набор команд — спека этого не заменяет. Ретроспективно переписывать
  весь существующий бот в спеки не нужно.
- Доменные и security-ограничения ниже действуют и внутри OpenSpec: предложение, вводящее сбор
  денежных сумм, пользовательский системный промпт или рантайм-переключение модели/провайдера,
  требует явного обсуждения с владельцем проекта, а не молчаливой реализации «по утверждённой спеке».

## Конфигурация

Секреты и параметры — из `.env` через `python-dotenv` (`.env` в gitignore, `.env.example`
документирует каждую переменную). `config.py`, `providers/*_client.py` и `config._validate_config()`
— источник истины по составу настроек и значениям по умолчанию; этот раздел — только правила.

- `load_dotenv()` — только в `config.py`; `providers/*_client.py` делают `import config` ради
  побочного эффекта (dotenv и `logging.basicConfig()` должны отработать раньше чтения окружения) и
  сами `load_dotenv()` не вызывают.
- `MAIN_CLIENT` (`deepseek`|`kimi`|`ollama`, по умолчанию `deepseek`) выбирает провайдера основного потока и
  research-режимов без собственного выбора модели; `MAIN_MODEL` — модель (по умолчанию зависит от
  провайдера; для `ollama` дефолта нет — пустая модель завершает запуск). Чистые правила выбора
  (допустимые значения, дефолты, подписи, валидация, тексты ошибок) — `main_client_settings.py`. `main_client` собирается в `providers/main_client.py`, а не в `config.py` — чтобы не
  было цикла импорта. `MAIN_CLIENT_LABEL` — подпись провайдера для текстов.
- **Обязательность ключа зависит от `MAIN_CLIENT`** (сохранять): `deepseek_client.py` завершает
  процесс, только если `MAIN_CLIENT == "deepseek"` и нет `DEEPSEEK_API_KEY`; симметрично для Kimi;
  для `ollama` ключ не нужен (оба облачных ключа опциональны), обязателен `MAIN_MODEL`. Облачные
  параметры вызовов (`extra_body={"thinking": ...}`) в Ollama не отправляются.
  Ключ невыбранного провайдера опционален (нужен `/research_models`), его отсутствие — только
  предупреждение, клиент создаётся с плейсхолдером (пустой `api_key` уронил бы конструктор
  `OpenAI()`). `TELEGRAM_BOT_TOKEN` и допустимость `MAIN_CLIENT` проверяет `_validate_config()`.
  Новые провайдер-специфичные переменные — в `providers/*_client.py`, общие — в `config.py`.
  `MAIN_CLIENT=ollama`: `OLLAMA_BASE_URL` общий с переписыванием вопроса; при удалённом адресе
  вопросы, память агентов и результаты инструментов уходят на этот сервер — решение оператора.
- `RESEARCH` (булево, по умолчанию `true`) — решение ОПЕРАТОРА, не пользователя. При `false` не
  регистрируются и не упоминаются в `/help`: `/research_constraints|reasoning|temperature|models|
  chunking_stats|chunking_compare|rag_compare|rag_compare_stop|rag_compare_report`,
  `/agent_compare`, `/agent_compare_report`,
  `/agent_compare_reset`, `/agent_mode`, `/agent_context`, `/mcp_tools` (`RESEARCH_ENABLED` в
  `main.py`); команда при этом молча игнорируется, как любая незарегистрированная. Не затрагивает
  `/agent`, `/agent_reset`, `/agent_history`, `/agent_checkpoint|branch|switch_branch`. Новую
  research-команду добавляй в этот же список (регистрация + `/help`), отдельный флаг не заводи.
- Параметры сценариев `/research_constraints`/`/research_temperature` — константы в модулях
  (предмет исследования). Идентификаторы моделей `/research_models` — в `.env` (меняются чаще кода).
- Каталоги данных (`AGENT_HISTORY_DIR`, `AGENT_MEMORY_DIR`, `PRICE_WATCH_DB`,
  `RAG_COMPARE_REPORT_DIR`, `data/`) не коммитятся. **Корпус документов в репозиторий не входит, и
  всё, что его содержит или на него ссылается, — тоже**: контрольные вопросы
  (`RAG_COMPARE_QUESTIONS_FILE`), калибровочные запросы, отчёты прогонов лежат в `data/`. Не
  копируй в код, тесты, документацию и артефакты OpenSpec названия документов, ники авторов и
  цитаты из них — в примерах используй вымышленные. Переменные `AGENT_*`, `MCP_*`, `PRICE_WATCH_*` описаны во вложенных `CLAUDE.md`
  соответствующих подсистем. Слой `rag` у `/smart_agent` настраивает оператор:
  `RAG_SMART_AGENT_STRATEGY` (по умолчанию `structural`), `RAG_TOP_K`, `RAG_MIN_SCORE` (порог
  откалиброван под `bge-m3` + `structural`, при смене модели/стратегии пересчитывать),
  `RAG_SEARCH_TIMEOUT_SECONDS` (бюджет ожидания эмбеддинга, 5 с); пользователь чата их не выбирает.
  Поиск двухэтапный: `RAG_CANDIDATES` кандидатов → шаги отбора (`RAG_MIN_SCORE`,
  `RAG_RELATIVE_MARGIN`, `RAG_MIN_CHUNK_CHARS`, `RAG_MAX_PER_DOC`; нейтральные значения отключают шаг) →
  не более `RAG_TOP_K`. Переписывание вопроса в поисковый запрос — тоже решение оператора:
  `REWRITE_PROVIDER` (`ollama`|`deepseek`|`kimi`; пусто — выключено, по умолчанию),
  `REWRITE_MODEL`, `REWRITE_TIMEOUT_SECONDS`, `REWRITE_SEARCH_MODE`, `REWRITE_HISTORY_QUESTIONS`
  (сколько прошлых ВОПРОСОВ пользователя передавать модели переписывания; 0 — не передавать),
  `OLLAMA_BASE_URL`; ключ невыбранного
  для переписывания провайдера не нужен, а его отсутствие у выбранного `deepseek`/`kimi` — только
  предупреждение при запуске (переписывание пропускается, бот работает). Порог привязан и к
  переписыванию: при включении или смене модели переписывания пересчитывать (`scripts/rag_calibrate.py
  --rewrite`). Режимы сравнения `/research_rag_compare` — `RAG_COMPARE_LEVEL`/`RAG_COMPARE_MODES`.
  `MCP_SERVER_COMMAND`/`MCP_SERVER_ARGS` и всё про MCP-серверы — настройка оператора (аргументы
  через `shlex.split`, запуск без shell).
- `PRICE_WATCH_ACTIVE = PRICE_WATCH and bool(MCP_MOEX_DIR)`; `PRICE_WATCH_DB` приводится к
  АБСОЛЮТНОМУ пути при загрузке (`uv run --directory` меняет cwd сервера).
- Технические промпты (`AGENT_*_SYSTEM_PROMPT`) в `.env` не выносятся — по тому же принципу, что
  `SYSTEM_PROMPT`.

## Основной поток (`main.py: handle_message`)

1. Фильтр `filters.TEXT & ~filters.COMMAND & filters.ChatType.PRIVATE` — групповые чаты и
   не-текст отсеиваются фильтром, а не отказом. Сохраняй его у любых новых обработчиков текста.
2. Проверка длины (`MAX_INPUT_CHARS`), `ChatAction.TYPING`, вызов `main_client` с `MAIN_MODEL`.
3. В провайдера уходят ровно два сообщения — `SYSTEM_PROMPT` и текст пользователя; история
   намеренно не подмешивается.
4. Исключения OpenAI SDK (`AuthenticationError`, `RateLimitError`, `APITimeoutError`,
   `APIConnectionError`, `APIStatusError`, общий fallback) ловятся ПО ОТДЕЛЬНОСТИ и переводятся в
   русское сообщение с реальным провайдером через `MAIN_CLIENT_LABEL` — не один общий `except`, не
   захардкоженное «DeepSeek». Тот же паттерн — для любой новой обработки ошибок.
5. Ответы режутся по `TELEGRAM_MESSAGE_LIMIT` (4000 символов, запас от 4096).
6. `error_handler` — общий обработчик PTB для всего, что не поймано внутри.

Все пользовательские строки — на русском. `main.py` регистрирует обработчики всех подсистем
(`build_*_handler(s)`).

## Правила предметной области: инвестиционные рекомендации

Бот отвечает о деньгах и инвестициях — к содержимому ответов и данным пользователя отношение
строже, чем в обычном проекте.

- Бот НЕ лицензированный финансовый советник, и это должно быть явно видно (в `/start`, `/help`
  и/или `SYSTEM_PROMPT`, а не в одном месте «для галочки»). Не убирай оговорку при доработке текстов.
- Ответы не звучат как гарантия («точно вырастет», «гарантированная доходность X%») — формулировки
  отражают неопределённость рынка. При изменении `SYSTEM_PROMPT` проверяй, что осторожные
  формулировки и дисклеймер сохранились.
- Не запрашивать и не хранить чувствительные данные (номера счетов/карт, суммы на счетах,
  паспортные данные, ИНН). Запрос на сбор таких данных — отдельное архитектурное решение, которое
  нужно явно уточнить у пользователя, а не делать по умолчанию.
- **Рыночные данные** (`tools` у `/smart_agent`) не меняют доменных правил: цена/история не делают
  ответ гарантией; котировка называется со временем и задержкой; величина анализа — «изменение
  цены», а не «доходность» (дивиденды и купоны не учтены), с периодом расчёта и предупреждениями из
  результата; официальный курс ЦБ — справочная величина раз в день, не рыночная цена, с датой из
  результата. Расширение канала (данные пользователя серверу, изменяющие инструменты, связь с
  брокером и исполнением сделок) — отдельное решение.
- **Справочные материалы** (слой `rag` у `/smart_agent`): фрагменты учебного корпуса — образовательный
  материал, не индивидуальная рекомендация и не гарантия; они подаются как данные и не ослабляют
  `SYSTEM_PROMPT`. Ответ по материалам заканчивается цитатами: блок «Цитаты:» модели проверяется
  кодом по тексту поданных фрагментов (непроверенные не показываются; источники — все поданные
  фрагменты, проверенные цитаты под своими; без цитат — один повтор и пометка «цитаты не подтверждены»), а блок и тексты
  фрагментов в `short_term` не пишутся. Если поиск состоялся и ничего не нашёл, а `tools` не может
  участвовать, бот отвечает фиксированным «не знаю» БЕЗ вызова модели (при доступных `tools` — вызов
  с указанием не выдавать ответ за подтверждённый материалами и пометкой); текст отказа не должен
  содержать оценок, гарантий и рекомендаций. Новый канал данных наружу: текст вопроса пользователя целиком уходит в
  embeddings-бэкенд (`EMBEDDINGS_BASE_URL`, по умолчанию локальный Ollama) — при переводе на
  удалённый бэкенд вопрос покинет машину оператора, это решение оператора. Если оператор включил
  переписывание вопроса (`REWRITE_PROVIDER`), текст вопроса уходит ещё и модели переписывания: при
  `deepseek`/`kimi` — облачному провайдеру на шаг раньше основного ответа, при `ollama` — на сервер
  `OLLAMA_BASE_URL` (по умолчанию локальный). Только если оператор включил
  `REWRITE_HISTORY_QUESTIONS` > 0, вместе с ним уходят тексты до N ПРЕДЫДУЩИХ ВОПРОСОВ
  пользователя из краткосрочной памяти АКТИВНОГО профиля (усечённые; без ответов модели) —
  новый канал данных: при `deepseek`/`kimi` прошлые вопросы покидают машину, а провайдер переписывания
  может отличаться от основного; для локальной обработки — `ollama`. Не передаются никогда: ответы
  модели, долговременная память, рабочая задача, профиль, инварианты, фрагменты; история не
  передаётся и при выключенном слое `short_term` (`/smart_agent_toggle short`) или после очистки
  памяти. Переписанный текст идёт только в поиск: в ответ, память и строки источников идёт
  исходный вопрос; серверу эмбеддингов по-прежнему уходит только поисковый текст.
- **Опрос цен** (`/watch*`) — первый случай, когда бот сам пишет без вопроса. Хранится только
  chat_id, тикеры, настройки, публичные цены и готовые сводки. Сводка — факты, не рекомендация;
  оговорки сервера должны доезжать до пользователя. Пороги/«сигналы», оценки и советы, суммы или
  количество бумаг, связь с брокером — отдельное решение.
- Оценка соответствия конкретному законодательству — ответственность владельца продукта; не
  утверждай правовое соответствие, по умолчанию сохраняй осторожные формулировки и дисклеймеры.

## Ограничения безопасности, которые нужно сохранять

**Нет админ-команд и рантайм-смены модели/провайдера/промпта.** Не добавляй команды или параметры,
позволяющие пользователю чата менять `MAIN_CLIENT`/`MAIN_MODEL`/`SYSTEM_PROMPT` или задавать
собственный системный промпт. Смена — решение оператора через `.env` и перезапуск.

Этому НЕ противоречат (они влияют только на сборку контекста или выбор из фиксированного набора, а
не на провайдера, модель или `SYSTEM_PROMPT`): кнопки-сценарии `/research_models`; `/agent_context`
и `/agent_checkpoint|branch|switch_branch`; `/smart_agent_toggle`; профили `/smart_agent_profile*`;
инварианты `/smart_agent_invariant_*`; слои `tools` и `rag` (включая переписывание вопроса для поиска
— провайдер и модель задаёт ТОЛЬКО оператор в `.env`, промпт — константа в коде, результат идёт лишь
в поисковый запрос, а не в ответ); `/watch*`. Общие условия:
- профиль (`meta`), инварианты, сообщения слоёв `tools` и `rag` уходят ОТДЕЛЬНЫМИ системными сообщениями,
  а не подменяют `SYSTEM_PROMPT`, и каждое прямо запрещает ослаблять обязательные предупреждения и
  осторожные формулировки — при правке текстов эту оговорку сохраняй, иначе слой превратится в
  пользовательский системный промпт;
- профиль влияет только на подачу ответа (стиль/формат/объём); инварианты СУЖАЮТ то, что агент
  предложит;
- серверы `tools` и `/watch*`, способ их запуска и пути задаёт оператор (`MCP_MOEX_DIR`,
  `MCP_BYBIT_DIR`, `MCP_CBR_RATES_ENABLED`, `PRICE_WATCH_DB`); модели отдаются только read-only
  инструменты из явного перечня (единственное поимённое исключение из проверки аннотации — Банк
  России, см. `src/mcp_integration/CLAUDE.md`); инструменты расписания модели не отдаются; `/watch*`
  не используют LLM вообще.

**История и память — только там, где явно запрошено, видимо и очищаемо пользователем.** Основной
поток и research-режимы ничего не сохраняют. Исключения (каждое запрошено пользователем проекта,
не расширяй их молча):
- `/agent` — история по веткам в JSON (`AGENT_HISTORY_DIR`), видна `/agent_history`, очищается
  `/agent_reset` (все ветки, чекпоинты, facts, summary).
- `/agent_compare` — три дополнительных файла истории на чат, очищаются `/agent_compare_reset`.
- `/smart_agent` — независимая память (`AGENT_MEMORY_DIR`) тремя слоями в разрезе профилей. Слои
  `working` и `long_term` пополняются ещё и АВТОМАТИЧЕСКИ техническим вызовом LLM после каждого
  ответа — осознанное сужение прежней гарантии «пишет только явная команда»; взамен: запрет
  чувствительных данных в промптах технического вызова, видимость (строка состояния,
  `/smart_agent_show`, `/smart_agent_long_show` с происхождением факта) и полностью ручное
  управление поверх автоматики. **Профиль (`meta`) и инварианты пишутся ТОЛЬКО явными командами
  пользователя — не распространяй на них автозапись и никакие эвристики.** Слои не фильтруют
  ввод, ответственность за чувствительные данные на пользователе, поэтому тексты команд обязаны об
  этом предупреждать.
- `/watch*` — сервер `mcp-moex` хранит в SQLite (`PRICE_WATCH_DB`) chat_id, тикеры, периоды,
  публичные цены и сводки; бот сам шлёт сводки по расписанию. Серверу уходят только chat_id, тикеры
  и периоды — не другие сообщения, не история, не память агентов. `/agent_reset`/
  `/smart_agent_reset` эти данные не трогают, удаляет `/watch_stop`. Не добавляй сбор денежных
  сумм и личных финансовых данных.
