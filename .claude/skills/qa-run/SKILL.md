# Единый QA-прогон

Два уровня и один отчёт. Не заявляй «всё хорошо», пока не прочитан вывод каждой команды.

## Порядок

1. **Что изменилось.** `git status`, `git diff main --stat` и список НЕОТСЛЕЖЕННЫХ файлов
   (`git ls-files --others --exclude-standard`): `git diff` новые файлы не показывает, а тесты из
   `test-writer` часто лежат в дереве без коммита. Итоговый список изменённых файлов — объединение
   обоих. Это нужно для вывода в отчёте и для `ruff`.
2. **Уровень 1 — код.** По очереди, читая вывод:
   - `.venv/bin/python -m compileall -q src`
   - `.venv/bin/ruff check <изменённые и новые файлы из шага 1>` — новых замечаний быть не должно
     (число до/после для `main.py`, как в `docs/code-style.md`, раздел 10);
   - `TELEGRAM_BOT_TOKEN=x DEEPSEEK_API_KEY=x .venv/bin/pytest tests/ -q -p no:cacheprovider
     --cov=src --cov=scripts --cov-report=term` — число passed/failed И покрытие: общий процент и
     по затронутым модулям. Покрытие обязательно и снимается в ЭТОМ прогоне; цифры из отчётов
     субагентов в отчёт не переносятся. Нет `pytest-cov` — поставь
     (`uv pip install --python .venv/bin/python pytest-cov`) или впиши в «Не проверено», что
     покрытие не снято и почему.
   - **Коды выхода.** Не бери код выхода из конвейера с `| tail`/`| grep` (там код последней
     команды). Запускай команду отдельно и читай `echo exit=$?`, либо используй
     `${PIPESTATUS[0]}`; для smoke важен именно код `scripts/smoke.py` (0 — всё прошло).
3. **Уровень 2 — smoke.** Запусти субагента `smoke-runner` (или сам `.venv/bin/python
   scripts/smoke.py --out <каталог результатов>/smoke`; каталог — из шага 6): он прогоняет
   `docs/smoke/*.md`, читает отчёт и скриншоты и объясняет падения. Нужны Chrome для PNG (иначе
   остаются HTML) и свободный `.venv`; Telegram, Ollama и модель не нужны.
4. **Если что-то упало** — по каждому падению: что ожидали, что получили, `файл:строка`,
   «баг бота / устарел тест или сценарий / окружение». Не чини молча и не ослабляй проверки; если
   нужен фикс — предложи (профиль `bug-fix`).
5. **Новая команда без сценария?** Сравни команды из `git diff main` (`CommandHandler("...")`) с
   `docs/smoke/*.md`; если команда не покрыта — предложи `/qa-update-smoke`.
6. **Сводный отчёт** — в ответе и в `report.md` каталога результатов; рядом, в `smoke/`, лежит
   отчёт smoke со скриншотами. Каталог зависит от просьбы пользователя:
   - **по умолчанию** — `reports/qa/<дата>_<время>/` (формат `2026-10-24_14-23`). `reports/` в git
     не попадает, повторные прогоны за день не перезаписывают друг друга;
   - **только если пользователь просит сохранить результаты в репозитории** («сохрани в docs»,
     «для коммита») — `docs/qa/<дата>_<время>/`; коммитятся они отдельно от кода и только по
     просьбе. В этом случае `*.html` скриншотов не нужны: оставь `report.md` и `*.png`.
   Время берётся один раз в начале прогона (`date +%F_%H-%M`) и используется во всех путях.
   Формат отчёта:

```
## QA-отчёт <дата>
Изменено: <модули/команды>
### Уровень 1 — код
compileall: …; ruff: …; pytest: N passed, M failed; покрытие: …
### Уровень 2 — smoke
сценариев K из L; отчёт со скриншотами: <каталог результатов>/smoke/report.md
### Упало и где искать
…
### Не проверено
(живая модель, MCP-серверы, реальный Telegram, ручные проверки из CLAUDE.md)
```

Скриншоты не вставляй в ответ — давай путь к `report.md`.

## Чего не делать

- Не коммитить, не пушить, не читать `.env`.
- Не подменять прогон пересказом: числа берутся из вывода команд этого прогона, а не из отчётов
  субагентов (`test-writer`, `smoke-runner`) и не из памяти.
- Не писать в отчёте «ничего не упало», пока не прочитан код выхода каждой команды.
