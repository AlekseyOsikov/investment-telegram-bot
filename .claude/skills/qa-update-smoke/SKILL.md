# Обновить smoke-сценарии и прогнать заново

Сценарии — текст в `docs/smoke/*.md` (формат — `docs/smoke/README.md`). Источник правды о
поведении — код и `openspec/specs/`; сценарий не должен «подстраиваться» под баг.

## Порядок

1. **Найди, что изменилось**: `git diff main` (или коммиты, на которые указал пользователь) —
   новые и изменённые `CommandHandler("…")`, тексты в `texts.py`, `help_command`, флаги в
   `config.py`.
2. **Реши, что нужно сценариям**:
   - новая команда → новый файл `docs/smoke/NN-<название>.md` (следующий номер) или шаги в
     близком сценарии;
   - изменился текст или команда → поправь `Ожидать:` в существующих сценариях (проверь по
     коду, что текст изменён осознанно, а не сломан);
   - команда удалена → убери шаги и строку из таблицы в `docs/smoke/README.md`.
3. **Пиши сценарий по образцу** `docs/smoke/02-profile-invariant.md`: путь «создать → проверить →
   удалить», проверка оговорок там, где команда говорит об инвестициях, вымышленные данные.
   Сценарии идут БЕЗ живой модели, MCP-серверов и сети: шаги, которым это нужно (вопрос модели,
   `/watch`, `/support`), не включай — отметь в итоге как «нужна ручная проверка».
4. **Обнови таблицу** в `docs/smoke/README.md`.
5. **Прогони заново всё** — `/qa-run` (код-тесты + smoke), а не только новый сценарий: фича могла
   сломать соседние.
6. **Итог**: какие сценарии добавлены/изменены и почему, результат прогона (числа из вывода),
   что не покрыто smoke.

## Чего не делать

- Не править `src/`, чтобы сценарий прошёл; не ослаблять `Ожидать:` до бессмысленного.
- Не добавлять шаги с реальными ключами, `.env` и данными пользователей.
- Не коммитить без просьбы.
